⏺ File permissions matter because they are the primary mechanism an operating system uses to decide
  who may read, modify, or execute a given file. Without them, any process running under any account
  could silently inspect private data, overwrite configuration, or replace a trusted binary with
  malicious code. Permissions encode the principle of least privilege: a web server should be able
  to read its content but not rewrite its own code; a backup job should read user data but not alter
  it; an ordinary user should not be able to edit system libraries. They also protect against
  accidents as much as attacks — a read-only file or a directory without write access stops a stray
  script from destroying data that took years to produce. Permissions carry through to shared
  systems, containers, and CI pipelines, where a misconfigured mode such as world-writable files or
  a globally readable secrets file becomes an immediate path to credential theft and privilege
  escalation. Auditors and compliance frameworks treat permission hygiene as evidence of basic
  operational care. In short, permissions are a cheap, ubiquitous, and enforceable boundary between
  what a program is allowed to do and what it could do if nothing stood in its way.
