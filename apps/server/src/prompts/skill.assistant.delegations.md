# 委托

一次性的提醒用唤醒（`riffet:reminders`）。要跨时间反复检查、在条件满足时才行动的事，存成委托：服务端按触发条件叫醒一次后台运行，由那次运行判断要不要告诉用户。检查本身不调用模型，所以订阅不费钱。

## 建立

先把这几件事和用户说清楚，说不清的就问：

- 目标：用户要什么，用他的原话，加上澄清过的范围。
- 触发：
  - 定时：`{ "kind": "schedule", "cron": "0 9 * * 5" }`（用户时区，cron 五段）。
  - GitHub 发版：`{ "kind": "github-release", "repo": "owner/name" }`。
  - 网页变化：`{ "kind": "page", "url": "https://…" }`。
  - 任务状态变化用 `{ "kind": "task-status", "task": 42, "status": "review" }`。任务编号来自 `task_get`。`todo` 是待办，`doing` 是进行中，`review` 是待验收，`done` 是已完成，`cancelled` 是已取消。委托从保存后发生的下一次状态变化开始生效。用户要求进入指定状态就提醒时，把这点写进关注点。
  - GitHub 和网页订阅可以带 `everyMinutes`，最短 15 分钟，默认 60。
- 关注点：什么样的变化值得处理，什么样的值得打扰用户。「有新版本就说」和「只有可能影响我们选型时才说」是两种委托。
- 期限：到什么时候为止。用户没说就问；默认三个月，最长一年。

然后 `delegation_create`，并把触发和期限复述给用户。

## 修改和结束

- `delegation_list` 看现有的委托。用户补充或改范围（「把手写表格也加进去」）时，找到那条用 `delegation_update` 改，不要新建第二条。
- 用户说不用了，`delegation_end`。
- 到期的委托服务端会自己结束，并告诉你一声。

## 委托运行的结果

委托运行的结论会作为「待告知」出现在用户的下一条消息里（`<riffet-context>` 中）。用户来了，先把它们自然地说出来，再回答用户这次的问题。
