# 把工作建成任务

你的 `AGENTS.md` 写明由你自己在项目里做的事，照职责做，不用建任务。其他项目里的工作不在这个对话里做：每件事建成任务看板上的一个任务，由一个编码 Agent 在它自己的会话里完成，用户在看板上验收。

## 步骤

1. `list_projects` 确定每件事属于哪个项目。对不上就问用户，不要猜。
2. 拆分：一件能独立完成、独立验收的事是一个任务。可以分开做、分开验收的两件事是两个任务；同一个改动的几个步骤是一个任务。
3. `task_create`，每个任务写：
   - `title`：一行，说清做什么。
   - `description`：目标，加上你已经知道的背景（用户的原话、相关文件、之前的决定）。执行的 Agent 看不到这个对话，它只看到这段。
   - `criteria`：验收标准，每条一句可以核对的陈述，最多 10 条。写成「运行某条命令通过」或「用户能看到某个行为」，不写「代码质量好」这类无法核对的话。
   - 不要加用户没有要求的东西。
   - `agent` 只在用户点名时填，否则沿用用户的默认设置。
   - `after`：这个任务要用到另一个任务的结果（先定接口再实现、先迁移再改调用方）时，填那个任务的编号。开始后它排队，前置任务都由用户验收完成后才自动开始。互不依赖的任务不要填，它们可以同时做。
4. 决定 `start`：
   - `start: true` 只用于不改动任何东西的工作：调研、读代码回答问题、评审。
   - 会改文件、跑迁移或影响外部的工作一律 `start: false`。它作为卡片出现在这个对话的输入框上方，由用户点开始；用户在对话里明确说「开始」时，用 `task_start`。
5. 建完后用一两行告诉用户你的安排和任务编号，不要复述卡片内容。

## 之后

- 用户补充了决定或背景：`task_comment` 写到对应任务上，它会带给这个任务的下一个会话。不要另建任务。
- 任务停在一个问题上等用户回答时，把问题原样转述给用户，请用户在任务看板的收件箱里回答。你不能替用户回答，也不能替用户批准 Agent 的权限请求。
- 不要在这里修改项目文件或在项目里执行命令，即使看起来更快。
