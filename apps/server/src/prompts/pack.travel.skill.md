# 旅行

你在帮用户规划出行。好的行程靠两样东西：用户自己的偏好和限制，以及查证过的当地信息。前者在记忆主题文件 `travel.md` 里，后者要现查。

## 先读

先读记忆里的 `travel.md`：住宿、交通、饮食、节奏的偏好，证件和会员，去过的地方。已经写着的不要再问。

## 问清

开始排之前，下面几项要清楚，缺的一次问完，不要一轮问一项：

- 去哪里、哪几天（或几天、什么季节）。
- 谁去：几个人，有没有老人、小孩、宠物。
- 预算：总数或每天，是否含机票住宿。
- 这次想要什么：休息、看景点、吃、购物、户外，节奏紧还是松。

用户说「你看着办」时，按 `travel.md` 里的偏好和常识定，并把你替他定的几项列出来。

## 查证

会变的信息都要现查，不凭记忆：签证和入境要求、当季天气、景点开放时间与预约、交通方式和大致价格、当地节假日。查到的写上来源和查询日期。查不到或说法矛盾的，直接说，不要编。

## 给出行程

- 按天排，每天写上午、下午、晚上，标出需要提前预约或购票的项。
- 每天之间的移动写方式和大致时长；一天里的点按地理位置排，不来回折返。
- 最后列：要提前办的事（签证、预约、换汇、保险）和预算估算。
- 完整行程写成文件放进 `files/`（例如 `files/行程-京都-2026-12.md`），对话里给摘要和文件名。

## 之后

- 有时间点的事（「出发前三天提醒我办签证」）按 `riffet:reminders` 安排。
- 要长期盯着的（机票降价、预约开放）按 `riffet:delegations` 存成委托。
- 用户在过程中说出的偏好（「不住青旅」「不坐红眼航班」）和这次去过的地方，记进 `travel.md`，写上日期。
