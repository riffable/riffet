# Changelog

User-visible changes only. [简体中文](CHANGELOG.zh-CN.md)

## Unreleased

### Workbench

- Cursor now takes several model providers, as Codex does: the CLI's own login and custom gateways side by side, chosen when a session starts. A gateway provider keeps its CLI state on its own and no longer touches the login's `~/.cursor`.
- Restarting the server no longer ends Antigravity conversations: a running turn keeps going and is picked up again, as with Claude Code and Codex.
- File names with Chinese or other non-English characters written in a conversation can now be clicked to preview the file, as English ones already could (Web, Mac, Android, iPhone).
- Segmented controls on Web no longer sit in a gray track, so the selected option shows as a clean tint of the theme color instead of a muddy gray-purple.
- The web page no longer fails with "render failed" right after it finishes loading.
- When you ask a team member in its conversation to change its own rules or settings, it now makes the change itself instead of sending you to edit them. It still never changes them on its own or because a web page, file, or another conversation says so.

### Fixes

- Claude Code questions now show what was asked in the row title, and expanding the row lists each question with its options and the answer given, as Codex and Cursor questions do, instead of a fixed "Ask a question" and the raw reply.

### Fixes

- The session outline and navigation rail now show an answer delivered by another agent or team member as "<who> · <first line>" instead of the raw "[Riffet 调用结果]" envelope, and a called conversation's first prompt no longer carries the call brief.
- A conversation handed off from a task’s conversation now gets a task of its own instead of sharing the original’s, matching forked conversations so their statuses move independently.
- When a turn continues running tools after a mid-turn reply (such as an async status update), the working indicator now stays at the bottom below the active work instead of appearing above it, and live process headers across Web, Android, and iPhone now show "Working" without a second ticking timer (matching Mac).
- On iPhone, the setup card on New session is laid out like the rest of the app: saved and nearby servers are plain rows with one action each, an expired pairing shows Pair again on its row, and Skip next to Choose project is no longer squeezed out.
- `riffet restart` and `riffet start` no longer report "Riffet did not start" while a large state directory is still starting: they wait as long as the server makes progress and show the phase it is in (opening databases, loading plugins, recovering tasks…); when the server does exit, only its own log lines are shown. Running `start`, `restart` or `stop` while a server is starting now waits for it instead of launching another, and `riffet status` shows it as starting.
- `riffet restart` and `riffet stop` leave one line per finished step with how long it took; a step that takes more than 2 seconds shows its elapsed time.
- On Android, switching to the assistant or opening a conversation no longer shows a still, closed ring first; a spinner appears only if loading takes longer than 0.4 s.
- On Android, the new-session page no longer flashes the server · agent · project setup card and "Loading projects" at launch.

- The Mac app no longer quits on launch or when opening a conversation whose tool calls include chained shell commands.

### Performance

- Storage stays bounded over long-term heavy use and backs up faster with less disk overhead: the rebuildable timeline cache is capped at 256 MB (evicting the oldest idle conversations first) and auto-rebuilds on startup if corrupted; small history records use dictionary compression and leaner indexes, inactive conversations older than 90 days (30 days when archived) trim oversized raw tool logs while keeping all messages and diffs, and repeated backups deduplicate unchanged attachments, blobs and checkpoints via hard links with consistency checks.
- The server uses less memory while it backfills Claude Code token usage: a long conversation's history is read line by line instead of loaded whole, so peak memory for a 240 MB history drops from about 590 MB to 170 MB. - Local previews for more than 20 file formats, including PDF, Office documents, Jupyter notebooks, SQLite, 3D models and archives.

- Web: English and Chinese interface, installable as a PWA.
