# Code Studio

Code Studio 是一个工作台页面，按 IDE 的方式读一个项目：左侧是模块或文件夹，中间是标签页和打开的文件，右侧是结构，底部是查找结果。它面向在 Android Studio 里只用来看代码的场景：大仓库（抖音 Android：38.6 万个文件、2249 个 Gradle 模块）在 Studio 里同步和索引都很重，这里不需要 Gradle 同步，也不编译。

状态：**服务端与 Web 已实现（第一版）**；Mac 与手机不做（见「各端」）。

## 1. 组成

| 部分 | 位置 | 职责 |
| --- | --- | --- |
| 声明索引 | `apps/server/src/workspace/symbols/` | 子进程用 tree-sitter 解析 Kotlin 与 Java 并直接写进按项目的 SQLite，按文件大小与修改时间增量更新；服务主线程只分派路径、读进度和查询 |
| 跳转与引用 | `apps/server/src/workspace/code-nav.ts` | 原有的基于搜索的导航；索引就绪时先查索引，按类名查引用时只扫引用了它的文件 |
| 接口 | `apps/server/src/routes/workspace.ts` | `/api/projects/:id/code/{symbols,outline,index,modules,definition,references}` |
| 契约 | `packages/contracts/src/workspace.ts` | `CodeSymbol`、`CodeOutline`、`CodeIndexStatus`、`CodeModules` |
| 宿主组件与写服务 | `apps/web/src/plugins/CodeFile.tsx`、`apps/web/src/plugins/host.ts` | `UiKit.CodeFile`、`UiKit.FileIcon` 与 `PluginHost.workspace`：复用文件面板的 CodeMirror 6 + Shiki、共享草稿池（`fileDrafts`）、乐观锁保存与 `unifiedMergeView` 冲突合并、按文件 LRU 保活的 `EditorState`（切标签保留撤销栈、折叠与选区），以及文件增删改名与回收站撤销 |
| 页面 | `plugins/riffet/code-studio`（内置插件 `riffet.code-studio`） | `main` 位置的单实例视图 |

数据与读文件由核心提供，页面放在内置插件里，可以整体关掉。插件经 `WebPlugin.access.requests` 只声明项目的 `files`、`file`、`find`、`search`、`code/` 与 `git/{head,file,blame,commits/,refs,switch}` 路由。

## 2. 页面

- 页面读的是哪台服务器上的哪个项目，写在页头标题之后（`ViewProps.header`）：`Code Studio › 服务器 ▾ › 项目 ▾`，只有一台服务器时不显示服务器。两个菜单分开选（项目多时不用在一张合并的长列表里找；每台服务器记住自己上次打开的项目）。服务器用链接的名称（设置里填的那个，如 `Devbox xxx`），不用别名（短代号）；离线的列出但不可选。项目菜单末尾是 Open Folder…，打开那台服务器上任意目录：与新会话的「选择其他目录」同一套（本机屏幕上用系统选择器，否则是应用内的目录浏览器，可换服务器），目录还不是项目时登记为项目（`SessionService.openDirectory`）。选一台还没有项目的服务器时直接打开目录浏览器。旧宿主没有页头位置时，两个选择框退回到树的上方。
- 布局不设单独的工具栏。左栏顶部是树的标题行：视图名、在树中定位当前文件、全部折叠、视图菜单（`list-filter` 图标，模块 / 文件，当前项打勾）。右侧第一行行首是项目树开关、后退、前进，中间是标签，行尾是搜索与结构面板开关。
- 面板：项目树、结构、底部查找结果都能拖边缘调整（`UiKit.ResizeHandle`，双击复原），项目树和结构能收起。尺寸与收起状态对所有项目共用，记在本浏览器（`riffet.code-studio.layout.v1`）。
- 模块与目录树：左栏采用侧栏底色（`bg-sidebar`）与中间代码画布拉开层次；构建文件（`build.gradle`、`package.json` 等）所在的目录按路径嵌套，只通向一个东西的目录并成一行。展开模块后依次是 `manifests`、源码根（`java`、`kotlin`，只含一个目录的包并成 `com.example.app` 一行；非 `main` 的源码集标在名字后）、`res`、`assets`、嵌套模块、其他目录和构建脚本。目录在展开时才读，列表只画看得见的行。目录树与标签采用统一 16×16 双色精工图标（`fileIcons.tsx`，JetBrains New UI / Zed 风格：区分展开/收起文件夹、模块右下角实心角标、源码/资源/包/清单及主流语言与 Gradle/XML/JSON/YAML 等语义色微标，全部绑定主题语义变量）；非活跃行文字退至 `fg-2`、低优先级目录（`build`、`log`、点文件等）弱化至 `fg-3`，缩进线在悬停时显现并高亮当前文件所在父目录的活跃链路，行尾显示未保存圆点与目录悬停快捷新建入口。
- 树的键盘：↑↓ 移动，→ 展开或进入，← 收起或回到上一级，Enter 打开并保留标签，空格预览，Home/End、PageUp/PageDown 跳转。右键：文件是打开、复制路径、引用到会话；目录是在此目录内搜索（Find in Folder，搜索弹窗的范围多一个该目录）、复制路径。
- 标签：当前标签下划线（`UnderlineTabs` 的样式）。单击树或查找结果打开的是预览标签（名字斜体），下一次这样打开会替换它；双击标签或树、Enter、或从它里面跳走后保留。新标签开在当前标签右边；关闭当前标签时左边的接上。中键关闭，右键：关闭、关闭其他、关闭右侧、关闭全部、保留、在树中定位、复制路径、引用到会话。回到一个标签时停在上次看到的位置。
- 搜索：一个弹窗（`UiKit.QuickPanel`，与 ⌘P、⌘K 同一种），连按两次 Shift 或标签栏的搜索按钮打开。页签 All、Classes、Files、Symbols、Text、Actions，Tab / ⇧Tab 切换，查询在页签之间保留，再打开时选中上次的查询。
  - All 列出类、文件、符号与命令各前几条；查询为空时 All 与 Files 列出最近打开的文件。
  - 类名按整名、前缀、驼峰首字母（`FF`）和名字里后面的词（`Fragment` 找到 `FeedFragment`）匹配，符号只按前三种。`Name:120`（或 `Name:120:8`）打开到该行，`:120` 跳到当前文件的那一行。
  - Text 是 Find in Files：区分大小写（⌥C）、整词（⌥W）、正则（⌥X）、文件类型（`*.kt, *.java`，遵守 `.gitignore`）、项目或当前文件所在模块；下方预览选中的那一处。⌘/Ctrl+↵ 把全部结果放进底部面板。
  - 不把「没搜完」写成「没有」：索引没建好时类与符号给出提示；文本搜索到了时间或大小上限、有文件读不了、或还有更多结果时，列表末尾写明；搜索失败显示原因。
  - Actions：定位、引用到会话、作者标注、跳到行、后退、前进、最近文件、项目树与结构面板开关、切换视图、折叠树、重建索引、关闭全部标签；有快捷键的在行尾写出。
- 编辑与读文件：服务端支持 `file-write-v1` 时，桌面端打开项目内 UTF-8 文本文件默认可编辑（触屏设备默认只读，状态栏可随时切换只读锁）；与侧栏文件面板共享未保存草稿池与离开页面守卫。支持多光标（`⌘/Ctrl+D` 逐个选中下一个词、Alt 拖拽列选）、括号与引号自动闭合/包裹选区、智能换行缩进、按语言切换行注释（`⌘/Ctrl+/`）、行上下移（`Alt+↑/↓`）、复制行（`Shift+Alt+↑/↓`）、删除行（`⌘/Ctrl+⇧+K`）、撤销/重做与软换行（`⌥/Alt+Z`）。切换标签时按 `FILE_BUDGET.draftsKept` 上限缓存 `EditorState`，切回保留撤销栈、折叠和选区。保存（`⌘/Ctrl+S`）与全部保存（`⌘/Ctrl+⇧+S`）均携带打开时的内容哈希；外部改动（如 Agent 写入）在无草稿时静默跟随磁盘，有草稿时在编辑器顶部给出警告条，支持 `unifiedMergeView` 逐块比较合并、采纳磁盘版本或覆盖保存。编辑态点击行号选中整行（`Alt+Click` 或右键仍可引用到会话）。预览标签一旦修改立即转为保留标签，关闭未保存标签先确认。
- 路径栏：文件路径后接光标所在的声明（类 › 方法），点击声明项直接弹出当前类成员或同级符号下拉菜单（零宽度占用即可快速跳转）；行尾是保存（有未保存修改时）与引用到会话。
- 分屏编辑：按 `⌘/Ctrl+\`、在文件/标签右键菜单选 `Open to the Side` 或从 Actions 面板打开右侧并排编辑窗，可独立切换文件并共享同一份草稿池，两处修改实时同步。
- 结构与右侧工具窗口：右侧栏默认收起，把完整水平宽度留给代码画布；点击标签栏最右侧开关按钮、或经 Actions 按需展开。展开后除 Structure（柔和圆角符号微标，属性弱化降噪）外，还放别的插件给这个项目的视图（Android 构建、Logcat 等）。
- 文件树操作：服务端支持写入时，项目树顶栏 `+` 菜单与右键菜单提供 `New File…`、`New Folder…`、`Rename…`、`Delete`；重命名同步更新已打开的标签、分屏、草稿与编辑器状态缓存，删除走 24 小时回收站并在 toast 提供撤销。
- 跳转：⌘/Ctrl 点击标识符或 F12 跳到声明；有多处时在底部列出；在声明本身上列出引用。⌥F7（或 ⇧F12）查引用，结果可在模块与项目之间切换。右键标识符：跳到声明、查引用、在文件中搜索这个词、引用这一行到会话、作者标注。
- 后退与前进：每次跳转（声明、查找结果、搜索、换标签、树里打开）记下离开的位置，⌘[ / ⌘]（Mac 另有 ⌃- / ⌃⇧-；其他系统 Alt+← / Alt+→）或标签行行首的箭头往返；同一文件里相距不到 10 行的不重复记。换项目时清空。
- 路径栏：文件路径后接光标所在的声明（类 › 方法），点一级跳到它；行尾是引用到会话。在树里定位在树的标题行（两种读法都展开到该文件）。点行号引用那一行。引用会转到该项目的新会话页并加进输入框（`NavigationService.quote`）。
- 工具窗口：右侧一栏除了结构，还放别的插件给这个项目的视图——Android 构建插件（`riffet.android`）的 Android、Logcat、Configs，以及接管它的插件（如抖音构建）改过的同一套动作。列哪些与会话侧栏一样判断（项目类型、在侧栏里隐藏的不列，只取按项目的视图），没有时栏头只写 Structure，有时栏头是 Structure 与各视图的页签。视图的实例与侧栏的是同一个，任务属于服务端，换页签或离开页面只停它的轮询；打开过的视图在页面里保持挂载，切回来状态还在。显示工具视图时这一栏至少 340 宽（这些视图按侧栏的 320 起做）。视图里打开的文件（构建错误的文件与行）在这里的标签里打开（`ProjectView.onOpenFile`）：绝对路径在项目根下的换成项目内路径，在项目外的提示打不开。Actions 里每个视图有一条「Show …」。接口是 `useProjectViews(projectId)` 与 `UiKit.ProjectView`（[插件界面](design/system/plugins.md) §4）。
- 结构：当前文件的声明成树，类型可收起，每层有缩进线，种类字母按代码里同类名字的颜色着色。光标（没有光标时是首个可见行）落在哪个声明里就标出并滚到哪个：服务端给类型与函数带结束行（`CodeOutlineItem.endLine`），所以落在两个方法之间时不会误标前一个。
- 查找结果：按文件分组、可收起，行里标出匹配处；↑↓ 逐条打开（文件行跳过），←→ 收起展开，Esc 关闭。
- 状态栏：左侧为索引状态与未保存文件计数（点击全部保存），右侧为 Git 分支、光标行列与多选区/字符计数（点击跳到行）、缩进风格切换（`Spaces: 2/4`、`Tabs: 2/4`）、行尾（`LF`/`CRLF`）、软换行开关与只读/可编辑锁。
  - 索引：建库或核对时转圈并写百分比，平时写符号数。点开是详情（`UiKit.Popover`）：进行到哪一步（列文件、解析、压缩库，服务端的 `CodeIndexStatus.phase`）、文件进度条与已做/总数、符号数、上次建好的时间、按最近一分钟的速度估算的剩余时间、失败原因，以及「只在页面可见时运行」和重建按钮。详情开着时每秒取一次状态，关上后回到每 5 秒。
  - 分支：点开列出本地分支（当前的打勾在最前，签出在别的工作树里的不可选），选一个即签出（`POST .../git/switch`，与 Git 面板同一个接口：会话正在改这个项目时、或未提交的改动会被覆盖时服务端拒绝并说明原因），下面是复制分支名与提交哈希。HEAD 一变（在这里签出，或别处提交、签出后回到页面），打开的文件、结构和树都重读，位置不变；模块列表变了才换。
- 没有打开文件时，编辑区列出几个入口与它们的快捷键。
- 双击标签：预览标签变成保留的标签；其他标签最大化编辑区（收起项目树、结构和底部面板），再双击或 Esc 复原。新的查找或比较结果出来时自动复原。双击查找结果的一行，在保留的标签里打开。
- Esc 在页面里归读代码的人（关查找、退出最大化），不会关掉整个页面（页面层只在 Esc 没被处理时关闭）。
- 右键菜单（`menus.ts`，用 `UiKit.ContextMenu`，子菜单是 `MenuEntry` 的 `submenu`）：每处显示文件、行或符号的地方给同样的分组、同样的顺序——先导航与查找，再复制，再 Git 与折叠子菜单，最后引用到会话。浏览器自带的右键菜单在页面里不出现（代码区经 `CodeFile.onMenu`）。
  - 代码（任意位置，含行号）：Go to Declaration、Find Usages（在标识符上时）；在文件中搜索选中文字或光标处的词、Find in File（⌘F）；Copy（有选区时）、Copy Path/Reference ▸（项目内路径、绝对路径、文件名、带行号的路径；在声明自身上时加限定名 `包.类.成员`）、Select All；Folding ▸（光标处折叠、展开，全部折叠、展开）；Git ▸（作者标注、Compare with HEAD）；引用这一行到会话。
  - 文件（树、标签、路径栏的文件名、查找结果的文件行）：打开；Kotlin / Java 文件按文件名查类的引用；在所在目录内搜索；在树中定位；Copy Path/Reference ▸；Git ▸；引用到会话。标签另有关闭、关闭其他、关闭右侧、关闭全部、保留、最大化、重新打开刚关闭的标签（记最近 20 个）。
  - 目录、模块、包（树、路径栏的目录段）：在此目录内搜索；Copy Path/Reference ▸。树的空白处：定位当前文件、全部折叠、View ▸（Modules / Files）、整个项目的搜索与复制。
  - 结构和路径栏里的声明：跳过去、查引用、在文件中搜索名字、复制限定名或带行号的路径、引用到会话。
  - 查找结果的一行：打开、在新标签打开、复制这一行、Copy Path/Reference ▸、引用到会话；空白处：全部展开、全部收起、关闭。
  - 作者标注那一栏：Show Commit、复制提交哈希、Close Annotations。
  - 状态栏：索引处重建索引；行列处跳到行、复制带行号的路径（分支见上，点开即是）。
  - 图标：菜单的每一项都带图标，与应用其余菜单一致；子菜单里的项不带（它们是打开它那一行的变体，同一个图标排一列没有信息）。
- Compare with HEAD 在底部面板（与查找结果同一处，后开的替换先开的）用宿主的 `DiffView` 画 HEAD 版本与磁盘上的文件；HEAD 里没有的文件写明是新文件，二进制或超过预览上限的不比较。
- 没有做的：Refactor（页面只读，改代码交给 Agent；要在菜单里直接把「重命名某符号」之类交给会话，需要宿主先提供往输入框里写入文字的接口）、Open In（外部编辑器、访达只对本机项目有意义）、文件历史（大仓库太慢，见 §3.1）。
- 快捷键只在页面内生效：⇧⇧ 打开搜索（All），⌘/Ctrl+O 找类，⌘/Ctrl+⇧+O 找文件，⌘/Ctrl+⌥+O 找符号，⌘/Ctrl+⇧+F 全文搜索，⌘/Ctrl+E 最近文件，⌘/Ctrl+L 跳到行，⌘[ / ⌘] 后退前进；光标在文件里时 F12、⌥F7、折叠键。⌘B 留给工作台的侧栏开关。
- 页面文字整块英文，与 Git 面板、Trace 相同；页面名 Code Studio 各语言相同，与工具名保留英文的做法一致。

打开的标签、预览标签、当前文件、最近打开的文件、文本搜索的选项、树的读法和结构面板开关按服务器与项目记在这个浏览器里（`localStorage` 的 `riffet.code-studio.v1`），不同步。

## 3. 索引

- 位置：数据目录下 `code-index/<项目根路径的哈希>.db`，可随时删除，下次查询时重建。
- 何时建：只在 Code Studio 页面可见时建。页面每 `CODE_INDEX_BUDGET.watchMs / 3` 续一次「观察」（`POST .../code/index/watch`），索引没有或距上次核对超过 `recheckMs` 时开始建或增量核对；离开页面（切到别的页面、浏览器标签进后台、关闭）时页面撤销观察，或 `watchMs`（15 秒）内没有续约，服务端立即中止建库并杀掉解析子进程，已写完的批次保留，下次接着做。查询（页面的搜索、Files 面板的跳转与引用、Agent 的 `code_*` 工具）只读现有索引，不会开始建或核对。
- 离开页面时页面上进行中的请求都中止：引用与文本搜索（服务端随之杀掉 ripgrep，回到页面重跑）、blame 与提交版本读取（杀掉 git，回到页面接着读）、搜索弹窗；模块列表读过后不重读。
- 新鲜度：索引是上次核对时的内容；用它回答时再加上自上次核对以来变过的文件（与核对时的 git HEAD 比较的差异、核对时就未提交的文件、未跟踪文件），这些文件直接读。取不到这份清单（非 git 仓库、git 超时、超过 `changedFiles`、服务刚重启还没做完第一次核对）时索引不回答「没有」，退回扫描。刚创建且没 `git add` 的文件最长 20 秒看不到。
- 释放：`CODE_INDEX_BUDGET.idleCloseMs` 无人查询就关库；同时打开的库至多 `openIndexes` 个；解析子进程建完即退出，内存全部还给系统。
- 范围：文件清单里的 `.kt`、`.kts`、`.java`，以及 `res/<目录>/<文件>` 形式的 Android 资源文件；超过 `fileBytes` 的源文件不解析，但会作为每次成员引用查找的候选。除声明外还存每个源文件出现的标识符（倒排）和资源定义位置。其他语言的结构面板为空，跳转仍走原来的搜索。
- 整词文本搜索走倒排（抖音，索引就绪后，2026-11-23）：`mFollowType`（2 个文件）限 `*.kt,*.java` 整词 39 ms–1 秒（首次含变动文件清单约 1 秒），原先全仓扫描 20 秒仍不完整；`getContext` 读满 50 条 0.2–0.4 秒；事件循环最长卡顿 20–50 ms。`include` 含其他类型或不是整词标识符时仍全仓。文件名搜索（`rankPaths`）改分片后事件循环卡顿由 130–200 ms 降到 8–15 ms，耗时不变（100–250 ms）。
- 文件名候选与未跟踪清单（抖音，51.6 万条路径，2026-11-23）：构建文件名候选原先一次同步算完约 0.75 秒，整个服务停住；现分片让出事件循环，总耗时约 0.45 秒，事件循环最长卡顿 12–18 ms。未跟踪清单改用 `git status -unormal` 加新目录展开，约 2–5 秒（`ls-files -o` 约 15 秒），刷新间隔由 60 秒缩短到 20 秒。内容搜索（限 `*.kt,*.java`、整词、区分大小写）首页 7–11 秒（冷盘），常见词 0.1 秒；找不到的罕见词扫完全仓会撞 20 秒上限，响应标 `incomplete: 'time'`。
- 实测（抖音 Android，34.1 万个文件：27.6 万个源文件加 6.6 万个资源文件，2026-11-23）：全量建索引约 5 分钟（不含倒排与资源时约 3.5 分钟），库 1.43 GB（其中倒排 157 MB、939 万行；声明 412 万个、资源 32 万行）；服务进程常驻内存建库前后都在 250–350 MB，事件循环最长卡顿不到 1 秒；无变化的核对约 7 秒；类名搜索 1–30 ms；类的引用按 import 收窄时 14 ms（全仓扫描 13 秒以上；之后改为按倒排读，见下）；跳转到库里的类 73 ms。成员引用：罕见方法名 6 ms（ripgrep 16 秒），`onViewCreated`、`getContext` 这类常见名读满 1000 条约 110–140 ms（ripgrep 1.5–2.3 秒，倒排查询本身 13–20 ms）；`R.layout`、`R.string`、`R.id` 与 xml 里的 `@+id` 跳转 0–10 ms。变动文件清单（`changedSince`）：暂存区没变时约 100 ms，2 秒内重复调用走缓存；加上它之后，罕见名引用冷启动约 100–270 ms、常见名读满 1000 条 240–280 ms；库里的类（`Bundle`）定义跳转 105 ms（取不到清单时要扫描全仓，18 秒）。解析子进程的内存主要是 tree-sitter 的 wasm 堆，随解析的文件数增长（1 万个文件约 770 MB，取词与资源解析只多约 13 MB），所以每个子进程解析 `workerRecycleFiles`（1 万）个文件后换掉，建库时四个子进程合计约 3 GB。
- 上限都在 `packages/contracts/src/budgets.ts#CODE_INDEX_BUDGET`。

## 3.1 Git

供行号旁的作者标注、与 HEAD 的对比、提交详情和签出本地分支用（除签出外都只读）；路由在 `apps/server/src/routes/git.ts`，实现在 `apps/server/src/git/{index,read}.ts`，契约 `GitHead`、`GitFileAtRev`、`GitBlame`，上限 `GIT_READ_BUDGET`。提交详情（`GET .../git/commits/:hash`，`GitCommitDetail`）、分支列表（`GET .../git/refs`）与签出（`POST .../git/switch`）是 Git 面板已有的接口。

- `GET /api/projects/:id/git/head` 返回 `{ branch?, head, short }`（游离 HEAD 没有 `branch`）。不是仓库时 `NOT_A_GIT_REPOSITORY`（422），没有提交时 `GIT_NO_COMMITS`（409）。
- `GET .../git/file?path=&rev=HEAD`：`rev` 只能是 `HEAD` 或 7–64 位十六进制哈希，其他表达式 `INVALID_REV`。一次 `cat-file --batch`；文本超过 `FILE_BUDGET.previewTextBytes` 时截断并带 `truncated`，二进制只带 `binary`，该提交里没有这个文件带 `missing`。
- `GET .../git/blame?path=&start=&end=`：对工作区文件执行 `git blame --porcelain -L`，未提交的行哈希全零（不在 `commits` 里）；范围超过 `blameMaxLines` 时从 `start` 起截断，超过文件行数时截到文件末尾，返回的 `end` 是实际范围。超过 `blameMs` 杀掉子进程，返回 `GIT_TIMEOUT`（504）；抖音上整文件 blame 超过一分钟，120 行的窗口冷缓存 4–21 秒，同一窗口再读约 4 秒。
- 同一仓库的 blame 一次只跑一个，后来的排队（至多 `blameWaiting` 个，再多返回 `GIT_BUSY` 429）；请求断开时排队的退出、运行中的子进程被杀。结果按（仓库、HEAD、路径、文件修改时间与大小、范围）缓存在一个按条数、字节和空闲时间限制的 LRU 里，滚回去不再调用 git。
- 不联网：读取都带 `--no-optional-locks` 与 `GIT_NO_LAZY_FETCH=1`（git 2.44 起），部分克隆里缺的对象返回 `GIT_OBJECT_UNAVAILABLE`，不去远端拉。

页面上：
- 状态栏显示分支（游离时显示短哈希）；窗口回到前台或页面重新可见时再读一次。不是仓库或 git 答不上来时不显示任何 git 内容。
- 行号右侧的改动标记：打开文件时读它在 HEAD 的版本（`UiKit.CodeFile` 的 `baseline`），新增的行绿条、改过的行强调色条、删掉的地方一道红线，在浏览器里比对，不再调 git。新文件整篇算新增；二进制或被截断的不标。最近 20 个文件的 HEAD 版本留在页面里。
- 作者标注（Annotate with Git Blame）：右键菜单的 Git ▸ 或 Actions 打开（同一处变成 Close Annotations），只对当前文件，换文件即关。按看得见的行每 200 行一块去读，滚到哪读到哪，同时只有一个在读；未提交的行留空。日期与作者分两段，日期用等宽数字对齐，作者过长时截断作者而不截日期。失败先静默重试一次（被超时打断的那次已经把 git 的缓存焐热），再失败才提示并关掉。
- 点标注的一行，在底部面板打开那个提交（与查找结果同一处）：标题、作者、时间、正文、改动的文件（状态字母、行数），右边是选中文件在这个提交里的改动（父提交与该提交两个版本，用 `DiffView` 画）；来自的那个文件先选中。双击文件打开它现在的版本。二进制或超过预览上限的不画。
- 分支比较、整个仓库的历史用右侧的 Git 面板，这里不重做；单个文件的历史在抖音上要十几秒，暂不做。

## 5. Agent 工具

内置插件 `riffet.code-studio` 声明工具组 `riffet.code-studio/code`（前缀 `code_`），把同一份索引给 Agent，与 `riffet.browser/browser` 一样在输入框「技能与工具」里按会话选择，选了才出现在这条会话的 Riffet MCP 里。实现在 `plugins/riffet/code-studio/tools.ts`，经 `host.code`（`PluginHost.code`，核心的只读代码导航，见 [PLUGINS.md](PLUGINS.md)）取数，不自己读文件。

| 工具 | 参数 | 回答 |
|---|---|---|
| `code_search` | `query`、`types?`、`limit?`（至多 40，默认 20） | 声明：`kind 名称 path:line (包名)`，好的在前 |
| `code_definition` | `path`、`line`、`word`、`column?` | `path:line  行文本`；`column` 缺省取该行第一个 `word`，同行出现两次时再传 |
| `code_references` | `path`、`word`、`scope?`（`module` 缺省、`project`）、`limit?`（至多 100，默认 40） | `path:line  行文本`，附总数 |
| `code_outline` | `path` | 一个文件的声明及行号，不要索引 |
| `code_index_status` | 无 | 索引状态与规模 |

- 只作用于这条会话所属的项目：没有项目参数，`projectId` 取自会话，经 `host.code` 走与项目路由相同的路径检查（`resolveScopedPath`），读不到项目外的文件。没有项目的会话得到 `NO_PROJECT`。
- 路径是项目相对路径，行列从 1 起；输出是单行 JSON，行文本截到 160 字符，列表有上限并写明还有多少没列出。
- 不把「没答出来」写成「没有」：每条结果带 `indexReady`（索引就绪且覆盖全部文件）与 `index`（`ready`、`building 35%`、`failed`、`partial` …），引用另带 `complete`；`code_search` 在索引没好、失败或被截断时附 `note`（如「Index building 35%; results may be missing, fall back to rg」）；跳转与引用在索引没好时由核心扫描项目作答，所以只在跳转为空（「confirm with rg」）或引用超出预算（`complete: false`）时附 `note`。Agent 的调用不会开始建索引：没建过时 `note` 说明索引只在 Code Studio 打开时建，让它退回 rg。
- 描述里写明：大型 Kotlin、Java、Android 仓库优先用它而不是 grep；其他语言只有文本扫描的跳转与引用，没有结构。
- 多服务器（[规范](guide/multi-server.md) §2）：属于 A 类工作对象。工具在会话运行的服务器上执行，查那台服务器上的项目与它的索引；没有跨服务器的参数，也不查别的项目（§3.6：普通会话的 Riffet MCP 不提供经链接的工具）。工具组的作用范围随 `agentTools` 的登记（对象）；对端离线时会话本身不可用，工具随之不可用。
