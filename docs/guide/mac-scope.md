# Mac 客户端范围规范

返回 [中文 README](../../README.zh-CN.md)。

Mac 客户端不逐项复刻 Web。本文规定 Mac 做什么、不做什么、Web 新增功能时 Mac 怎么处理，以及已有的原生实现怎么对待。Mac 的实现方式见 [MACOS.md](../MACOS.md)，界面写法见 [macOS](../design/system/macos.md)。

状态：2026-11-20 定稿。§3.4 的「转到 Web」已实现（`Services/WebHandoff.swift`，Web 的 `/settings/<分区>` 与 `#handoff=`），未在真实浏览器和运行中的 App 里验收；§5 第 1 项（Mac 作为设备，T0）已实现，同样未验收；其余按顺序进行，缺口列在 §6。

## 1. 定位

| 组件 | 运行位置 | 只有它能做的 |
| --- | --- | --- |
| 服务端 | 守护进程，可以在任意机器上 | 运行 Agent，保存会话与配置 |
| Web | 浏览器标签页，由服务端提供 | 不用安装；功能全集；管理每台服务器自己的配置 |
| Mac App | 用户的图形登录会话 | 系统权限与全局入口；托管本机服务；窗口关闭后仍在运行 |

Mac App 的职责按优先级排列：

1. **系统能力**：把这台 Mac 提供给 Agent 和用户，包括设备能力、全局入口、通知与审批。
2. **工作路径**：会话中反复用到的操作，原生实现，行为与 Web 一致。
3. **本机服务托管**：安装后不配对、不填令牌即可使用。

两条约束：

- **Web 是功能全集。** 除系统能力外，Mac 不提供 Web 没有的功能。
- **功能在 Mac 上不缺席。** 一项功能在 Mac 上要么有原生实现，要么有一步到达 Web 对应页面的入口；不出现只做了一部分、其余无处可去的页面。

## 2. 归类

每项功能属于下面四类之一，归类决定处理方式。

| 类 | 判断 | 处理 |
| --- | --- | --- |
| S 系统能力 | 浏览器标签页做不到：需要系统权限（辅助功能、屏幕录制、麦克风）、全局快捷键、菜单栏、系统通知与共享、本机进程和文件，或者窗口关闭后仍要工作 | 主线，排在其他三类之前；不以 Web 是否已有为前提 |
| W 工作路径 | 一次会话的过程中会用到，或者 Agent 正在等人处理：读转录、发消息、审批、切换会话、查看变更、文件和终端 | 原生实现，与 Web 保持同步 |
| L 本机偏好 | 这个 App 在这台 Mac 上的表现：窗口、侧栏、标签页、排版、主题、图标、快捷键、通知范围、本机编辑器、已连接的服务器列表、更新 | 原生实现，Mac 自己决定，不与 Web 对齐 |
| M 管理与分析 | 其余：保存在服务器上的配置、对象的批量管理、统计分析、内容整理 | 不新增原生实现；入口打开 Web 对应页面（§3.4） |

拿不准时按顺序问：

1. 浏览器标签页做得到吗？做不到，是 S。
2. 用户在一次会话里会用到它，或者不处理它 Agent 就停着吗？是，归 W。
3. 它只影响这台 Mac 上这个 App 的表现吗？是，归 L。
4. 以上都不是，归 M。

M 改归 W 要在 [设计决定](../design/DECISIONS.md) 追加一条，写明它进入工作路径的依据。「Mac 上看起来缺一块」不是依据：M 类功能有入口，不算缺。

## 3. 规则

### 3.1 S 系统能力

- 顺序见 §5。同一时期 S 的下一项排在 W 的新增对齐之前。
- Mac 作为设备，沿用 [能力与设备](../DEVICES.md) 的设备通道、工具组和两层开关，不另建协议。
- 默认不抢焦点：截取窗口不激活它，打开链接不把浏览器带到前台。
- 开关在这台 Mac 上，按服务器分别保存，开启时验证本人；服务端和 Web 不能替它打开。这个开关防的是另一台机器上的 Agent：服务端在同一台 Mac 上时，Agent 本来就有这个用户的 shell，开关不构成边界。
- 不提供能在这台 Mac 上执行任意代码的能力：不按路径打开文件，链接只放行 `http` 与 `https`。
- 设计写在各功能自己的文档里（DEVICES.md、[VOICE.md](../VOICE.md)、MACOS.md「原生能力」），本文只定顺序。

### 3.2 W 工作路径

- 对齐的是能做什么，不是画面相同。交互跟平台（[macOS](../design/system/macos.md) §1）；动效、纯展示上的差异不算缺口。
- 规则写在共享层（`:client`、`:core`），Swift 只订阅状态、发命令（MACOS.md「Swift 与 Kotlin 的边界」）。
- Web 改动 W 类行为时，在功能文档里写明 Mac 已跟进还是待跟进；待跟进的记入 MACOS.md「与 Web 的功能对齐清单」。该清单只跟踪 W 类。
- Web 新增的独立页面即使归 W（不在会话里出现的工作方式，如模型协作），也先按 §3.4 给入口，原生实现排在 S 当前一项之后。

### 3.3 L 本机偏好

- 不进对齐清单。Web 的同名设置怎么做，不构成 Mac 要改的理由。
- 例外是控制工作路径行为、保存在服务端的设置（Enter 键行为、默认审批、排队与引导）：它们随 W，取值各端一致。

### 3.4 M 管理与分析：转到 Web

- 不新增原生页面，也不在 App 里用 `WKWebView` 嵌入 Web 的页面：同一个窗口里会出现两套弹窗、菜单和键盘约定（[设计决定](../design/DECISIONS.md) 2026-11-14）。
- 入口放在 Web 上同一功能所在的位置（侧栏导航、设置分区、会话菜单），并进命令面板。动作是用系统浏览器打开该服务器的对应地址；地址格式以 `apps/web/src/app/state/page-url.ts` 为准。
- 配置属于哪台服务器，就打开哪台的网页，与多服务器适配规范对 B 类的规定一致：对端的配置在对端的网页里改。
- 一步到达：落在对应页面或设置分区，不要求再登录一次，重复打开不重复登记设备。做法：Mac 用自己的设备令牌向服务器取一次性配对码，放在地址的 `#handoff=<code>` 里；Web 已登录就丢弃它，未登录才兑换（`apps/web/src/app/App.tsx`）。取码超过 2 秒或失败时不带码打开。
- Mac 上只有一个入口函数 `WebHandoff.open(_:in:)`；页面到地址、设置分区到 Web 分区的对应关系都在 `Services/WebHandoff.swift`。
- 入口行尾用外链图标表示会离开 App，不加说明文字。
- Web 上只面向开发者的页面（`/design`）和不属于工作的内容不设入口。

**首次使用的例外**：没有它就发不出第一条消息的配置，保留最小的原生形式，放在引导里：连接或托管服务、检测 Agent 与登录状态、选择默认 Agent。

### 3.5 已有的 M 类原生页面：冻结

2026-11-20 之前已经实现的 M 类页面（§4）保留，按下面的规则维护：

- 修缺陷，不跟进 Web 之后的新增。
- 页面工具栏提供「在 Web 中打开」。
- 出现下面任一情况时删除该页面，改成 §3.4 的入口，不做修补：
  - 服务端契约或共享层的变化，使它需要一次超出字段改名的改动；
  - 它只显示了 Web 上的一部分数据或选项，而页面上看不出还有其余部分。
- 设计规范迁移（macOS 文档各节的「现状」）先做 W 与 L；冻结的页面只做 `pnpm check:design` 要求的部分。

### 3.6 Web 新功能的处理

功能文档在客户端一节写一行：`Mac：<类>，<处理>`。

| 类 | 要做的 |
| --- | --- |
| S | 设计写进对应文档，排入 §5 |
| W，出现在会话里 | 同一个功能里跟进，或记入对齐清单 |
| W，独立页面 | 确认页面有地址，加入口；原生实现排在 S 当前一项之后 |
| L | Mac 不需要动 |
| M | 确认页面或设置分区有地址，加入口 |

不给 M 类写「Mac 补齐」任务。

## 5. 系统能力的顺序

1. **Mac 作为设备，T0**：列出并截取指定窗口（不激活）、打开链接、读写剪贴板、发通知。按 DEVICES.md 的设备通道接入，工具组 `device:<这台 Mac>` 在「技能与工具」里按对话选；只剩菜单栏时也在线。
2. **Mac 作为设备，T1**：读辅助功能树、点击与输入。设备侧开关和本人确认的规则同手机。
3. **快速提问浮窗**：全局快捷键打开一块不激活主窗口的面板，带上选中的文字、前台应用与窗口标题、当前文档或网址、框选的截图。
4. **语音**：按住全局快捷键说话，转写走 VOICE.md 的服务端接口。
5. **收件箱进菜单栏与通知**：任务看板的收件箱条目（含插件审批，[TASK-BOARD.md](../TASK-BOARD.md) §7）和待确认项列在一起，就地处理。

每一项做完，在 §4 的 S 表里改成「已有」。

## 6. 现状

与本规范不符的现有代码和文档。改掉哪条就删哪条；新留下的不一致也记进来。

- 任务看板的入口只在命令面板里，侧栏没有：Web 按服务器是否支持任务接口决定显示，Mac 没有这个状态。
- 侧栏的模型协作入口不能在 Mac 的「自定义侧栏」里置顶或排序，只跟随服务端保存的置顶设置，并排在原生项之后。
- 设备管理在 Mac 上是「连接」分区的一部分，没有通往 Web「设备管理」的入口。
- 「转到 Web」只打开当前连接的服务器。经链接合并进来的对端，它的配置页还不能从 Mac 直达（§3.4 第三条）。
- MACOS.md「与 Web 的功能对齐清单」包含 M 类条目（设置各分区、统计、扩展页、任务页）。这些是历史记录，不再更新。
- 全局快捷提问会把主窗口带到前台（`Features/QuickPrompt/QuickPrompt.swift` 调 `WindowRouter.shared.showMain()`），不是浮窗，也不带桌面上下文。
- 窗口截图没有共享的大小上限：设备文件的上限只写在服务端（`apps/server/src/workspace/index.ts` 的 `MAX_ATTACHMENT_BYTES`），不在 `budgets.ts` 里。Mac 先传 PNG，靠服务端的 413 逐级降档；编码后超过请求体上限的图可能直接失败而不降档。
- Agent 调用（W 类，[AGENT-CALLS.md](../AGENT-CALLS.md)）在 Mac 上没有原生实现：输入框不能 @ Agent，`agent_call` 画成普通工具行，被调用的会话在列表里平铺。
- Code Studio（W 类，[CODE-STUDIO.md](../CODE-STUDIO.md)）在 Mac 上没有原生页面，视图只声明 `web`。
- Cursor 的提供商在 Mac 上仍是冻结的原生页（`riffet.cursor/provider`，只声明 `macos`），只显示内置的「Cursor CLI」；Web 已改用通用的提供商列表，另加的 Cursor 提供商在 Mac 设置里看不到。
- Mac 作为设备只到 T0。代码里没有辅助功能、事件注入和音频采集的调用（§5 第 2、4 项）。
- 只开了「允许助理修改本机外观」的 Mac，在各端的设备列表和「技能与工具」里显示成可操作的设备，调用任何设备工具都会得到 `DEVICE_CAPABILITY_MISSING`：`allowControl` 没有区分这两个开关。
