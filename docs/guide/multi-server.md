# 多服务器适配规范

返回 [中文 README](../../README.zh-CN.md)。

服务器之间可以互联（设计见 [SERVER-LINKS.md](../SERVER-LINKS.md)）：打开任意一台的 Web，都能看到所有互联服务器的会话。新功能和对现有功能的改动，都要说清楚它在多台服务器下怎么表现。本文规定怎么归类、要回答哪些问题、哪些写法会被检查拦下。

状态：规范先于实现。§3 里的检查随 SERVER-LINKS.md 的 L1、L2 落地；落地之前，按 §2 的清单在功能文档里写明归类和处理方式。

## 1. 原则

- **先归类，再实现**。每项功能属于下面四类之一，归类决定写法（§3）：

  | 类 | 判断 | 处理 |
  | --- | --- | --- |
  | A 工作对象 | 存在某台服务器上、用户工作时要找到它（会话、终端、项目、任务、自动化、高亮、分享） | 合并显示并标出服务器，操作发往所在服务器 |
  | B 环境和配置 | 描述一台机器的能力和设置（插件、扩展、模型源、Agent 与 CLI 登录、更新、诊断） | 不合并。只在用到时按目标服务器出现；要改就打开那台的网页 |
  | C 人的偏好与随手工具 | 属于用户本人、和机器无关（外观、主题、主人资料、个人助理、快速对话） | 只用入口服务器本机的 |
  | D 入口提供的服务 | 入口服务器对客户端提供的通道（推送、语音转写、IM 通道、设备） | 用入口服务器本机的，可以作用在合并后的对象上 |

  拿不准时问：换一台服务器当入口，用户期望它还在吗？期望还在，又只存在一台上的，是 A；期望跟着机器变的，是 B；期望跟着人走、不在意在哪台的，是 C 或 D。各项现有功能的结论见 SERVER-LINKS.md §3「功能归属」。

- **数据只存在所在服务器**。入口服务器只能有缓存，缓存要有上限和释放时机（[性能与资源规范](performance.md) §3.1），链接删除时一起释放；不在入口持久保存对端内容的副本。
- **A 类看得见，就要能搜到、能打开、能操作**。只做合并列表、不做搜索或打开，比干脆不显示更让人困惑。
- **经链接只返回本机数据**。经链接来的请求不再转发；会合并对端数据的接口，经链接被调用时只回答本机那部分。
- **默认不能经链接调用**。漏了适配的结果应该是「对端用不了」，而不是越权。
- **不能削弱对端对它自己的控制权**。链接管理、配对、令牌、设备撤销经链接一律拒绝。
- **对端的配置在对端的网页里改**。不在本机做一套远程设置；入口提供「打开 <名字> 的网页」。
- **普通会话的 Agent 用不到链接**。个人助理是唯一的例外，规则见 SERVER-LINKS.md §3「个人助理」。

## 2. 新功能的检查清单

在功能文档里加「多服务器」一节，逐条回答。不适用的写「不适用」并说明原因。

1. 属于 A、B、C、D 哪一类？
2. A 类：列表数据带不带 `serverId`？能不能经合并列表和搜索找到？操作发到所在服务器了吗？对端离线时怎么显示？
3. 新加的服务端路由：在策略表里登记了经链接来的请求怎么处理吗（§3.1）？
4. 客户端请求：只经按服务器选目标的请求层吗（§3.2）？
5. 新对象的 id 和显示编号：跨服务器会不会重复（§3.3）？
6. 新扩展点或视图位置：插件扩展的是对象还是全局，在核心的对照表里登记了吗（§3.5）？
7. 助理或 Riffet MCP 的新工具：只查本机，还是跨服务器（§3.6）？
8. 入口的缓存：有没有上限和释放时机？
9. 提醒：是不是由入口发出，并按 `(serverId, id)` 去重（§3.7）？
10. 新协议字段：对端是旧版本时怎么办（§3.8）？
11. 会不会削弱对端对它自己的控制权？会的就必须拒绝。

## 3. 规则

### 3.1 每条路由声明链接处理方式

每条路由在策略表里登记经链接来的请求怎么处理。策略表按路由模式写，可以用前缀规则覆盖一组路由，写法与 `app.ts` 的 `PUBLIC_API` 相同；不在每个注册处加参数（服务端约有 330 处路由注册）。取值：

| 取值 | 含义 | 用于 |
| --- | --- | --- |
| `serve` | 经链接照常处理，回答的本来就只有本机数据 | 会话、终端、文件、Git、项目、任务等单个对象的接口；新会话要选的 Agent、模型等 B 类配置的只读接口 |
| `serve-local` | 这个接口在入口会合并对端数据；经链接被调用时只回答本机那部分 | 会话、终端、项目列表，列表流，搜索，bootstrap |
| `deny` | 经链接调用返回 403 `LINK_FORBIDDEN` | 链接管理、配对、令牌、设备撤销，`/api/servers/*`；B 类配置的写接口（在对端自己的网页里改，§3.9），C、D 类接口，本机的网页和文档 |

- 匹配不到策略的路由在运行时按 `deny` 处理。Fastify 的 `onRoute` 钩子收集所有 `/api` 路由，测试检查每一条都能匹配到策略，匹配不到的直接失败，所以新路由不会在悄无声息中可以或不可以被调用。
- 前缀规则下新加的路由自动继承前缀的取值。在 `serve` 前缀（如 `/api/sessions`、`/api/projects`）下加路由时，确认它只碰这个工作对象；碰到本机配置的，在前缀规则之前单独登记 `deny`。
- 本机没有允许对端入站时，这条链接上的请求不论策略一律拒绝。
- `deny` 的路由清单和这条测试属于「鉴权与数据隔离」，按仓库规则保留为核心测试。

### 3.2 客户端只经请求层发请求

- 客户端的 HTTP 请求和 WebSocket 都经同一个按服务器选目标的请求层：本机走 `/api/…`，对端走 `/api/servers/<serverId>/…`，不在业务代码里拼路径。
- `pnpm check:servers` 拦下请求层之外直接写的 `fetch('/api…`、`` `/api/…` ``、`new WebSocket(`。现有的写法记在基线里，只许减少。Kotlin 客户端同理。
- 拿到一个 A 类对象，就知道它在哪台。Web 的请求层按路径或 `sessionId`、`projectId` 参数里的对象 id 自动选服务器（`lib/server-routing.ts`）；不带对象的请求用 `apiFor(serverId)` 或 `serverPath(path, serverId)` 指定，不假定在本机。
- 新建对象没有可依据的 id：新建会话、终端按请求体里的 `projectId` 选服务器，新建项目由调用方给出服务器。新建的对象在列表读到它之前，用列表的 `upsert*(…, serverId)` 先放进那台的列表。

### 3.3 A 类对象的标识

- id 用 UUID 这类全局唯一的值，不用服务器内递增的数。
- 给人看的编号可能只在一台服务器内唯一。例如任务的 `number` 是服务器内递增的，`#128` 在两台上都可能出现。合并显示时，编号要和服务器名一起出现，或者只在单台的上下文里单独出现。
- 线上的 A 类对象不带 `serverId`：客户端从哪台读到它，就记它在哪台（SERVER-LINKS §5）。所以不另设契约里的 A 类清单；新的 A 类对象要做的是让它的 id 出现在请求路径或 `sessionId`、`projectId` 参数里，或在 `server-routing.ts` 的 `OBJECT_PATH` 里加上它的路径。

### 3.4 合并与搜索

- 合并在客户端做（SERVER-LINKS §5）。每台服务器的修订号单独记，不合成一个数。
- 跨服务器的查询（搜索、⌘K、助理的查询类工具）并发发给各台，各台按自己的索引和可见范围回答；客户端按发往哪台记录结果在哪台。
- 没按时返回或离线的服务器不阻塞其他结果，结果里写明不含它。等待时长和条数上限进 `packages/contracts/src/budgets.ts`。

### 3.5 插件扩展点声明作用范围

- 作用范围由核心按扩展点和视图位置登记（`packages/contracts/src/plugins.ts` 的 `DECLARATION_SCOPES` 和 `VIEW_LOCATION_SCOPES`），插件的 manifest 不加字段，已发布的插件不用改。
- `object`：依附在会话、项目、任务等对象上，由对象所在的服务器提供，视图包和数据经链接取来。例子：Agent 后端、`session-view`、`file` 位置的视图（文件查看器，由文件所在的服务器提供）、`taskProviders`、`runtimeControl`。
- `global`：只用入口本机的，并且不能出现在对端的对象上。例子：`sidebar` 和 `main` 视图、插件页、设置页里的操作、`avatarStyles`、`imChannels`。
- `global` 还包括：`host.approvals`（插件放进收件箱的审批，只在入口服务器的收件箱里，对端不提供，链接策略拒绝 `/api/plugin-approvals`）、`assistantEvents`、`assistantPack`（每台服务器的助理只在本机，事件只送本机的委托，包只装进本机助理，§3.6）；视图桥的 `navigation.openExternal`（只打开入口所在客户端的浏览器，不依附对象，转发时不需要服务器）。
- 新扩展点或新视图位置要先在这张表里归入其中一种，不能两者都是；两张表的类型覆盖全部键，漏登记编译不过。
- 插件视图运行在不透明源的 iframe 里（`sandbox="allow-scripts"`），对端的视图包可以在入口渲染；宿主桥接调用（`sessions.*`、`navigation.*`、`commands.execute`）按视图所属对象的服务器转发，权限检查带上服务器。

### 3.6 个人助理与 Riffet MCP

- 每台服务器的助理只在本机显示，不合并。
- 助理能力的声明（`defineRead`）带必填的 `servers`：`local`（只查本机）或 `linked`（可以跨服务器）。`linked` 的能力在数据所在的服务器执行，可见范围和截断规则由那台判断。
- 派到对端的任务记 `dispatchedBy`，只有派活的助理跟进。
- 普通会话的 Riffet MCP 不提供任何经链接的工具。

### 3.7 提醒与推送

- 第一版各台只给直接配对的设备推自己的会话，入口不代推。
- 入口代推（SERVER-LINKS.md L3）时，去重键带上所在服务器：`(serverId, id, kind)`；同一台手机同时配对了所在服务器和入口服务器时，只收到一次提醒。

### 3.8 离线与版本

- A 类界面都要有对端离线时的状态：照常列出，标为离线，不能操作。
- 新协议字段用 `ProtocolFeature` 声明（`packages/contracts/src/protocol.ts`）。对端没有声明某个特性时，入口按旧行为处理，不假定对端已经升级。
- 对端版本不兼容（`compatible: false`）时，只列出它的对象，不能打开、不能新建，提示打开那一台的网页更新。

### 3.9 B 类配置

- 设置页只管本机，不加服务器选择器，也不做远程设置。
- 选择器里需要对端的配置时（新会话选了对端），从对端读取，只读。
- 要修改时，提供「打开 <名字> 的网页」：在新标签页打开对端自己的地址，在那里登录（不经链接取免登录码，见 [服务器链接](../SERVER-LINKS.md) §12 现状）。浏览器访问不到对端时只显示地址。
- 不在入口自己的源下代理对端的网页：对端的页面代码会拿到入口的 Cookie 和 CSRF 令牌。

### 3.10 C 类与 D 类

- C 类只读写入口本机，不经链接同步。以后确实需要同步的（例如助理的 `USER.md`），单独设计。
- D 类作用在对端对象上时，产出的结果发往对象所在的服务器。例如语音转写在入口完成，转出的文字发给会话所在的服务器。

## 4. 正例与反例

| 场景 | 正例 | 反例 |
| --- | --- | --- |
| 新增一个会话列表上的筛选 | 筛选条件在入口作用于合并列表，对端离线时其中的会话照常参与筛选、标为离线 | 只筛选本机会话 |
| 新增一个设置项 | 只在本机设置页出现；对端有同名设置，用户打开对端的网页修改 | 在本机设置页加服务器下拉框，经链接写对端 |
| 新增一个会话里的面板 | 面板数据经 `api(serverId)` 读取会话所在的服务器 | 直接 `fetch('/api/sessions/…')`，打开对端会话时读到本机的 404 |
| 新增一个 A 类对象 | id 用 UUID；登记进 A 类清单；合并显示时编号带服务器名 | 用自增整数作 id，两台合并时冲突 |
| 新增一个插件扩展点 | 在核心对照表里登记为 `object`，由对象所在的服务器提供 | 用入口本机的插件处理对端会话的数据 |
| 新增一条路由 | 在策略表里登记，经链接调用的行为写进功能文档 | 不登记，等到经链接调用失败时再补 |

## 5. 验证

- 用两个隔离实例实测：各用独立的数据目录和端口启动、互相链接（拟定 `pnpm dev:linked`，随 L1 提供）。检查合并列表、打开对端会话、搜索、停掉一台后的离线状态、版本不兼容时的表现。
- 路由声明、`deny` 清单、`serve-local` 经链接只返回本机数据、经链接的请求不再转发，这几项写核心测试（§3.1）。纯界面的部分按仓库规则以实际界面检查为主，不加界面测试。
- 汇报时写明是否在两个实例下验证过、覆盖了哪些场景。

## 6. 现状

下面是已知不符合本规范的现有代码，迁移了哪条就删哪条，新留下的不一致也记进来。

- **Web**：请求层之外直接写的 `/api/` 路径和 `new WebSocket(` 记在 `scripts/servers-baseline.json`，只许减少。其中不带对象 id 的（`lib/shares.ts`、`plugins/isolated/services.ts` 等）经链接时仍发往入口。
- **Web 合并**：任务看板（`app/state/workItemsStore.ts`）只读入口的任务；对端会话上的插件视图仍取自入口的插件（`object` 类扩展跟着对象走还没接）。在接入对端插件目录前，对端对象上的视图无法执行 `plugin.query`。
- **Kotlin 客户端**：`RiffetApi` 一个实例只连一台；`SessionStore`、`ListsFeed` 与各缓存按裸 id 存放。
- **契约**：任务的 `number` 是服务器内递增的；Project、Terminal、WorkItem、Automation、Mark 没有 zod schema，列表流的 `changed` 事件和 bootstrap 没有命名类型。
- **助理**：`defineRead` 没有声明 `servers`。
