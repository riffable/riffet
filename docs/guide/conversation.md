# 对话、模型与会话

返回 [中文 README](../../README.zh-CN.md)。本文汇总工作台对所有后端通用的会话行为：后端适配、设置、输入、渲染、模型与权限语义、上下文用量与输出速度。Cursor 特有的行为见 [cursor.md](cursor.md)。

## 工作方式

工作台保留一种会话类型 `native`，由后端适配器处理各 CLI 的启动、会话恢复、事件、配置与交互。

| 后端 | 原生执行与会话来源 | 终端视图 |
| --- | --- | --- |
| Cursor | 保留现有 tmux CLI、只读 chat store 和屏幕交互实现 | 完整 Cursor TUI |
| Codex | Unix socket WebSocket App Server；使用官方 thread/turn、审批与输入请求（子 Agent 是独立 thread，按 `receiverThreadIds` 跟随） | `codex --remote` 附着同一个 App Server |
| Claude Code | 原生 CLI、hooks 与 CLI 写入的 JSONL 历史（子 Agent 是 `subagents/agent-*.jsonl`）；网页操作经原生 hook/终端确认 | 完整 Claude TUI |
| DeepSeek Harness | 自定义 profile 加载官方 base bundle 与小型 bridge 插件，直接调用原生 agent、会话、模型、审批和提问服务 | 网页直接使用协议交互 |
| Factory Droid | 每个会话一个 `droid exec --input-format stream-jsonrpc` 进程，使用 Droid 自己的会话、模型、Agent/Spec 模式与 autonomy 审批 | 网页直接使用协议交互 |
| TRAE CLI | Codex 的 fork，复用 Codex app-server 驱动（loopback WebSocket + capability token），详见 [TRAEX.md](../TRAEX.md) | 原生 TUI 附着同一个 app-server |

首页只加载当前选择后端的模型目录。模型参数、模式、权限和命令菜单由后端能力决定；目录加载失败会显示可重试原因。输入草稿按项目、后端与配置分别保存，Cursor 特有的 Fast/Max 模型归一化不会用于其他后端。已有会话固定保存 `backendId`、`backendProfileId` 与 `nativeSessionId`，旧的 Cursor 会话仍兼容 `cursorSessionId`。不转换各 CLI 自己的历史格式。

「设置 → Agent 与模型」管理多个配置及新会话默认后端，也可以按 Agent 设置「默认审批模式」。选项来自该 Agent 支持的模式，选择「沿用 CLI 默认」会清除审批覆盖值；保存到服务端后 App 和 Web 共用，仅影响新会话。新会话读取保存后的配置；已经打开或恢复的会话继续使用当时绑定的配置，重启 Web 服务后重新读取。Key 不回显，读取只返回是否已保存。Cursor 的网关与默认模型在「设置 → Agent 与模型 → Cursor → 连接与默认模型」，账户、团队、MCP、插件和命令放在「设置 → CLI 管理」；已有 Cursor 终端仍需重新打开 CLI 才能加载新的启动配置。DSH 既可以使用已安装的同版本 CLI，也可以指定含已构建 Host `lib` 产物的本地源码 checkout；桥接复用其 MIT 源码中的服务接口和持久化格式。

设置按「使用偏好」「工作环境」「支持」分组：外观、通知、输入行为分开；连接、Agent 与模型、CLI 管理、项目配置、文件与编辑器各有入口；诊断、备份与关于放在支持组。桌面保留侧边分类，手机先选分类再进入详情。未保存的提供商、项目配置和编辑器修改会在离开时确认；保存期间等待回执后才能离开。主题和显示偏好保存在当前浏览器，Agent、输入行为与文件访问设置保存在服务端。

DSH 默认在 `~/.riffet/dsh` 建立独立 profile。API 地址和 Key 优先使用工作台 profile，留空时可沿用启动服务环境中的 `DEEPSEEK_BASE_URL` 和 `DEEPSEEK_API_KEY`。已有 DSH 的目录配置需要在 profile 中显式选择；默认独立目录不会复制其他 DSH 安装的凭证或历史。


会话标题后显示项目当前 Git 分支，长名称截断，悬停可查看完整名称；移动端也可在会话信息中查看。新会话首页保留目录选择器，不再重复显示路径与分支。标题右侧是「对话 / 终端」的切换图标（图标表示点击后进入的视图）；变更、文件与 Shell 终端收在右上角的“更多操作”菜单里，变更项右侧直接显示文件数与 +/− 行数，菜单会标出当前打开的面板。终端面板仍可用 Ctrl + 反引号切换，新建终端使用面板里的“＋”。移动端的同一菜单在会话信息面板中展开。

侧栏底部的主题按钮和“设置 → 外观与显示”提供跟随系统、浅色、深色三种选择。默认跟随设备系统外观，登录页也会随系统切换。主题偏好保存在当前浏览器，同一地址下的其他标签页会即时同步；不同设备、协议、域名或端口分别保存。终端、配置编辑器、Git diff 和大文件预览随页面主题更新，切换主题时终端会重放当前画面。

任务运行时可以继续编辑消息、添加附件和引用文件。默认发送进入队列，等待当前任务完成；排队项的“停止并发送”会先停止当前任务，再优先发送该条消息。选择补充当前任务后，如果目标或能力不可用，内容会保留，由用户明确选择是否加入队列。发送记录可靠保存后，已提交内容从输入框移走，等待期间新编辑的内容保留。发送状态暂时未知时，在对应消息旁检查状态；只有可安全重试的提交才提供“重试发送”。

“设置 → 交互与输入 → 任务输出时发送到”提供“排队 / 引导”两个选项，默认排队。改为引导后，在支持引导且存在可接收输入的活动任务时，原发送按钮和发送快捷键会直接将补充说明交给当前任务；正在执行的工具继续运行，消息不等待下一轮。任务结束后可以正常发送下一条。任务仍在运行但暂时无法补充时，内容会保留，你可以选择排队。输入区保留原发送按钮和布局，不额外展示引导按钮；这个偏好保存在服务端，对连接同一工作台的设备生效。

桌面 Web 上，排队消息旁的转向箭头用于补充当前任务，向上箭头用于停止并发送。将鼠标停在图标上可看到对应的操作名称。队列转引导会保留原正文、附件和文件引用；如果后端不支持其中的输入形态，会明确提示并保留可恢复的内容。直接发送仍表示打断后发送，Enter 键偏好独立设置。

当前支持 Codex 0.160.0 及以上、具备工具 hooks 的 Cursor 2026.10.01 及以上，以及 Claude Code 的活动 hook 会话；Web、iPhone、Android 和 macOS 共用这一规则。Cursor/Claude 在下一个工具返回时接收，等待期间显示“等待当前任务接收”；没有后续工具且任务已结束时，会提示未发送。Cursor 初版支持文本和文件引用，Claude 另外支持普通文件附件，图片附件及命令/技能调用暂不支持；这两个后端的渲染输入最多 6,000 字符。Codex 沿用其原生输入能力。

补充消息沿用当前任务的模型和权限，不会因任务结束或连接故障自动投向下一轮。发送中显示简短状态，确认收到后隐藏成功标签；任务结果未知与消息是否发送未知分别处理。“检查状态”读取原记录，不重新发送。Cursor 同一会话里已有后续独立任务完成，且当前输入框空闲、没有草稿或待处理输入时，后面的排队消息会自动发送，旧消息保留原状态。需要手动放行队列时，确认框会显示待发消息数量。修改发送偏好不会改变已有提交的方式和目标。

输入框的 Enter 键默认换行、⌘/Ctrl+Enter 发送；改回“Enter 发送”后 Shift+Enter 换行，而 ⌘/Ctrl+Enter 在两种选择下都发送——这样无论怎么选，键盘上都留着一个能发送的手势。开关在“设置 → 交互与输入 → Enter 键”，是**账号级**设置：写进工作台设置文件，换设备或换浏览器打开同一个工作台都生效；它只影响桌面端的物理键盘，手机软键盘的回车始终换行（手机外接键盘的回车仍是发送）。发送按钮的提示跟着这个选择变（`↵` 或 `⌘↵`），因为它和 Enter 走同一条判定。输入法组合期间的 Enter 只用于选词，不会发送；长按 Enter 也不会连发。

发送后的图片显示缩略图，点击可在页面内放大预览；普通附件可打开预览并下载。旧原生消息也会从已保存的附件信息恢复文件名和图片类型。消息的发送状态、操作和时间戳放在同一行，窄屏按需换行；Web 用户消息的复制按钮位于发送时间后面。

输入框里的图片附件同样是缩略图：发送前就能看清截的是哪一屏，点开在原图预览里看，右上角的 ✕ 逐张移除（移除后焦点落到相邻那张，不回到页面顶部）。从剪贴板粘贴时文件与文字一起收下——复制一段带图的网页内容不会只剩图、也不会有字没图；拖动文件到窗口任意位置都能收，整页会显示落点提示。上限与服务端一致：单个附件 24 MiB、单条消息 20 个；超了整批拒绝并说明是哪个文件超了，不会悄悄只收一半。同一张图重复拖入只算一个。

桌面端输入文字后，模式选择右侧会出现一个无边框的四角展开图标：草稿在居中的面板里铺开写，附件轨、模式/模型/权限、待办与排队卡片都跟着进去，Esc 或关闭按钮退出；关闭后光标和滚动位置还在原处。它刻意没有快捷键——全屏是看得见的状态切换，不值得再占一个组合键。全屏时对话内容仍可见、可用滚轮继续读，但已从 Tab 顺序和点击范围里移出，编辑面只剩眼前这一个。

Agent 产生或查看的图片也会显示：读取图片文件（Cursor 的 Read、Claude Code 的 Read、DSH 的 `read_image`、Codex 的查看图片）、生成图片和截图类工具的结果，在工具行下方直接显示缩略图；回复里用 Markdown 引用的本地图片（`![](/tmp/shot.png)`、相对项目根目录的路径或 `file://` 地址）同样会显示。这些图片按路径经项目的只读图片接口加载，普通文件与文件面板预览遵守同样的读取范围；当前工作台已登记的附件路径按附件权限读取，不受项目外文件读取开关影响。只有原始数据、没有文件路径的图片，小于 40 KiB 时直接内联，更大的显示占位说明。

侧栏会话按最近的消息活动排序，查看历史、同步运行状态、改名或修改设置不会把会话提到最新。会话菜单与页头“更多操作”都可置顶或取消置顶；置顶会话固定在所属项目的列表前面，刷新页面或重启服务后仍保留，取消置顶后回到正常的时间顺序。

## 对话与回答的渲染

回答按 GFM 渲染，并提供代码、图表、数学公式和文件入口。

Web 桌面布局和 macOS 的章节导航附着在当前阅读回答的左侧，在正文与左侧边界之间水平居中，只做透明度淡入淡出；随正文进入、在回答范围内停靠，并随回答末尾离开。阅读位置进入用户消息、处理过程、回答间距或没有目录的回答时退场，不提前展示下方回答的目录。目录取最浅且至少出现两次的 Markdown 标题层级，平铺为一列；留白不足时显示垂直圆点，当前章节的圆点更大。目录默认弱化，悬停正文或目录、键盘聚焦时增强；悬停或聚焦可查看标题，点击定位到章节并停止追随新输出。显示文字目录或圆点导航及退出动画期间隐藏正文宽度拖动条，退场结束后恢复。单独加粗的段落、思考、引用和代码围栏中的标题不进入目录。

章节导航默认开启。Web 在「设置 → 视图」、macOS 在「设置 → 排版」切换，仅保存在当前设备；关闭后立即隐藏目录并恢复宽度拖动条。

同一轮的上下文压缩记录与相邻的思考、工具调用归入同一个处理分组，最终回答单独展示。Web 中被打断的处理过程和引导消息之前的输出保持展开，手动展开或收起的选择优先。

- **代码围栏有语法高亮**，与文件预览共用 `apps/web/src/lib/highlight.ts` 的 refractor 管线，45 种语言（ts/tsx/js/jsx/json/json5/yaml/toml/ini/sh/powershell/py/go/rs/java/kt/swift/c/cpp/cs/rb/php/dart/scala/lua/r/perl/objc/elixir/haskell/clojure/graphql/protobuf/docker/makefile/nginx/diff/regex/html/css/scss/md/sql 等）各自 `import()` 成独立 chunk。围栏进入视口才高亮，且 80ms 去抖——流式回答每帧都在改文字，只有稳定下来才值得分词；产出的 HTML 绑定它对应的那段源码，旧 token 不会贴到新代码上。围栏头部是独立于代码底色的一条工具条。
- **围栏工具条**提供自动换行、复制源码，以及 Markdown、图表、HTML、SVG 的「源码 ⇄ 渲染」切换。
- **图表**：Web、macOS、iOS 和 Android 可渲染 Mermaid、DOT/Graphviz、PlantUML、D2、Vega 和 Vega-Lite。图表随明暗外观与当前配色重新渲染；中文标签和 `<br/>` 换行沿用各引擎语法。引擎在本机提供，消息图表源码只放在 URL 片段中，不发送给服务端；图表中的外部数据、远程图片和未内置的 PlantUML 标准库不加载。Web 可打开图片预览；macOS 在流式回复结束后渲染，分享图片复用同一图表缓存。语法不完整、超出快照限制或渲染失败时保留源码。
- **HTML / SVG** 围栏可在隔离页面预览，HTML 仅使用内联脚本、样式和内嵌资源；页面不能访问工作台存储、登录态或 API。JSX、TSX、MDX 组件不作为应用执行。
- **数学公式**走 KaTeX（`remark-math` + `rehype-katex`）：`$…$`、`$$…$$`、` ```math ` 都渲染；`throwOnError:false`、`trust:false`，KaTeX 拒绝的内容回退成原文（流式里的半截公式保持原文）。超长公式在正文栏内横向滚动，不撑宽对话。
- **行内代码里的文件路径可点**：形如 `src/app.ts:42` 的整段 inline code 变成能打开右侧预览的按钮；`npm run build` 这类不像路径的保持原样。

没有显示章节导航时，会话正文栏的宽度可以直接拖：指针移到正文左侧留白会出现一条竖条，按住左右拖动即可加宽或收窄（双击恢复默认，键盘 ←/→ 也能调，Shift 加大步长）。宽度按浏览器保存并作用于正文、输入框和终端抽屉，桌面端始终给两侧留出拖拽条所需的空间，所以窗口比偏好值窄时也还能拖回来。

侧栏底部「设置」旁的状态只在需要处理时出现（后端 CLI 缺失、Cursor 未登录）；一切正常时这一行不显示状态文字。会话标题用最强对比度，行尾的后端、项目与时间保持弱化。

Claude Code 的运行状态结合原生 hooks、输入框上方的工作状态和后台任务列表判断，兼容 Fast 模式带闪电的输入框边框。终端重绘不完整或版式暂时无法识别时，保留最后确认的状态，不把识别失败当作任务完成。原生已确认的活动回合由 Stop、打断或会话退出结束；停止后仍有续跑或后台任务时继续显示运行。

## 模型、权限与上下文用量

模型选择按后端记忆：在首页或会话里主动选择模型，会写回该后端的新会话默认值，刷新页面或换设备访问都保持。Cursor 同步保留既有 `defaultModel` 设置。不同后端的模型 ID 和参数互不套用；观察已有会话不会改变默认值。权限选择仍需显式选择，不会因为一次使用不受限模式就改变所有新会话。

会话内改模型或权限，各后端遵守同一条语义：**运行时在跑就就地生效，没跑就记在会话上，由下一次打开或下一条消息带上**。落地方式各按自己的协议来：Cursor 与 Claude Code 的模型、权限都是启动参数，所以切换意味着**重启 CLI 并接着当前会话**（正在进行的那一轮结束时才重启）；Codex 走 app-server 的线程配置，每条消息的 `turn/start` 都带上审批策略与沙箱（Codex 的权限是两者成对的预设：Default = `on-request` + 工作区可写，Read only = `on-request` + 只读，Full access = `never` + 不设沙箱；单改审批策略不算权限，`never` 落在未受信项目默认的只读沙箱里时既不能写也不能申请）；DeepSeek Harness 走协议内的会话配置，不重启也不开终端，权限就是 DSH 自己的权限预设（工作区内修改、仅可查看、完全权限，以及工作台 profile 固定挂载的实验层 Auto review），切换经 DSH 的预设服务同时改沙箱与审批策略。反向也成立——**工作台跟随实际生效的值**：你在 CLI 自己那边改过（Cursor 的权限状态行、Claude 的权限模式、DeepSeek Harness 自己的会话选择），下一次读取会把记录对齐到实际生效的那个，而不是拿记录里的旧值把它悄悄改回去（Codex 的 app-server 不回报权限字段，线程模型也暂未采纳，所以这两项目前不跟随）。任何**语义**上的变化都会让会话的 `configRevision` 前进一格（把模型 id 规范化成 CLI 认得的拼写不算变化）。**排队中的消息按它真正开跑时的配置执行**——这与 DSH 自己的做法一致：它在消息的步骤组装时才解析模型与权限，而不是在提交时（它另有 ACP 客户端把选择固定在提交那一刻，那是客户端协议层的取舍）。**进行中也能改**：正在跑的那一轮保持它自己的配置，你在这期间改的配置会被记下来，并在这一轮结束的那一刻自动生效（Cursor 与 Claude Code 在那时重启 CLI 并接着当前会话，DSH 在会话内即时切换、从下一步生效）——所以既不会出现"排队消息因为配置改过而失败"，也不会出现"界面显示新配置、实际跑旧配置"。

Claude Code 的已验证 Opus 模型在模型参数里提供 Fast：默认继承原生配置，开启或关闭仅通过本次 CLI 的 `--settings` 覆盖文件传入，并随 Riffet 会话保存，不修改用户全局设置，也不改变 effort。当前接入要求 Claude Code 2.1.252 及以上，按该 CLI 的能力识别 Opus 别名、Opus 4.8 和 Opus 5 系列，保留网关前缀及日期后缀。运行中的回合及后台任务保持原配置，下次空闲启动或发送时应用新选择。该选项表示请求 Fast，实际速度仍受原生托管设置、账户、模型及上游服务限制，Fast 也可能增加费用。显式选择开启且 Riffet profile 使用自定义服务地址和 bearer 凭据时，仅为该进程加入官方文档要求的 `CLAUDE_CODE_SKIP_FAST_MODE_ORG_CHECK=1`，处理网关凭据无法完成 Anthropic 客户端可用性预检查的情况；服务端仍可拒绝并降级。详见 [Claude Code Fast 文档](https://code.claude.com/docs/en/fast-mode)。

Claude Code 的已验证 Opus／Sonnet 型号，以及网关明确声明窗口至少为 1,000,000 token 的自定义模型，提供「上下文：默认／1M」。网关目录中的 `runtime.max_input_tokens`、`max_input_tokens`、`context_window`、`context_length` 按此顺序取有效的正整数；模型没有声明时不按名称猜测窗口。默认模式会将所选未知自定义模型的精确窗口传给原生 `CLAUDE_CODE_MAX_CONTEXT_TOKENS`，例如 DeepSeek 的 `1048576` 原样保留；切换模型会重新读取，不沿用上一模型的值。`claude-` 开头的型号由 CLI 按自带型号表判断，不接受这个变量：提供商里为这类型号声明 1M 时，改以原生 `[1m]` 启动，早于该型号发布的 CLI 也按 1M 运行；声明小于 1M 不改变 CLI 的判断。选择 1M 会传入原生 `[1m]` 模型选项，并与 Fast、推理强度独立保存；恢复默认会移除这一覆盖。已有原生 `[1m]` 会话也能还原菜单选择。Mac、Android 和 Web 复用 Cursor 的模型选择器，Fast 使用开关并保留默认入口，开启时在输入框旁显示闪电，选择 1M 时显示 1M 标签。实际窗口受 CLI、模型、账户及服务端能力约束；窗口未声明的自定义模型和 Haiku 不提供强制 1M 选项。详见 [Claude Code 模型配置](https://code.claude.com/docs/en/model-config)。

Riffet profile 明确配置凭据时，Claude Code 的认证限于该配置，包括未单独指定服务地址的配置：会话覆盖文件清空继承的 `ANTHROPIC_AUTH_TOKEN` 和 `ANTHROPIC_API_KEY`，通过进程内的 `apiKeyHelper` 读取该配置的独立环境变量。原生客户端在首次构建请求头前等待 helper，使 `Authorization` 与 `X-Api-Key` 使用同一凭据，避免首次请求只有 bearer，或混入 macOS Keychain 中另一个账户的 Console key，导致网关返回 401。helper 命令本身不含明文凭据，也不依赖服务退出时会删除的临时文件。官方 Anthropic 模型目录使用原生 `x-api-key` 认证，其他网关沿用 bearer。未配置凭据的本地原生账户继续沿用 CLI 登录。详见 [Claude Code 网关认证](https://code.claude.com/docs/en/llm-gateway-connect)。

Claude Code Artifacts 是发布到 claude.ai 的能力，需要官方账户登录，API key 或网关 token 无法发布。对于 Riffet profile 明确配置的第三方服务地址及 bearer 凭据，启动覆盖文件会设置 `enableArtifact:false`，避免不兼容的 edge 返回 Artifacts 400；官方直连继续继承原生设置。此覆盖只在重新启动 CLI 后生效，不改会话历史。单独使用 CLI 时，可在 `/config` 关闭 Artifacts，或在当前使用的 `settings.json` 中合并 `"enableArtifact":false`；若 edge 仍要求新会话，再新建会话。详见 [Claude Code Artifacts 文档](https://code.claude.com/docs/en/artifacts#disable-artifacts)。

Droid 的内置非 Auto 模型在模型参数里提供「上下文预算」：默认沿用 Droid 自己的配置；长上下文请求最高 1M token，由 Droid 按实际模型输入窗口收敛并保留输出空间。选择随 Riffet 会话保存，正在运行的一轮继续使用原预算，新预算从下一轮生效。配置通过当前 Droid 进程的 `--settings` 覆盖文件传入，仅针对所选模型，不修改用户全局设置，也不提高其他模型的压缩阈值。窗口未知的自定义模型与 Auto 不提供这一选项。

Droid 的设置请求必须由对应 `requestId` 的 `settings_updated` 确认；空 RPC 应答不视为模型、推理强度或权限已经生效。无法确认时在发送用户消息前停止，不把期望值记成实际值。运行中，旧回合的设置回报不能覆盖用户已保存的下一轮选择。

Droid 标准额度耗尽时，原生超额使用策略可能把 Opus 等标准模型切到 Droid Core，例如 Kimi。Riffet 会显示原生 `user_only` 系统通知；若明确选定的主模型发生未请求的变化，会尽快停止该轮、报告期望和实际模型，并保留原选择。Auto 的 `routedModelId` 和 Spec 的独立模型不当作主模型变更。额度路由发生在原生 CLI 内，收到通知后停止仍有传输和调度延迟，不能保证备用模型已经产生的请求或费用为零。用户可在 Droid `/limits` 检查额度与超额偏好，Riffet 不自动启用付费超额或修改全局偏好。详见 [Factory CLI Reference](https://docs.factory.com/droid-cli/cli-reference)。

上下文用量显示在输入框的模型选择器右侧（环形进度 + 百分比）。计量及对应上限**必须由 provider 给出**（CLI 存储、协议帧，或它自己写的 rollout）才会画这个环；分项只有 CLI 提供分解时才列出，没有分项时点开只有比例条——工作台不会用事件日志去估算一个数字冒充模型用量。低于 75% 为蓝色、75% 起橙色、90% 起红色。

Droid 的表明确显示「压缩预算」：分子使用原生 `get_context_breakdown.lastCallCompactionTokens`，包含最近一次模型请求的输入、缓存写入、缓存读取及输出；分母 `contextBudget` 是自动压缩阈值，并非模型的硬输入窗口。没有最近计量时不显示主表。原生 `usedTokens` 和 `categories` 是另一套内容字符估算，只在详情中以「内容估算」和 `~` 展示，分项占比按估算总量计算，不与主表相加。超过阈值时保留真实数字，环形和条形图只限制绘制范围。选择「最高 1M」请求的是延后自动压缩，实际阈值由 Droid 收敛，不会把分母直接改写成 1M。旧版 Droid 缓存中的估算主表不再恢复，会话正文与历史仍保留。

DeepSeek Harness 会话同样显示这个环，数字来自它自己提交的记录：占用取最新一步 `assistant/message.usage` 的 prompt 侧 token（`inputTokens` + `cacheReadTokens` + `cacheWriteTokens`，与 DSH 自己的压力口径一致），窗口取最新的 `request/context.contextWindow`。两个数都齐了这个环才出现。分项则读 DSH 自己的 `contextBreakdown` 投影（系统提示词 / 工具定义 / 对话）——它按固定密度估算构成，CJK 与 JSON schema 会被系统性低估，**三项之和不等于上面的占用**：那些分项只当构成展示，绝不并进占用数字里。恢复的历史会话不用重新发送也能显示占用与分项（没打开过的会话由 bridge 在存储日志上冷折一次投影）；DSH 没有这个投影时就只有占用。

Claude Code 会话的环来自它自己写给状态行的 `context_window`：占用取 `total_input_tokens`（最近一次回答的 `input_tokens` + 缓存写入 + 缓存读取，也就是 `used_percentage` 的分子），窗口取 `context_window_size`。这个窗口只存在于 CLI 内部（模型表、`[1m]` 开关、账户权限、服务商声明的窗口、自动压缩设置共同决定），转写、配置文件与 API 流量里都没有，所以工作台不用模型名去猜：会话启动时窗口就已经有值，首条回答后出现占用，`/compact` 之后回到 0。为此本次启动的 `--settings` 覆盖文件会注册工作台的状态行采集脚本，并把你原有的状态行命令接在后面、把同一份输入交给它渲染——`~/.claude/settings.json` 不被改动，你自己的状态行照旧显示。受管设置的 `allowManagedHooksOnly`、`disableAllHooks` 或 `--safe-mode` 会禁用自定义状态行，此时会话没有环，其余功能不受影响。

Codex 会话的环来自 app-server 的 `thread/tokenUsage/updated`：占用取该帧 `last.totalTokens`（最近一次请求的整段 prompt 加输出，也就是下一次请求要带的东西），窗口取同一帧的 `modelContextWindow`。自定义网关常在模型目录里不声明窗口、该字段为 `null`，此时改从线程 rollout 尾部读 Codex 自己写的 `model_context_window`（读到即缓存复用，未拿到时最多每 15 秒重查一次，新线程的 rollout 晚落盘也能补上）；两个数来自哪一边都可以，但凑不齐就不画。Codex 不提供分项，所以点开只有比例条。

## 思考、正文与布局

助手正文按 Markdown 排版，行高约为字号的 1.8 倍；标题与粗体用中等字重，不用半粗（苹方的半粗在正文字号下发黑）。正文不做两端对齐，避免英文与中英混排拉出大词距。

**助手正文始终按原始顺序显示**：Agent 边做边说的中间叙述（"我先读一下项目结构"）和最后的回答都是正式消息，回合结束后继续可见。`TurnProcess` 只折叠思考、工具调用和计划等过程细节，不用“最后一条”规则隐藏前面的助手正文。过程运行中展开、结束后自动收起、出现运行级错误时保持展开；结束后主动展开的内容会保留，运行中手动收起也不会被强行弹开。

过程比正文安静：工具行、工具组头和过程头用常规字重与弱化颜色，工具行标题统一用等宽字体，路径的目录部分再淡一档。思考收起时是一行预览，点开后标题只写「思考」、下方是全文。连续的工具调用和夹在其中的收起思考合成一个工具组，组名按工具类别概括（「运行命令、读取文件等」）；正文、叙述和委派会断开工具组，只有一个调用时直接显示该调用。后台任务并在启动它的工具行上，不另起一行。

行尾只放进行中、可操作的东西：停止按钮，以及点了停止之后的「停止中」。运行中的转圈已经说明在运行，结束后的完成、耗时、退出码等收在展开详情里。单个工具调用失败是常态，不标红、不计数，错误内容在展开后查看；后台任务或子 Agent 整体失败、调用没有结束时，标题后面跟一个「失败」或「未完成」。消息发送失败、运行级错误和审批仍用醒目的颜色。

展开布局对齐规则：**内容与自己的行头左对齐**——顶层展开不加左缩进、不加竖线（缩进只留给工具组和工具行的二级展开那种真正的嵌套细节）。间距按相邻两项决定，组件自身不额外留白：回合之间最宽，用户消息到回答次之，一行行的工具调用彼此紧挨，正文与工具行之间留出与段落间距相同的距离。

输入控制按浏览器连接分配。另一个设备可以观察终端，选择接管后，旧设备的输入和尺寸调整会因过期的控制编号被拒绝。断开浏览器不会停止 tmux 中的程序。

## 模型输出速度（tok/s）

底部“正在处理”旁的数字采用**近期输出 token 数 ÷ 对应模型响应的实际测量时间**。
最近 180 秒只用于筛选样本，不作为分母；例如模型在 2 秒内输出 90 个 token，会显示 `45 tok/s`。
流式计时按请求累计首字到末字的跨度，模型请求之间的工具执行、审批与等待不计入生成时间。
只有 transcript 或落库观测时间可用的后端，分母仍包含首字延迟，提示文字会说明这个测量口径。
服务端统一计算，通过 `NativeStatus.outputRate` 提供给 Web、macOS 和移动端，每秒检查窗口变化。
同一响应的累计值只计新增部分，最终 provider usage 会校正流式估算，重读历史不会把旧输出搬到当前窗口。
流式增量按观测时间计入；只有整段记录的后端按区间重叠比例计入。估算或混合计数显示 `~`。

已获得采样但窗口内没有输出时显示 `0.0 tok/s`；尚无采样或最近一次有效样本已超过 5 分钟时隐藏数字。
与服务器断开连接时也隐藏数字，避免把断线前的采样当作当前速度。
短暂切换页面或断线重连会保留服务端窗口；服务端重启后等待新的有效采样，不用历史回合均值填补。
这一窗口沿用主智能体的 metrics 采集链，不额外汇总子智能体，也不依赖本机 kaboo-cli 进程。

回合头行（`Working · 12s` / `Processed · 12s`）后面会显示这一回合的输出速度，例如 `42 tok/s`。数字来自服务端按模型响应窗口的测量，各后端统一汇总到同一个累加器（`apps/server/src/metrics/turn-metrics.ts`）。Codex 在一轮内保留绝对输出时间、按请求累加生成时长，工具暂停不会压低这轮 TPS。

指标同时携带 Riffet run 或原生用户消息的身份，终端直接发送的回合也能显示速度。已完成测量写入统计账本，重连后按原生消息恢复；Claude 的历史 transcript 可按精确消息身份补录。Cursor 缺少原生精细时间戳，未观测的历史及工具响应仍可能无法测量；旧 Codex 回合若仅有 token 总量而没有生成计时，也不会用整轮运行时长填一个 TPS。

各后端能拿到的数据差别很大，界面如实区分（TRAE CLI 与 Codex 共用驱动，口径相同；Droid 的口径见 `apps/server/src/backends/droid/runtime.ts`）：

| 后端 | token 数 | 时间窗口 |
| --- | --- | --- |
| DeepSeek Harness | provider 精确 `usage`（流内的 `usage` 帧，取不到时用已提交的 `assistant/message.usage`） | 首个 delta 到末个 delta，不含首字延迟 |
| Codex | provider 精确 `thread/tokenUsage/updated` | 同上（`item/agentMessage/delta`） |
| Claude Code | transcript 里的精确 `output_tokens` | 上一条记录到本次回答结束，**含首字延迟** |
| Cursor | 无 provider 计数，按文本估算 | 上一次提交落库到本次落库（700ms 轮询观测） |

- **精确与估算分得清**：只有 provider 报了数才叫精确；估算值前面加 `~` 并用更浅的颜色，鼠标悬停会说明是估算、窗口包含了什么、合并了几次模型响应。工作台不会把估算值伪装成测量值——和上下文环「CLI 没给就不渲染」是同一条规则。
- **估算是标定过的，不是拍脑袋**：字符 → token 的系数是用本机真实 Claude transcript 里 194 条**同时有精确 `output_tokens` 和完整输出文本**的回答做最小二乘拟合得到的（ASCII 与非 ASCII 两类字符足够；再加一类只让误差好不到 0.1 个百分点）。在这批样本上平均相对误差 17%，中位偏差 5%。单条回答是近似值，一回合多次响应累加后误差会互相抵消。
- **窗口口径写在 tooltip 里**：`stream` 是「首字到末字」，是真正的解码速度；`transcript` / `observed` 从上一条记录算起，因此包含首字延迟，数字会系统性偏低。一回合里只要有一次是后一种口径，汇总就按较差的那个报告，不会用最好的一次冒充整回合。
- **量不出来就不显示**：没有输出、窗口时长为零（例如历史重建时整回合共用同一个时间戳）都会让这一行留空，而不是显示 `0 tok/s`。
- **重载后仍然可见**：Cursor 和 Claude 的速度只能在被观察时测出来，所以每个回合结束后聚合值会写进 Run（`native.metrics`），刷新页面从 `/api/sessions/:id/native/stream` 的 runs 快照里读回来。
