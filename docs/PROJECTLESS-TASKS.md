# Riffet 无项目任务方案

日期：2026-11-03。状态：首版已实现，覆盖服务端、Web 与 Mac；Android、iPhone 保持现有创建入口，通过能力协商兼容。

用户在“新建任务”中选择“不选择项目”后，可以直接发送。Riffet 在运行任务的设备上分配持久工作目录，保存文件和会话；需要长期维护时，将这个目录保存为项目。现有“快速会话”继续走 chat 后端，无项目任务继续使用用户选择的 Agent。

## 1. 首版范围

| 纳入首版 | 后续单独实现 |
| --- | --- |
| 不选择项目即可发起 Agent 任务 | 将运行中的任务迁入其他目录 |
| 独立目录、附件、文件预览与下载、终端 | 携带上下文和文件在已有项目中继续 |
| 目录按日期和任务名称生成，重试与恢复复用原目录 | 按 Agent 能力重新定位移动后的目录 |
| 历史记录中的“未关联项目”分组 | 批量清理任务文件、自动保留期限 |
| 服务端级“任务文件位置”设置 | Android、iPhone 的创建与管理入口 |
| 将当前工作目录保存为普通项目 | 单独备份、迁移全部任务工作文件 |

首版不自动初始化 Git、不创建远程仓库、不增加第三个会话 Tab。工作目录并非安全沙箱，读写与执行继续遵循所选 Agent 的权限设置。

## 2. 新会话交互

### 2.1 项目选择与默认值

项目菜单按下面的顺序排列：

1. 不选择项目。
2. 分隔线。
3. 新建 Worktree，仅在所选项目具备 Git 条件时出现。
4. 选择其他目录。
5. 分隔线。
6. 最近使用的普通项目和 Worktree。
7. 收藏的目录。

选中“不选择项目”后，选择器显示“未关联项目”，标题显示“要做点什么？”。复用同一个输入框实例，文字、附件、光标、模型、effort 和审批选择保持不变。

客户端必须区分三种状态：尚未恢复选择、明确选择无项目、已选项目。用明确的本地选择值表示无项目，不能用一个同时表示“未初始化”的空字符串；也不能通过 `projectId ?? recentProjectId` 把它还原成上次项目。

全局新建任务沿用当前设备在当前服务端上最近的明确选择，包括无项目；首次使用且没有历史选择时默认无项目。从项目菜单发起新任务则显式选中该项目。从无项目任务发起新任务时分配新目录，不复用旧任务目录。这个选择在客户端按服务端保存，不修改其他设备的默认选择。

发送前切换任务目标时，文字和附件保留。切换到无项目或另一个项目时清除旧项目的文件引用；仅切换“新建任务 / 快速会话”Tab 时，沿用已实现的任务引用保留规则。

### 2.2 能力与文件

| 能力 | 首次发送前 | 创建成功后 |
| --- | --- | --- |
| Agent、提供商、模型、effort、审批 | 可选，沿用默认值与所选提供商的全局模型列表 | 沿用正常 Agent 会话能力 |
| 附件 | 上传至现有服务端附件存储，不创建任务目录 | 由现有输入处理链路交给 Agent |
| Skills、MCP | 列出所选 Agent 的可用全局能力 | 由 Agent 的实际运行配置决定 |
| 文件引用与搜索 | 尚无任务文件，不提供目录文件搜索 | 只搜索当前任务目录 |
| 文件面板、Shell 终端 | 尚无目录，不创建空项目或终端 | 以当前任务目录作为根目录和 cwd |
| Git、Worktree、PR、并行尝试 | 不显示 | 满足实际 Git 条件后才能使用；并行 Worktree 尝试首版要求先保存为项目 |

无项目不会增加 Agent 权限，也不会使已有全局 Skills、MCP 自动失效。界面不宣称“无法访问其他目录”；权限限制由各后端执行。Riffet 自己的文件树、搜索和预览仍走现有目录边界与敏感文件检查。

### 2.3 历史与项目保存

按时间查看时，无项目任务正常参加排序、搜索、置顶和归档。按项目查看时，只要有可见记录，就展示一个“未关联项目”分组。这个分组仅存在于展示层，没有公共运行目录；每个独立任务的目录仍不同。

会话标题正常自动生成和手动修改，目录名不随标题变化。文件面板显示真实路径。本机连接可“在 Finder 中显示”，远程连接提供文件下载和路径复制，不尝试打开当前客户端上的同名路径。

“保存为项目”要求输入项目名称。服务端保留 Project ID、cwd、Session ID、原生会话 ID 和文件，移除内部项目标记并更新名称。所有客户端刷新后，该任务出现在普通项目下，目录开始参加项目选择与最近使用排序。保存行为不移动文件、不初始化 Git、不改写 Agent 上下文；有归属关系的交接会话一起进入这个项目。服务端在同一事务内记录第一次保存的名称：同名重复请求返回现有项目；同一项目的不同名称并发请求返回冲突，不互相覆盖。不同 Project ID 允许同名，界面以路径区分；之后改名走现有项目编辑入口。快速会话项目及没有转换回执的普通项目不能调用此操作；已经转换成功的项目可按回执处理重试。

## 3. 工作目录

### 3.1 根目录与命名

默认位置由运行服务端的设备决定：

| 环境 | 默认根目录 |
| --- | --- |
| Mac | 系统文稿目录下的 `Riffet`，通常为 `~/Documents/Riffet` |
| Linux 服务端 | 服务账号 Home 下的 `Riffet`，即 `~/Riffet` |
| 自定义 | 设置中的绝对目录，服务端校验后使用 |

Mac App 从 Foundation 获取系统文稿目录，通过现有本机服务启动配置传递平台默认值；它不覆盖已保存的 `taskWorkspaceRoot`。独立 CLI 服务端在 macOS 上默认使用 `~/Documents/Riffet`，Linux 上使用 `~/Riffet`。服务端统一按“已保存覆盖值、受信任的本机启动默认值、平台默认值”解析位置。默认位置无法解析或不可写时，返回可处理错误并让用户设置位置，不能静默改到其他路径。不得将当前客户端的 Home 路径用于远程服务端。

最终结构如下，示例中的短 ID 为演示值：

```text
~/Documents/Riffet/
└── 2026-11-03/
    ├── 竞品调研-a7f3c2d1/
    │   ├── .riffet-workspace.json
    │   ├── 报告.md
    │   └── 对比表.xlsx
    └── 数据分析-b8d4e1f2/
        ├── .riffet-workspace.json
        ├── analyze.py
        └── result.csv
```

目录日期使用首次创建时服务端所在时区的日历日期。预留后将日期与绝对路径持久化，跨天重试、服务端换时区、修改存储位置或会话改名都不重新计算。

名称从首条非空输入行确定，保留中文、字母和数字，将分隔符合并为 `-`，去掉路径分隔符、控制字符、前导点与首尾空白，按 Unicode 字符截取最多 24 个字符。清理后为空则使用 `task`。短 ID 使用创建 ID 的 SHA-256 摘要前 8 位，复用现有加密模块；它便于区分同名任务，不替代完整身份校验。名称不调用模型生成、不转拼音，不把完整提示词写入路径。

首次分配遇到原本已存在的同名目录时，延长 ID 后缀并重新独占创建，不能合并现有目录。更新后的候选路径先写入预留，再继续创建。一旦进入“目录已就绪”状态，路径不可再变；重试遇到与记录身份不匹配的目录时直接报告冲突。

### 3.2 目录生命周期

打开新会话页、切换 Tab、选择无项目、查询模型、上传附件，都不创建任务目录。首次有效提交才分配。目录属于这一项工作：继续原会话、原目录中的分叉与交接复用它；从入口发起新的独立任务使用新目录。

任务文件与 `~/.local/share/riffet` 中的数据库、凭据、日志分开。任务根目录不得位于服务端私有数据或已知凭据目录内；按规范化后的真实路径检查，不能通过软链接绕过。内部目录身份文件只含版本和不敏感的工作目录标识，不含提示词、密钥或配置内容，文件树与打包下载默认不展示它。

关闭窗口、归档、服务重启、修改根目录配置，都不删除或搬动任务文件。首版没有自动目录清理器。创建未完成产生的目录，只能在确认归属且仅含身份文件时清理；出现用户文件或无法确认归属时保留并报告，不递归删除。

目录消失时，不自动创建同路径的空目录。会话历史保持可访问，发送与终端启动返回“工作目录不可用”；首版引导用户恢复原位置后重试。由于部分后端把原生记录绑定到路径，首版不提供直接修改 cwd 的“重新定位”。后续为每个后端明确恢复能力后，再增加带校验的重新定位或新会话交接。

### 3.3 设置与备份

现有“文件”设置新增“任务文件位置”，服务端保存 `taskWorkspaceRoot` 覆盖值。保存时验证绝对路径、目录类型、真实路径边界和写入能力；允许创建用户明确指定的根目录，不能因权限失败回退到别处。清空覆盖值表示恢复平台默认值。

设置同时显示解析后的实际位置，说明“仅用于新任务”。Mac 文稿目录是否经 iCloud 同步由系统设置决定，Riffet 不另外上传文件，也不承诺文稿一定只在本机。

现有备份保存应用状态、附件和检查点，不包含外部项目工作树。首版无项目任务遵循同一规则：数据库包含目录对应关系，任务文件通过现有目录打包下载或文件系统备份保存。备份界面须说明“备份不含任务工作文件”。恢复到其他设备时不能只凭旧绝对路径声称目录已经恢复。

## 4. 数据与协议

### 4.1 复用 Project 作为运行目录

现有数据库要求 `sessions.project_id` 非空，Agent、终端、文件面板与恢复过程从 Project 读取 cwd。首版保留这一关系，不增加 Workspace 表，也不把已持久化 Session 的 `projectId` 改成可空。

为 Project 的 `system` 增加 `task-workspace` 值：

```ts
interface Project {
  // 保留现有字段。
  system?: 'quick-chat' | 'task-workspace';
}
```

一个新建的无项目任务创建一个带该标记的 Project。所有记录仍使用真实、不可变的 Project ID。`quick-chat` 项目保持原有专属规则，不能承载 Agent 任务。

服务端内部保留创建预留记录，以服务端自身命名空间中的创建 ID 为键，存入现有 SQLite `settings` 表。记录至少包含原始请求摘要、解析后的 Agent 配置、Project ID、已选 cwd、创建时间和目录身份；状态区分“已预留”和“目录已就绪”。会话成功提交后，是否已接受由 Session 与首个 Run 判断，预留记录保留以支持原请求重放。该记录不进入用户 AppSettings 或 API 列表。它与对应任务同生命周期；首版不按时间删除已接受的回执。记录只保存恢复必需的配置、摘要和目录信息，不额外复制提示词或附件字节。

### 4.2 创建请求

沿用 `POST /api/sessions`，为请求增加 `projectless: true`。仅请求层允许不传 `projectId`，响应中的 Session 仍含真实 Project ID。

```json
{
  "kind": "native",
  "clientSessionId": "稳定的创建 ID",
  "projectless": true,
  "backendId": "codex",
  "backendProfileId": "default",
  "model": "已选模型及完整参数",
  "mode": "agent",
  "initialMessage": {
    "commandId": "稳定的首消息 ID",
    "text": "整理这些资料，输出一份对比报告",
    "attachments": [{"id": "已上传附件 ID"}]
  }
}
```

创建参数必须满足以下约束：

- 普通请求保持 `projectId` 必填；只有显式 `projectless: true` 才允许省略，不能把漏传项目解释成无项目。
- `projectless: true` 与 `projectId` 互斥，只接受新 Agent 任务，必须有创建 ID、首消息 ID 与首条消息。
- 不接受 `backendId: chat`、已有原生会话 ID、resume picker 或其他项目的文件引用。
- 模型参数、审批和提供商按现有规则校验，解析后的值随创建预留记录固定。重试不能重新读取已变化的默认配置。
- 客户端拿到成功响应时，先接收附带的 Project，再接收 Session 和 Run，最后导航。创建响应增加可选 `project`，普通请求保持兼容，避免会话先到而目录尚未同步造成空页。

### 4.3 API 变更范围

| API | 变更 |
| --- | --- |
| `POST /api/sessions` | 接受无项目创建，返回 `session`、`run` 和新建 `project` |
| `POST /api/attachments` | 新增不依赖项目的上传入口，复用现有附件校验和存储；原项目上传入口保留 |
| `GET /api/backends/:id/catalog`、`usage`、`slash` | 增加显式 `scope=global`，与 `projectId`、`sessionId` 互斥；普通查询继续要求项目或会话 |
| `GET /api/task-workspaces/location` | 返回已解析根目录、默认或自定义来源及可用性；查询不创建任务目录 |
| `PATCH /api/settings` | 保存或清除 `taskWorkspaceRoot`，沿用现有认证与设置保存流程 |
| `POST /api/projects/:id/promote` | 将 `task-workspace` 保存为普通项目，请求只包含名称；返回同 ID、同 cwd 的 Project |

上传仍使用现有文件大小、类型、数量限制及服务端状态目录，创建过程按附件 ID 读取；上传接口不需要创建空项目。模型与参数选择继续复用现有规范化逻辑。

全局模型与能力查询需调整后端查询接口，使查询上下文中的 Project 可缺省；运行接口仍要求真实 Project。优先使用提供商 API、配置或已有全局管理查询。CLI 确实要求 cwd 时，使用按 Agent 与提供商分开的空管理目录，放在操作系统缓存位置；它不属于用户的任务根目录，不注册 Project，不打开会话，不读取上次项目，不预热任务进程。查询缓存键必须区分 global 与具体项目，并继续包含 Agent、提供商和配置版本。逐个核查后端的模型、额度和 slash 查询能力；某项全局查询不可用时返回该项缺失或明确原因，不返回伪造的查询结果。

无项目草稿关闭 cwd 相关预热。首次创建后再使用真实任务目录加载目录级能力。

## 5. 首次提交与故障恢复

创建由服务端统一完成，Web 与 Mac 不先调用创建项目再发消息。

1. 客户端冻结目标、文字、附件 ID、Agent、模型参数与审批，生成创建 ID 和首消息 ID，将完整请求写入现有待确认提交存储。
2. 服务端完成请求形状与身份校验后，按创建 ID 串行处理，先查询回执并比较原始请求摘要。内容不同返回冲突；已经接受的相同请求直接返回现有结果，不依赖当前目录、附件或提供商仍可用。尚未接受的请求才校验附件与当前运行条件，并复用已有预留的配置和路径。
3. 首次请求解析提供商默认值，确定目录根路径、日期、名称和 Project ID，持久化预留。SQLite 事务不跨文件系统或 CLI 的异步操作。
4. 独占创建目录并写入身份文件，核对真实路径与归属后标记就绪。未就绪记录重试时，仅在身份匹配后复用已有目录；否则保留该目录，按第 3 节重新分配并记录候选位置。已就绪记录发生身份不匹配则返回冲突。向 Agent 派发前再次验证目录，不运行归属不明的目录。
5. 在一个 SQLite 事务中写入 Project、Session 和首个 Run，复用 `createNativeSubmission` 的输入规范化与去重。提交事务后才发布列表变化并触发 dispatch。
6. 客户端先落盘清除已提交草稿，再清除待确认记录。提交期间新增的文字和附件保留；用户已经离开页面时，成功响应只更新列表，不抢回导航。

| 中断位置或变化 | 处理 |
| --- | --- |
| 预留前校验失败 | 保留草稿，不创建 Project、Session、Run 或目录 |
| 预留后、创建目录前退出 | 原请求重试从预留记录恢复 |
| 创建目录或身份文件时失败 | 不启动 Agent；未就绪记录按身份复用或重新分配候选目录，归属不明的残留目录保持原状 |
| 目录就绪、数据库提交前退出 | 校验身份后复用目录，继续同一次提交 |
| 数据库已提交、响应丢失 | 返回已有 Project、Session、首个 Run，不重新派发首消息 |
| 客户端收到响应、清草稿前退出 | 待确认记录仍在，恢复时重放同一请求，完成草稿清理 |
| 用户修改根目录、模型默认值或跨天重试 | 使用首次预留值 |
| 创建成功后保存为项目，再收到旧请求重试 | 返回原会话，不重新创建带标记的项目 |
| 目录被移走或替换 | 历史可读，停止新的运行；不能自动补空目录或接管替换目录 |

无网络响应、5xx 与客户端取消等待都不能解释为创建失败。待确认请求继续绑定原 ID；确认接受前不能把重试变成第二次创建。客户端按错误码与“是否已接受”语义处理，不能把全部 4xx 一律视为可以丢弃请求。服务端明确返回尚未接受的校验或目录错误后，客户端才允许修改目标并重新提交；创建 ID 冲突须先保留并核对原请求。实现时核对 Web 现有待确认提交清理顺序；Mac 改用共享 Kotlin 已有的 `prepareCreation`、`createPreparedSession` 与 `acknowledgePreparedCreation`，避免另写一套请求恢复机制。

## 6. 兼容与边界

新增协议特性 `projectless-tasks`。新 Web/Mac 仅在服务端声明后显示“不选择项目”及相关设置，并在请求头声明自身支持。未支持的服务端保持原行为。

旧客户端不应看到陌生的 Project.system 值或失去目录的会话。复用现有客户端能力协商机制，同时过滤未支持客户端的托管 Project、关联 Session、搜索、统计、收藏与嵌套引用；直接项目、会话、文件、终端、同步和 SSE 路由也执行同一可见性规则，不能只过滤列表。账号访问范围继续由现有认证决定，能力协商负责客户端兼容。

保存为普通项目后，旧客户端可按原有项目协议访问它。无需迁移已有普通项目和快速会话，不批量移动历史文件。数据库与新标记在旧版本服务端上的表现需要降级演练；演练通过前不承诺服务端降级兼容。

首版允许已有无项目任务在同一目录内继续和交接。用户主动创建 Git 仓库后，文件与 Git 能力按实际状态判断；会创建其他项目的并行 Worktree 功能要求先保存为项目。这个限制同时落实在 UI 和 API，防止生成无法正确归组的隐藏 Worktree。

## 7. 实现拆分

| 顺序 | 写入范围 | 完成条件 |
| --- | --- | --- |
| 1. 契约与目录创建 | `packages/contracts`、服务端设置、创建预留、目录管理、Session 创建 | API 可完成独立任务创建；重试、并发、路径校验与故障恢复通过核心测试 |
| 2. 提交前能力与兼容 | 附件、backend 查询、客户端特性过滤、同步与 bootstrap | 未选项目可上传附件和选择模型；旧客户端既能工作也不会收到无法解码的新记录 |
| 3. Web 与共享 Kotlin | Web 导航、项目菜单、Composer、历史、文件设置；Kotlin DTO、API、待确认提交、列表分组 | Web 完成创建、恢复、文件访问与保存为项目；Mac 可调用共享接口 |
| 4. Mac 与集成验收 | 原生 Home、DirectoryMenu、Workbench、Sidebar、FilesSettings、语言目录 | 对齐 Web，继续使用稳定输入框；本机与远程路径行为正确 |

“保存为项目”的服务端事务放在第 1 步，两个客户端入口随各自实现交付。第 3 步中的 Web 与 Kotlin 可在契约稳定后并行；Mac 依赖 Kotlin DTO 与 API 完成。实现保持组件职责边界：运行目录分配由服务端负责，客户端负责选择、展示和持久提交；Swift 不实现原生协议与提交状态机。

涉及的现有实现依据：

- `apps/server/src/native/session-input.ts`：创建时项目、提供商、参数校验。
- `apps/server/src/store.ts`：项目外键、创建指纹、首个 Run 去重及事务。
- `apps/server/src/backends/service.ts`：运行 cwd 校验及模型、额度、slash 查询。
- `apps/server/src/native/client-features.ts`：列表与直接会话请求的能力协商。
- `apps/server/src/routes/workspace.ts`、`workspace/scope.ts`：附件入口、目录访问与敏感路径限制。
- `apps/web/src/app/use-session-actions.ts`：持久化首次提交请求；新功能延续同一请求身份。
- `apps/mobile/client/src/commonMain/kotlin/riffet/ui/composer/NativeSessionCreationOutbox.kt`、`ui/state/SessionStore.kt`：Mac 可复用的持久提交与确认机制。

## 8. 验收

自动化用例优先扩展现有 `store.test.ts`、`app.test.ts`、客户端特性与工作目录测试，以及 Web/Kotlin 现有提交恢复测试。只有既有测试无法覆盖目录创建故障时，才在目录管理边界补最少用例。不新增 UI 展示、布局或快照测试。

必须验证的核心行为：

1. 没有任何普通项目时仍能创建无项目任务；创建 ID、Project 和首消息 Run 一一对应。
2. 同请求并发、响应丢失、跨天与根目录变化后重试，都只接受一个任务工作目录、一个会话和一个首消息 Run。就绪前无法确认归属的残留目录按恢复规则保留，不关联会话、不启动 Agent。
3. 同创建 ID 的不同输入发生冲突，不使用已有目录启动第二项工作。
4. 校验失败、创建中断和数据库提交失败后，不派发未提交任务；已就绪记录按原路径继续，未就绪记录按身份校验结果恢复或重新分配。
5. 两个独立任务的 cwd 和文件树不同；上传附件不创建任务目录，不引用上次项目文件。
6. 路径穿越、软链接替换和无权限目录被拒绝；首次分配遇到同名目录时选择未占用名称，已就绪目录的身份冲突被拒绝；不放宽现有敏感文件预览规则。
7. 保存为项目前后 ID、cwd、原生会话标识与文件不变，归组更新；同名重放返回已有结果，不同名称的并发转换返回冲突。
8. 旧客户端的列表与直接请求都遵循能力协商，现有项目和快速会话仍可用。
9. 待确认请求跨进程恢复，提交成功后只清理已经提交的草稿，模型参数不因回包顺序回退。
10. 归档、重启、修改根目录不会删除或搬动文件；工作目录消失时不会被自动重建。

Web 执行类型检查、语言检查及生产构建；共享 Kotlin 执行受影响的协议和持久化测试；Mac 执行 Debug 编译、语言检查与 perf-lint。已有检查通过后不重复无关整套平台构建。

实际界面验收覆盖深浅色、空项目列表、两种历史布局、键盘操作和主窗口失焦；确认任务/快速会话切换时输入框不重建。连接远程服务端时检查存储位置、下载与 Finder 入口。运行测试选择临时根目录，不能在用户真实文稿目录制造验收任务。

## 9. 用户可见文案

| 文案 | 保留原因 |
| --- | --- |
| 不选择项目 | 项目菜单中的明确操作 |
| 未关联项目 | 当前选择状态与历史分组 |
| 任务文件位置 | 可配置的存储位置 |
| 仅用于新任务 | 避免误以为设置会移动历史文件 |
| 保存为项目 | 将托管目录纳入普通项目 |
| 文件保存在运行此任务的设备上 | 解释远程连接时的文件归属 |
| 工作目录不可用 | 区分文件缺失与模型或网络失败 |
| 将目录恢复到原位置后重试 | 首版目录缺失时的下一步 |
| 无法写入此位置，请选择其他目录 | 存储位置校验失败的下一步 |
| 备份不含任务工作文件 | 明确现有备份范围 |

复用现有“名称”“取消”“保存”、路径复制、下载、重试及 Finder 文案。主输入框不增加操作说明或副标题；内部标识、目录身份文件和创建预留状态不显示给普通用户。
