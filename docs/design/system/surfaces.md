# 界面

[基础](foundations.md)定义取值，[组件](components/)定义部件，[模式](patterns.md)定义组合。本文定义 Riffet 自己的三个整页：会话、新会话、侧边面板。取值以 Web 为准；Mac 与移动端的对应写法见 [macOS](macos.md) 与各端文档。设计规范页「界面」一组逐页画出本文的结构与取值，规则与原因只写在这里。

每节末尾的「现状」是 2026-11-14 盘点时与规则不符的实现，迁移后删掉对应条目。路径相对 `apps/web/src/`。

## 1. 会话

会话页保持对话的形态：一条纵向的阅读列，回答是正文，过程是可折叠的行。不做成追踪视图。

### 1.1 结构

| 部分 | 取值 | 来源 |
|---|---|---|
| 页头 | 桌面高 52，手机最小高 48；左内边距 16（桌面）、右 12 | `app/Header.tsx` |
| 阅读列 | 上限 `--content-width`，默认 920，范围 640–1600，读者拖动；含左右内边距，与文档、看板两档不同（[模式](patterns.md) §1.2） | `lib/content-width.ts`、`styles/index.css` |
| 列内边距 | 左右 12（手机）/ 16（≥640）/ 48（≥768）；转录顶部 24 / 32，底部 16 | `session/TranscriptView.tsx`、`session/sessionLayout.tsx`（`ContentColumn`） |
| 窗口余量 | ≥768 时列宽取 `min(--content-width, 100% − 56)`，两侧各留 28 给宽度手柄 | `styles/index.css`、`COLUMN_GUTTER_TOTAL` |
| 宽度手柄 | 左侧留白里宽 10 的条，距列 6；列居中，向外拖 1px 列宽增 2px；双击恢复默认；只在窗口留得出空隙时出现 | `session/ContentWidthHandle.tsx` |
| 行距 | 回合间 40，回答前 24，块间 16，紧邻 4；密度「紧凑」30/18/12/3，「宽松」50/30/20/5；触屏上紧邻为 0 | `--timeline-gap-*` |
| 输入框列 | 与转录同一个 `ContentColumn`，同宽同轴；列底 20（手机 12） | `terminal/NativeSession.tsx` |
| 侧列 | 宽 248；会话自身宽度 ≥ 1088（`SESSION_ASIDE_MIN_WIDTH`）时出现 | `session/sessionLayout.tsx` |
| 文字缩放 | 0.9 / 1 / 1.1 / 1.2，整页一起缩放，含转录、菜单、弹窗 | `lib/display-settings.ts` |

- **三项由会话宽度决定，不由内容决定**：侧列、轮次导航（侧列里的大纲，或贴在列边缘的导轨）、待办与目标（在侧列，或停在输入框上方）。消息、计划、文件的到来不增减任何一列，否则读到一半的版面会跳动。
- 转录、输入框、终端抽屉共用阅读列的一个宽度上限和一条轴线，三者不各自取宽；滚动条占位用 `--session-gutter` 补给列外的两列，保证对齐。
- 阅读列的宽度是读者的偏好，只存在这台设备（`riffet.contentWidth`）。Mac 的阅读栏默认 760（[设计决定](../DECISIONS.md) 2026-11-13），Web 默认 920，各端按自己的窗口取默认，范围和手势相同。
- 页头只放会话标题和操作；标题点击重命名，操作进「更多」菜单（[模式](patterns.md) §1.2）。手机 Web 的页头右端固定一个会话信息按钮，和标题一样打开会话详情弹层，弹层的结构见 [移动端](mobile.md) §10.4。

### 1.2 正文排版

回答、旁白、计划、工具返回的 Markdown 都用 `.md`（`session/Markdown.tsx`，样式 `styles/index.css` 的 `.md`）。设计规范页直接渲染真实的 `Markdown`，数值读自渲染结果。

| 元素 | 字号 / 行高 | 字重 | 外距（上 / 下） |
|---|---|---|---|
| 正文 | 14 / 26 | 400 | 0 / 14 |
| h1 | 20 / 28 | 500 | 22 / 8 |
| h2 | 17 / 26 | 500 | 22 / 8 |
| h3 | 15 / 24 | 500 | 22 / 8 |
| h4–h6 | 14 / 24 | 500 | 22 / 8 |
| 列表项 | 同正文 | 400 | 3 / 3；嵌套列表上 3；左缩进 22，项内再缩 2 |
| 引用 | 同正文，`fg-2` | 400 | 0 / 14；左线 2px `line-strong`，左内边距 14 |
| 表格 | 13 / 20 | 表头 500，`fg-2` | 0 / 14；只有行间横线 1px `line`，表头下 `line-strong`；无外框、竖线、表头底色；单元格 8 / 12，首列左、末列右不留内边距 |
| 行内代码 | 13，等宽 | 400 | 无底色与内边距，`fg-2` |
| 分隔线 | – | – | 20 / 20，1px `line` |

以上字号乘 `--text-scale`；段落间距 14 也随之缩放。

- **层级靠字号和颜色，不靠加粗**：标题与 `strong` 都是 500，PingFang 的 600 在这个字号下发黑。标题只有三档放大，h4 起回到正文字号。
- 行高 26 是长文阅读的行高，比界面的 `base`（14 / 22）松，保持 2px 整数倍。旁白（`.md-muted`）与正文同一字阶与段距，只在颜色上降为 `fg-2`，避免一轮里出现两种字号；展开的思考（`.md-thought`）取 13 / 20、`fg-3`，与折叠时的标题同一档。
- 正文里可点的文字都有下划线：链接用强调色加 1px 实线下划线（`line-strong`，偏移 3，与文件引用的虚线同色），悬停时下划线变强调色；强调色接近墨色的主题（Pencil）里，下划线是唯一的暗示。指向项目内文件的行内代码是按钮：正文色加虚线下划线，悬停变强调色。
- 提示块（`[!NOTE]` 等）只改左线与首词颜色：强调、`warning`、`danger`。
- 宽表格保持自然宽度、横向滚动；滚动条悬停或聚焦时才显示，聚焦时轮廓同焦点环。表格内换行在词间，代码不换行，约 8 个汉字以内的单元格整格不换行（避免标签列被长内容挤成一字一行）；保留 GFM 列对齐并使用等宽数字（`tabular-nums`）。
- 仅转换安全的无属性内联标签：`<br>` / `<br/>` 转为真实换行（包括表格单元格内），配对的 `<kbd>`、`<sup>`、`<sub>` 按对应语义渲染；其余原始 HTML 与未闭合标签按文本转义显示。
- 图片圆角 10；公式用 KaTeX，行内 1.05em，独立公式 1.15em，过宽时在列内横向滚动。
- 中英文混排、数字、标点按 [基础](foundations.md) §2.4。
- 回答左侧的章节导航在留白不足以显示标题时使用横线：高 2、通常宽 12，悬停宽 16，当前章节宽 20 并用正文色；横线左端对齐，加长部分只向右延伸；标题通过提示气泡和无障碍名称保留。

**现状**：

- Mac 与 iPhone（`MarkdownModel.swift`）的 `<kbd>` 按行内代码绘制，暂未做成按键胶囊。
- Mac（`TranscriptViews.swift` 的 `TableBlockView`）、iPhone（`ConversationMarkdown.swift`）与 Android（`TranscriptMarkdownTable.kt`）的表格仍有外框和表头底色，还没改成只有行间横线。
- Android（`riffet/ui/timeline/MarkdownRender.kt`）的链接只有强调色、没有下划线：Compose 的 `SpanStyle` 画不出与文字不同色的下划线，满色下划线又太重。
- Android（`riffet/ui/timeline/MarkdownRender.kt`）目前仅将 `<br>` / `<br/>` 转为换行，暂不支持 `<kbd>`、`<sup>`、`<sub>` 的语义渲染。

### 1.3 消息

| 部分 | 取值 |
|---|---|
| 用户消息 | `bg-bubble`，圆角 24，内边距 16 / 10，`text-base`，右对齐；最大宽 `min(82%, 560px)` |
| 用户消息的元信息 | 在气泡下，右对齐，`text-2xs` `fg-3`；来源、送达状态、补充标记、时间、复制。来源只在消息由另一个 Agent 写出时出现（机器人图标加「主对话」或「另一个 Agent」），带来源的元信息常显 |
| 回答 | 无气泡，占满阅读列；正文即 §1.2 的 `.md` |
| 回答脚注 | 最小高 36（触屏 44），`text-2xs` `fg-3`：操作菜单、时间、速度（`tok/s`）；估算值前缀 `~`、字色 `fg-4` |
| 用户消息里的引用 | 消息开头的 Markdown 引用画成气泡下的胶囊，样式同会话引用：引用图标加首行文字，单行截断；点开是浮层，显示整段引用 |
| 附件 | 在气泡下，缩略图；本回合的图片可放大 |

- **脚注停留 500 ms 才显示**（指针在自己那一行上静止，移动即重新计时），离开即隐藏；焦点进入或菜单打开立即显示；触屏常显。最新一条和已停止的回合常显（`footerPinned`、`stopped`）。原因：每行都挂着操作会让阅读列变密。
- 脚注的位置在回答仍在流式输出时就预留（`progress`），回合结束时回答不下移。
- 用户消息的状态词（恢复中、发送中、已排队、需确认）取代时间；失败的发送在这里给出恢复动作（重试、检查状态、恢复到输入框），原因详情折叠。

- **发送时恢复**：待恢复的会话仍可发送；消息持久化后立即进入时间线并清空已提交的草稿，服务端恢复原会话后继续发送。实际恢复期间，气泡下原有状态位显示「恢复中」，随后为「发送中」，收到回执后回到正常元信息；不新增弹窗或成功通知。手动恢复保留为独立入口，不作为发送前置步骤。
- 恢复失败时保留消息与附件，使用原有「发送失败」和详情；确认尚未进入发送边界的消息可「恢复到输入框」。已进入发送边界但结果未知时只提供检查状态等既有恢复动作，不自动作为新消息重发。

**选中文字**（Web）：在一条回答或一段旁白里选中文字，选区上方出现工具栏（上方放不下时在下方），`bg-popover`、`shadow-pop`、圆角 12、内边距 4，层级 `menu`。

- **跟随选区**：工具栏和插件结果卡片都放在正文的滚动层里，滚动时随文字一起移动，不由脚本逐帧跟随；出现时定下在选区上方还是下方，之后不换边。
- **旁白**：旁白没有消息锚点，回合结束后还会折叠，高亮和侧边聊天都找不回它，所以工具栏只有引用、插件项和复制。
- **工具栏的去留**：工具栏属于选区。选区滚出正文的可视区域时，工具栏淡出（`--duration-fast`）；选区还在、滚回视野时，工具栏再出现。选区取消、按 `Esc`、执行任何一项操作后，工具栏关闭。

| 位置 | 内容 |
|---|---|
| 左组 | 引用、侧边聊天：`sm` 按钮，图标加文字 |
| 竖线 | 1px `line-strong`，高 16 |
| 右组 | 高亮、插件项（[插件界面](plugins.md) §2.1 的 `selection` 菜单）、复制、导出图片：`icon-sm` 按钮，只放图标，悬停给名称，提示出现在远离选区的一侧 |

- **引用**：选区成为输入框上方的一枚引用胶囊，和会话、文件引用排在同一行，可以移除，焦点移到输入框。选区全在一个代码块里时，引用的是代码围栏。发送时，各条引用以 Markdown 引用写在消息开头，后面接输入的文字，所以各端和各 Agent 读到的都是普通文本；草稿也按这种格式保存。归档或终端接管的会话不显示。
- **高亮**：点击用这个标签页里上次选的颜色（起初是黄色）。指针停在按钮上或焦点进入时，按钮外侧（远离选区的一侧）出现一排色点，触屏上第一次点按出现色点。工具栏常驻部分没有彩色。
- **插件项的结果**：在选区旁的卡片里，卡片放在选区上下两侧空间较大的一侧；宽 448（窄屏减去两侧 8）、最高 400，正文在内部滚动；标题行和回答下方的结果块相同，底色换成 `bg-popover` 加 `shadow-pop`。运行时卡片里转圈，选区保持选中。卡片属于一次请求：选区滚出正文的可视区域时关闭，滚回来不再出现；`Esc`、点卡片外、重新选择文字也会关闭。出现和消失与浮层相同：淡入加轻微缩放用 `--duration-fast`，淡出用 `--duration-exit-fast`。结果不写进会话。
- 不做：工具栏里的说明文字、常驻色点、二级菜单。

**现状**：Mac、iOS、Android 没有选中文字工具栏；它们的用户消息里，开头的引用按 `>` 原文显示。

### 1.4 工具调用与过程

一个动作一行（`Disclosure`，`session/Timeline.tsx`）：

| 部分 | 取值 |
|---|---|
| 行 | 最小高 24（触屏 36，可点的整行 44），`text-sm` `fg-3`，悬停 `fg-2` |
| 前导图标 | 16 的格，图标 15，`fg-4`；运行中换成 `Spinner`；悬停时变为展开箭头 |
| 标题 | 工具名与命令用等宽 `text-xs`；其余用正文字体。标题最多占 70%，其余给详情 |
| 详情 | 等宽 `text-xs` `fg-3`；路径只截目录段，文件名保留 |
| 行内结果 | 在标题之后：改动统计（`+12 −3`）、「失败」（`danger`）、「未完成」（`fg-4`） |
| 展开体 | 左缩进 8，`edge-l` 一条线，内边距 16，块间 8 |

- **触屏没有悬停，展开箭头常驻**，跟在标题后面，不贴右缘；右缘留给状态（后台任务的停止按钮）。
- 命令行和工具名保留英文原文（[设计决定](../DECISIONS.md) 2026-10-27）。
- **回合过程组**（`TurnProcess`）：一个收拢的行，包住本回合的思考和工具。行高 28、`w-fit`、悬停有浅底；标题 `处理中 · 12s` / `已处理 · 1m 41s` / `已停止`；运行中图标用强调色、文字流光。
  - 回合运行时自动展开；正常结束后折叠；被中断、被补充指令打断、或含失败的工具时保持展开。读者手动展开或折叠的选择优先，并被记住。
  - 读者正在看这一段（向上滚离末尾且这段在屏幕内）时不自动折叠。
  - 内容与标题左对齐，不加竖线缩进；缩进只留给真正嵌套的细节（工具行展开自己的内容）。
  - 结果（失败、停止）不在过程里：由行规划放到折叠之外（[设计决定](../DECISIONS.md) 2026-11-12「回合结果独立于执行过程」）。只有结果、没有执行过程的块不加「已处理」标题。
- **思考**：旁白（模型给用户看的摘要）是不带行的正文，用 `.md-muted`；原始思考折叠成一行，预览即标题，展开后标题为「思考」。
- 子 Agent 的调用行进入它自己的转录页，不就地展开。
- Agent 之间的往来按对话画，不画成工具：主对话中途发给子 Agent 的消息，在子 Agent 页是带来源的用户消息，在主对话是「发送消息」工具行（标题取消息摘要，展开是正文）；子 Agent 发给主对话、不是报告的消息，在主对话是带来源的用户消息；子 Agent 交回的报告，在子 Agent 页是它的回答，在主对话是子 Agent 通知行，展开是报告正文和「查看子 Agent 对话」。报告只在这两处，各出现一次。

### 1.5 代码与 diff

| 部分 | 取值 |
|---|---|
| `CodeBlock`（工具输出、命令） | `bg-subtle`，圆角 8，内边距 14 / 12，等宽 `--text-code` / `--leading-code`（13 / 20）、`fg-2`；最高 288 内滚动；复制在右上角，悬停显示（触屏常显） |
| 围栏（`.md-code`，回答里的代码块） | `bg-subtle`，圆角 8，顶栏高 32（`bg-muted`，下有分隔线）：语言名大写 `text-2xs`、可渲染的预览开关、自动换行、复制；内边距与字号同 `CodeBlock`。顶栏标签只占一行，截断不换行。有的 Agent 用 `起:止:路径` 引用代码（```` ```218:228:src/app.ts ````），这时标签写 `路径 · L起–止`、保持原样大小写，按路径的扩展名高亮；放不下时截断开头，留住文件名和行号 |
| `DiffView` | `bg-subtle`，圆角 8；标题栏最小高 32：路径（目录 `fg-4`、文件名 `fg-2`）、`+N −N`、复制、下载、在编辑器打开；正文最高 320，两列行号各 36、符号列 20，等宽 `text-xs` / 18 |

- **diff 色角色**：每个角色有添加与删除两种，主题提供（`--diff-*`）。

| 角色 | 用于 |
|---|---|
| `--diff-add` / `--diff-del` | 整行底色 |
| `--diff-add-gutter` / `--diff-del-gutter` | 行号列底色，比整行深 |
| `--diff-add-marker` / `--diff-del-marker` | 行号、`+` `−` 符号、标题栏的 `+N −N` |
| `--diff-add-strong` / `--diff-del-strong` | 行内的词级强调（Web 暂未使用） |

- 未变的行用 `fg-2`、无底色，改动行用 `fg`；折叠的未变区段显示一条 `text-2xs` 的省略说明。新文件没有旧行号列。散文类文件（`.md`、`.txt`）折行显示，其余横向滚动，整行底色铺满滚动宽度。
- 超过 300 行的 diff 先显示前 300 行，余下一键展开；超过约 450 行的输出只保留首尾各 200 行，中间可展开。原因：一个长文件的重写不应一次把全部行挂进转录。
- 一个复制按钮对应一份完整文本：折叠或带 `$` 提示符的块，复制的是原始命令或输出。
- **代码高亮**：`CodeFence`、文件预览与移动端代码块统一消费 [基础](foundations.md) §1.1 的 14 个语法色角色（Web 为 `--code-*`），可在各端「主题」设置里按设备选择风格或 `auto` 跟随界面主题。

**现状**：

- `--diff-*-strong` 在主题里有定义，Web 的 `DiffView` 没有用它做词级强调。

### 1.6 审批与交互

原生审批与提问（`session/NativeInteractionCard.tsx`）是一张贴在转录末尾的卡片：

| 部分 | 取值 |
|---|---|
| 卡片 | `bg-subtle/45`，圆角 12，内边距 12 / 10 |
| 标题 | `text-sm` 500，单行截断；右侧：`Esc 拒绝` 提示（仅卡片获得焦点时）、倒计时、题号 |
| 正文 | 在 `bg-bg` 的内嵌区里，**最高 288 内滚动**（计划 320）；命令与授权范围用等宽 `text-xs` / 20，自动换行 |
| 选项 | 全宽 `Button`，最小高 36；当前聚焦项为 `primary`，危险项 `danger`，其余 `secondary`；文字完整显示、不截断：选项写的是授权范围，截断后在触屏上无法看全；右侧数字键提示 |
| 提交 | 底部一排 `xs` 按钮；主操作 `primary`，等待选择时禁用 |

- **有边界**（[设计决定](../DECISIONS.md) 2026-11-13）：标题单行，正文有最大高度并在内部滚动，操作留在滚动区外。长命令、长路径不撑高卡片、不把按钮挤出视野；原文可选中、可复制。
- 动作名与授权规则分开：记住规则的选项把后端给出的实际范围写在正文里，选项上只写动作名。
- **摘要里直接回答**（[设计决定](../DECISIONS.md) 2026-11-15）：Mac 与手机的摘要依次是「详情」、拒绝、允许，不论标题和正文是否被截断；记住规则的选项、标签放不下的选项只在详情里选，关闭详情不等于回答。协议请求按动作 id 认出允许与拒绝，从终端读出的权限框按 `tone` 认（服务端把单独的 Yes 标 `primary`、No 标 `danger`）。
- 数字键 1–9 选择对应行，`Esc` 拒绝；只在卡片获得焦点时可用，卡片首行给出键位提示，行内不重复。
- 提交过程有明确的状态：提交中、无法确认（给出「检查状态」与「终端」）、题目已更新；结果不确定时由读者决定是否重试。
- **权限模式**（`ApprovalPicker`）在 Web 和 Mac 上是输入框工具行里的一个胶囊：文字，不用图标；只有「全部放行」类模式用 `warning` 色。手机的输入框不显示权限，它在模型胶囊打开的面板里（[设计决定](../DECISIONS.md) 2026-11-16）。

### 1.7 回合状态

| 状态 | 表现 |
|---|---|
| 处理中 | `WorkingIndicator`：16 的格里一个 8 的强调色圆点，1.4 s 呼吸；「正在处理」`text-sm` 500、流光；计时 `text-xs` 等宽数字，预留 3 位宽；`tok/s` 在其后 |
| 后台运行中 | 主 agent 的回合已结束、它委派的子 Agent 或工作流仍在运行：`BackgroundWorkIndicator`，放在「处理中」的位置；同一格里一个 8 的 `fg-4` 静止圆点，「N 个子 Agent 运行中」（有工作流时分别计数，如「2 个子 Agent、1 个工作流运行中」）`text-sm` 500 `fg-3`，行高与「处理中」相同；不计时、不显示速度；点击打开会话信息（Mac 为页头的会话信息浮层，手机为会话详情）。Mac 是 `WorkingView` 的后台模式，iPhone 是 `ConversationView` 的 `conversationBackground` 行，Android 是 `DelegatedWorkIndicator`；计数取共享 presenter 的 `delegatedAgents` / `delegatedWorkflows`。后台命令和监控不计入：它们可能一直运行（开发服务、watch），只在会话信息里列出 |
| 已停止 | 过程组标题改为「已停止」；回答脚注以「已停止」开头并常驻 |
| 失败 | 一行 `danger` 文字加 16 的警示图标；原因一行，有诊断时右侧箭头展开等宽详情（最高 192），可复制 |
| 结果未知 | 「暂时无法确认」，给出检查状态与终端；保留恢复动作 |

- **同一次失败只显示一处**（[设计决定](../DECISIONS.md) 2026-11-12）：已加载的失败记录负责展示该次错误，消息下方不再重复「任务失败」与诊断；没有对应记录时才保留消息处的错误。按命令与原生回合身份关联，不按文案合并。
- **已结束的回合不因后台工作延长**：主 agent 收尾后，折叠标题照常写「已处理 · 耗时」，脚注照常出现，输入框可以发送；后台结果回来时由新的回合接着显示「处理中」。
- 状态指示是自己的组件，动态标志不兼任（[设计决定](../DECISIONS.md) 2026-11-11）。
- 减少动态效果时，流光停止，文字回到 `fg-3`，状态仍可读。
- 计时与速度每秒更新，屏幕阅读器只在状态出现时朗读一次（`aria-live="off"`）。

### 1.8 输入框

Web 和 Mac 的输入框是一张实底卡片：`bg-elevated` 加 `shadow-composer`，停在转录列下方，转录不滚到它下面。悬浮玻璃只用于移动端（[设计决定](../DECISIONS.md) 2026-11-11、2026-11-14）。

| 部分 | 取值 |
|---|---|
| 卡片 | `bg-elevated`，圆角 16，`shadow-composer`；聚焦 `shadow-composer-focus`。手机：圆角 24，1px `line-strong` 描边，`shadow-soft` |
| 形态 | `dock`（会话，文本区下限 52，自动增高至 240）、`hero`（新会话，76，至 320）、`embedded`（侧边讨论与并行尝试，下限 52，至 120，圆角 12、`bg-subtle`、描边、无阴影）、`compact`（手机未聚焦，44，单行） |
| 文本区 | 左右 16，`text-base` / `leading-6` |
| 工具行 | 左右 8，上 4、下 8，间距 4；手机允许换行 |
| 左侧按钮 | 28 方，图标 18：只有「+」常驻（附件、引用会话、技能与工具）；其余入口先看能否放进已有菜单 |
| 权限、模型 | 高 28 的全圆角文字胶囊，`text-sm` `fg-3`；模型带 Agent 标志。会话里模型在右侧发送键旁；新会话页的模型按钮同时选 Agent，排在左侧「+」之后（§2）。手机只有一个胶囊：上下文圆环和模型名，点开是模式、权限与模型的面板；Agent 没报上下文用量时不画圆环 |
| 发送 | 32 的圆，`primary`；禁用为 8% 墨色；运行中为停止（方块）；手机可见 36、点击区 44，与 iOS 一致 |
| 附件 | 桌面在文本区上方一排（左右 12，顶 12）；手机折成一行摘要，点开展开 |
| `/` 与 `@` 菜单 | 在卡片上方的浮层：顶栏高 32（`text-xs` `fg-3` 加分隔线），列表内边距 4，行最小高 32（触屏 44）、圆角 8；`/` 列表最高 256，`@` 列表固定高 256（结果数变化时高度不变）；手机时菜单在卡片上方的文档流里，最高 144 |
| 拖入文件 | 整个输入区 2px 强调色内描边，不加虚线框、不加遮罩 |
| 停靠卡片 | 待办、目标、排队消息贴在卡片上方（`ComposerDock`）：同样 `bg-elevated`、圆角 16；与卡片相接处，卡片上圆角为 0 |
| 录音栏 | 语音输入时取代工具行（`DictationBar`），间距 8：左侧取消（28 方，与左侧按钮同样式）；波形（2px 宽的竖条，`fg-3`，桌面 28 根、手机 16 根）；仍在识别的那句，`text-sm` `fg-3`，放不下时裁掉开头；计时 `text-xs` 等宽数字；右侧「完成」占发送键的位置，同尺寸同 `primary`，转写中换成加载圈。失败时中间换成 `danger` 的原因，可重试时右侧是次要按钮「重试」 |

- **不默认加常驻按钮**（[设计决定](../DECISIONS.md) 2026-11-12）：工具行是最常被看到的地方，发送键旁不放同等权重的东西。必须常驻的非核心功能做成设置开关、默认关闭，开启后用左侧工具按钮的样式（「稍后发送」即是）。
- 能力按对话选：Skill、MCP、手机控制、浏览器都在「+」里的「技能与工具」，不另设开关或按端配置（[设计决定](../DECISIONS.md) 2026-11-10）。
- 回车行为按设置：回车发送或 ⌘↵ 发送；输入法选词期间的回车不触发；手机的硬键盘回车始终发送。发送按钮与它标注的快捷键走同一个判断。
- 草稿按会话保存；浏览器存不下时在卡片内提示「刷新后会丢失」，字色 `warning`。
- 全屏编辑：文本区有内容时，工具行出现一个放大按钮；全屏时内部不做阴影。
- 语音输入（[VOICE.md](../../VOICE.md) §7）：设置里选了识别方式才出现麦克风按钮，在左侧工具组。桌面点击开始，工具行换成录音栏，已经定下的句子写进光标处，仍在变的那句只在录音栏里；Esc 取消并恢复原文，Enter 完成。触屏见下一节。

#### 语音输入（触屏）

Android、iPhone、手机浏览器同一套（[决定](../DECISIONS.md) 2026-11-17「触屏语音输入」）。

| 部件 | 规则 |
|---|---|
| 切换按钮 | 紧挨「+」，同一组、不另留间隔：两个按钮各宽 40（触控高度不变），图标之间只隔按钮自身的留白；键盘模式下是麦克风，语音模式下是键盘。点按切换，模式只存本机；识别方式关闭时按钮和语音模式都没有 |
| 按住说话 | 草稿为空时占文本区：`bg-subtle`（按下时 `press`）、控件圆角，居中的「按住 说话」是正文字号、`fg-2`。左缘对齐草稿文字，右缘对齐发送按钮，距卡片顶边与距发送按钮相等；输入框高度与键盘模式相同。草稿有字时文字照常显示（点文字回到键盘），长条移到工具行，替代模型胶囊，高同发送按钮。松手后等最后一句时长条里是加载圈、不接受按住，文字写进草稿后恢复 |
| 对齐 | 触屏输入框卡片左右与正文同宽。卡片里只有两条竖线：左边是草稿文字、长条和「+」图标的左缘，右边是长条和发送按钮的右缘；发送按钮距右边与距底边相等 |
| 按住 | 按下即开始录音、轻震。页面盖遮罩，深色主题下加倍（浅色 25% 黑、深色 50% 黑；iPhone 在系统 `ultraThinMaterial` 上叠同样的墨色）。气泡：浮层底色（`bg-popover`）、`shadow-pop`、圆角 16、左右与输入框对齐，正文是正在识别的文字（定下的 `fg`、仍在变的 `fg-3`），右下是波形与计时；没有中途结果时只有波形与计时。底部是一条浅拱：全宽、高约 136（含底部安全区）、中间比两侧高 24，浮层底色加 `line` 细边；弧顶下方依次是提示「松开转文字，上滑取消」`fg-2` 小字，和 28 的麦克风；提示在浅拱上，不压在遮罩下的正文上。输入框停靠在屏幕下部时，浅拱盖住整个输入框（两侧与输入框顶边齐平，输入框留在下面不动），气泡在浅拱上方；输入框在页面中间（首页、助理、新会话）时浅拱是底部独立的一条。气泡始终在浅拱上方，不放在页面中间的输入框上方，否则会盖住输入框上方的内容 |
| 上滑取消 | 手指离按下点上移超过 80：气泡底色换 `danger-soft`、文字 `danger`，提示换「松开取消」，再轻震；移回恢复 |
| 时长 | 4:50 起计时变 `warning`；5:00 自动结束，同松手 |
| 位置不动 | 按住期间写进草稿的句子不改变长条的位置（按下时草稿为空，长条就一直留在文本区），否则长条会从手指下移走 |
| 动效 | 入场时没有东西位移：停靠时浅拱第一帧就不透明地盖在输入框上，遮罩和气泡原地淡入（`fast`、减速）；页面中的浅拱随遮罩一起淡入。手机常丢掉动画开头几帧，位移会被看成跳动。松手就是退场：遮罩、气泡、浅拱一起淡出（`fast`、标准曲线，手一松就开始变淡；加速曲线前半段几乎不动，看起来是停顿后突然消失），一段完成，不等识别结果；气泡保留最后的内容淡出，不先清空。输入框高度只随草稿变化，有过渡，不随按住、松手跳动 |
| 松手 | 300 毫秒内松开算轻点：浮层收起，工具行换成录音栏（见上表「录音栏」），手离开也继续录。否则浮层随即退场，长条显示加载圈，最终结果写进草稿光标处；取消区里松开则直接收起、草稿不变 |
| 失败 | 浮层（松手后已退场的也重新出现）的气泡里换成 `danger` 的原因，气泡下方「重试」「放弃」，浅拱与提示隐去；不点不收起 |

**现状**：

- 停靠卡片与输入框卡片各自写了一遍阴影与底色（`session/ComposerDock.tsx` 的 `dockSurface`），而不是共用一个表面类。
- 手机上输入框的描边与阴影是 `max-md:` 单独写的一套，与桌面不是同一个配方。

## 2. 新会话

新会话页就是项目主页：选好项目后在这里写第一条消息。输入框居中，是 [模式](patterns.md) §1.2「内容列」的例外：内容列宽跟随输入框，不取文档宽度。

| 部分 | 取值 |
|---|---|
| 内容列 | 最大宽 720，左右 32（手机 16），顶 `max(48, 14vh)`、手机 24，底 64（手机 24） |
| 标志 | 64（手机 48），位置固定；动态标志只出现在这里、启动与关于（[设计决定](../DECISIONS.md) 2026-11-11） |
| 标题 | `text-2xl` 600（手机 `text-xl`），一行截断：「要在 {项目} 做什么？」 |
| 项目 | 输入框上方的一个文字按钮，高 28，`text-xs`，点开选择目录；这是会话开始后唯一不能再改的选择，所以只在这里给 |
| 输入框 | `hero` 形态（§1.8），自动聚焦 |
| 入口 | 三列卡片：Shell 终端、并行尝试、继续终端会话；手机折叠成一行「CLI 与终端工具」 |
| 最近会话 | 只在手机上显示，最多 5 条；桌面的会话列表在侧栏 |

- **Agent 并入模型菜单**（[设计决定](../DECISIONS.md) 2026-11-14）：桌面端输入框只留一个模型按钮，显示 Agent 标志、模型名与推理档位。菜单三栏：Agent（宽 176）、所选 Agent 的提供商（160）、所选提供商的模型；各栏分别滚动。没有 Agent 配了多个提供商时省掉中间一栏，菜单宽从 660 降到 500。打开时停在生效的那一项；选另一个 Agent 时停在它保存的默认提供商。选中模型时 Agent、提供商、模型一起保存。搜索在左栏所有已读到的列表里找，结果按 Agent 分组。菜单最高 `min(64dvh, 420)`。
- **按钮在工具行最前**（[设计决定](../DECISIONS.md) 2026-11-16）：新会话页的模型按钮紧跟「+」，排在权限之前；菜单锚在按钮上、左对齐，向左偏 2，让按钮里的 Agent 标志和 Agent 栏的标志落在一条竖线上。菜单宽度固定，不跟输入框卡片同宽，空间不够时由弹层推开。会话开始后 Agent 不能再换，按钮回到发送键旁，菜单右对齐按钮。
- 手机暂保留设置弹层里的 Agent 一行。
- 从侧栏点「新会话」只是一次导航，不会预先创建会话；首条消息发出时才创建。
- 并行尝试、继续终端会话在系统项目（任务工作区）里禁用。
- 聊天模式（`quickChat`）没有项目、Agent 与入口，只有输入框和历史。

## 3. 侧边面板

会话旁的上下文：变更、文件、浏览器与插件视图。整块面板连同页签一起变形，不按视图单独弹出。

### 3.1 形态与尺寸

| | 取值 | 来源 |
|---|---|---|
| 停靠宽度 | 320–720，默认 380；拖左缘调整，双击恢复默认 | `app/state/uiStore.ts` |
| 停靠外边距 | 右、上、下各 8，圆角 12；页签栏之下时顶部与标签栏对齐 | `app/WorkbenchPanels.tsx` |
| 停靠阈值 | 窗口 ≥ `panelDockMinWidth`：侧栏默认宽度下 1200，侧栏收起 1024；两者每多一像素就把阈值推后一像素 | `uiStore.ts` |
| 可拖宽度上限 | `min(720, 窗口 − panelDockMinWidth(侧栏, 0))`，保证拖宽后仍能停靠 | `WorkbenchPanels.tsx` |
| 悬浮 | 整块面板悬浮在会话上方；拖标题栏移动，四边四角调整；最小 320 × 240；距会话区边缘 ≤ 16 时吸附，Web 内缩 16（Mac 8）；吸附的边在窗口缩放时保持贴住 | `panels/FloatingPanelFrame.tsx` |
| 全屏 | 占满侧栏右侧的全部区域，与悬浮互斥 | `WorkbenchPanels.tsx` |
| 窄窗口与手机 | 窄于阈值：右侧抽屉，宽 `min(400px, 92vw)`；手机：全屏打开 | `WorkbenchPanels.tsx` |
| 终端 | 停靠在会话底部，高 160–560，默认 280；拖顶边调整；标题栏高 36（全屏 48） | `terminal/TerminalDock.tsx`、`uiStore.ts` |

- **悬浮是全局布局偏好**，位置与大小跨会话记住；面板是否打开、停在哪个视图按会话记住：在会话 A 打开面板，切到 B 时按 B 自己的状态显示。新会话页开着的面板交给它创建的会话；手机上切换会话总是收起面板（`uiStore.ts` 的 `switchSession`）。
- 停靠时会话的阅读列一次性让出面板的宽度（侧栏、面板的出现都是一步，不逐帧动画宽度），再让列平移到新位置（`useSessionLayout`）。拖拽面板宽度只改 CSS 变量 `--panel-w`，不重渲染工作台。
- 浏览器、Logcat 这类视图要与对话同时看：停靠受侧栏宽度限制，全屏会挡住对话，所以有悬浮（[设计决定](../DECISIONS.md) 2026-11-13）。

### 3.2 标题栏与页签

- 标题栏高 48，下有分隔线；左侧是视图页签，右侧依次是视图自己放进来的控件、悬浮、全屏、关闭（`quiet` `icon-xs`）。整条标题栏可拖动（`data-panel-drag`）。
- 页签是 `UnderlineTabs`；放不下的页签进入末尾的菜单，当前视图始终保留自己的页签。
- 页签集合由视图目录决定：位置为 `sidebar`、满足各自 `when` 条件、读者没有隐藏，按读者的顺序排列。宿主自带两个：`changes`（「变更」，仅 Git 仓库）与 `files`（「文件」）；浏览器是内置插件 `riffet.browser` 提供的视图，其他插件视图同理（[设计决定](../DECISIONS.md) 2026-11-13）。没有任何视图时显示空状态与「视图设置」。
- 面板主体不为单个视图做特殊外壳：宿主视图直接挂载，`keepAlive` 的（文件）显示过后保持挂载；插件视图经 `PluginView` 绘制。
- 浏览器视图由用户与 Agent 共同操作，不分控制权；Agent 请求接手时，面板顶部出现请求条，用户完成后点「完成」。

### 3.3 Git

- **Git 面板里所有可见文案都用英文**，中文界面下也一样，复数写对（1 file / 2 files）；Git 面板以外照常本地化（[设计决定](../DECISIONS.md) 2026-11-12）。
- 顶部 `Segmented`：Changes、History、Checkpoints、Worktrees（后者在系统项目里不出现）；右侧是刷新。
- Changes 下先是「与什么比较」（Uncommitted、This Turn、Branch），再是文件行：高 32，文件名 `text-sm`、目录 `text-xs` `fg-3`、`+N −N`、状态字母（A 与 U 为 `success`，D 为 `danger`，R 为强调色，其余 `warning`）；暂存、撤销等行内操作悬停才出现，触屏常显。
- 丢弃、还原这类不可逆操作先确认；能撤销的操作用带「Undo」的 toast（[模式](patterns.md)「确认与撤销」）。
- 评论：在 diff 的行号上添加，Shift 选一段；评论合并后「Send to Agent」作为一条消息发给当前会话，没有会话时禁用并说明。
