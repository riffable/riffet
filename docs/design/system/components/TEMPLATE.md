# 组件规范模板

一个组件一个文件，文件名用英文小写（`button.md`、`menu.md`）。复制下面「模板正文」，按顺序填写，不适用的节写「无」，不要删节：删掉的节，读的人分不清是不适用还是忘了写。

写法：

- 写规则，不写说明文。每条一句，能用表就用表。
- 只引用语义：颜色角色（`fg-2`、`bg-hover`）、文字角色、尺寸档位、状态名，见 `foundations.md`。具体数值只出现在「风格取值」一节。
- 交互按四端写全，iOS 不能缺。某端用系统控件时，写清用哪个控件、改了哪些参数。
- 与现有实现不一致的地方，在「迁移」一节列出，不要为了迁就现状改规则。

## 交付前自查

1. 四端的交互都写了吗？iOS 有没有落下？
2. 正文里除「风格取值」一节外，还有没有具体数值？
3. 每个变体都说得出和其他变体的区别吗？
4. 每个状态在触摸端怎么表现，写了吗？
5. 屏幕阅读器读出什么，写了吗？
6. 迁移清单里，每端的调用点都查过了吗？
