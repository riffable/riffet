# 模式

[基础](foundations.md)定义取值，[组件](components/)定义单个控件。本文定义多个组件如何组成页面、浮层和选择。取值以 Web 为准，Mac 与移动端按 [README](README.md) §3 的平台分工映射；Mac 的对应写法见 [macOS](macos.md)。

每节末尾的「现状」列出与规则不符的实现，迁移时逐项消掉。

## 1. 页面布局

### 1.1 工作台

| 区域 | 尺寸 | 来源 |
|---|---|---|
| 侧栏 | 208–400，默认 280，上限 40vw；收起后宽度为 0，悬停边缘时浮出 | `state/uiStore.ts` |
| 主区 | 浮在 `bg-canvas` 上的卡片，外边距 8，圆角 12（`rounded-xl`），底色 `bg` | `Workbench.tsx` |
| 侧边面板 | 320–720，默认 380；可停靠、悬浮、全屏 | `uiStore.ts`、`WorkbenchPanels.tsx` |
| 终端 | 160–560，默认 280，停靠在主区底部 | `terminal/TerminalDock.tsx` |

- **手机布局**：宽度小于 768，或粗指针且高度不超过 500（横屏手机）。条件写在 `MOBILE_LAYOUT_QUERY`，Tailwind 的 `md` / `max-md` 与它一致。页面只用 `md` 一个断点，`sm`、`lg` 只用于页面内部的栅格。
- **面板停靠**：窗口宽度达到 `panelDockMinWidth`（侧栏默认宽度下为 1200，随侧栏和面板宽度增减）时停靠，窄于它时悬浮在主区之上。
- 手机上，侧栏是左侧抽屉（`min(360px, 90vw)`），面板与设置全屏打开。

### 1.2 页面骨架

一个页面由页头和滚动区组成，滚动区里是一条居中的内容列。

- **页头**：高 48（手机）/ 52（桌面），左内边距 12 / 16。左侧依次是侧栏按钮（仅在侧栏收起或手机上出现）和页面标题（`text-sm font-medium`），右侧是页面操作，图标按钮在前，主操作在最后。手机上页头带底边线 `edge-b`，桌面上靠滚动区的内容和留白分隔。
- **内容列**：三档宽度，按页面的内容选择。

| 档 | 宽度 | 用于 |
|---|---|---|
| 阅读 | `--content-width`，默认 920，读者可拖到 640–1600 | 对话、终端、输入框 |
| 文档 | 768（`max-w-3xl`） | 列表、表单、自动化 |
| 看板 | 1200 | 统计、任务看板、插件、收藏这类并排放图、分列或排卡片网格的页面 |

- **内边距**：内容列左右 16（手机）/ 32（桌面）；顶部 24 / 40；底部 64，给最后一项留出滚动余量。文档、看板两档的宽度不含内边距；阅读档是例外，`--content-width` 含左右各 48 的内边距，文字宽是它减 96（[界面](surfaces.md) §1）。
- 一个页面只有一个滚动容器。页头固定，滚动区占满剩余高度。
- **实现**：Web 的页面用 `app/PageScaffold.tsx`：`PageScaffold` 给出页头、滚动区和内容列档位（`column="document" | "board" | "none"`），并把页面登记为可用返回键关闭的一层；只需要页头的页面用 `PageHeader`。
- 页面的一级视图用 `UnderlineTabs`，放在内容列顶部；视图内的筛选用 `Segmented`（§3）。

**例外**：扩展管理是目录加检查器的双栏页，只用 `PageHeader`，目录自带 1080 的上限。项目主页是新会话的起始页，输入框居中，宽度跟随输入框（720，[界面](surfaces.md) §2）。

### 1.3 设置页

- 设置是一个大弹窗：`min(1080px, 100vw − 32)` × `min(820px, 100dvh − 32)`，左侧 208 宽的分类导航，右侧是标题栏（高 56）加滚动区。手机上先显示分类列表，进入分类后全屏显示。
- 分类内容由 `SettingsGroup`（组标题 + 一张卡片）和 `SettingsRow`（左侧名称与说明，右侧控件）组成。进入二级页用 `SettingsLinkRow`；需要时在箭头前写一个当前值（`text-sm` `fg-3`），例如「未下载模型」。
- 分类按设置的对象分组，各端一致：无标题组（个人资料、通用设置）、外观、行为（输入、通知、会话标题、文件与编辑器）、功能（个人助理、任务看板、快速对话、机器人）、模型（Agent、模型提供商、辅助模型）、访问（连接与访问、设备管理）、服务器（服务管理、存储空间、备份与恢复）、支持。新设置放进它的对象所在的分类；Riffet 的一个功能自己有设置时，在「功能」组加一页。说明文字只写读者推断不出的信息：存储位置、是否需要重启、是否跨设备、计费与权限。

**现状**：

- 「会话标题」页只有 Web 有，Mac、Android、iOS 还没有（[会话标题规则](../../SESSION-TITLES.md) §5）。

#### Agent 与模型提供商

- 同在「模型」组，分别使用「Agent」「模型提供商」入口。Agent 页先放全局默认 Agent，再用与模型提供商页相同的横向 Agent 导航切换下面设置的对象；「启动设置」包含默认提供商、默认模型与模型参数；审批等会话行为另分组。
- CLI 入口、配置目录、源码目录与自动更新收进「高级启动配置」，自动跟随上方选定的默认提供商，不再提供第二个提供商选择器或 profile 列表；底层仍分别保存原 profile 的配置。切换默认提供商或 Agent 前检查高级配置的未保存修改。配置目录影响账号与原生历史范围，保留一句影响说明。
- 默认模型使用设置表单的 Select，和默认提供商同宽同高；「自动选择」作为菜单选项，不另起恢复按钮。模型参数按既有语义选控件：Fast、Thinking、Max 等即时开关用 Switch；2–4 个短档位用 Segmented，较多或长标签用 Select。参数位于各自设置行，不套用会话工具栏的模型胶囊。
- 两页的对象导航都用同一套横向下划线页签平铺 Agent；单行不换行，超过宽度时横向滚动，选中项和键盘焦点自动进入可见区域。模型提供商页下方保持纵向列表，只显示名称、连接摘要、模型数和默认标记；进入编辑内容后不再显示其余提供商。返回先检查未保存修改。
- 编辑器将「接入方式」与 API 的「网关类型」分开，均用 Select；后者只列通用 API 与插件声明的 adapter。切换网关类型保留连接与模型；切换独立登录源使用该源的连接语义。协议仅在需要用户选择时出现。
- 额度使用所属连接的缓存，刷新时保留读数，初次失败显示重试，不可得显示「—」。更换地址、Key 或类型后不使用旧连接读数；读取失败不影响保存连接或模型调用。
- Web 使用设置内的编辑内容，Mac 用 sheet，手机进入编辑页。复用设置行、选择、反馈组件。样张在 `/design/patterns/forms`。

### 1.4 页面类型

工作台里的页面只有五种，每种对应一个骨架；新页面先归入其中一种，不另起布局。

| 类型 | 骨架 | 内容列 | 用于 |
|---|---|---|---|
| 会话页 | `Workbench` 的会话区 | 阅读 | 会话、个人助理；页头是标签栏或标题行，底部是输入框。个人助理页去掉只对项目有意义的操作（[个人助理](../../ASSISTANT.md) §3.1） |
| 文档页 | `PageScaffold column="document"` | 768 | 自动化 |
| 看板页 | `PageScaffold column="board"` | 1200 | 统计、任务看板 |
| 目录加正文 | `PageScaffold` 的 `aside` | 正文按文档、看板或阅读列 | 设计规范；插件、收藏（正文看板档，卡片网格）；扩展管理（见现状） |
| 项目主页 | 新会话页 | 输入框居中，宽度同阅读列 | 选定项目后的起始页 |

- **目录加正文**：`aside` 是滚动区左侧一列，宽 224（`w-56`），底 `bg-sidebar`、右边线 `edge-r`，自己滚动；窄于 `lg` 时隐藏，目录收进页头的菜单。正文仍是 `PageScaffold` 的唯一滚动容器。目录的行用 `ListRow`，分组标题 `text-2xs font-medium fg-4`；目录里的条目除了去处，也可以是筛选（插件页的「有更新」、收藏页的类型与项目）和一行添加动作，放在所属分组的最后。
- **页内导航**：目录列的是这一页内容的范围（插件页的已安装、各个插件源；收藏页的类型、项目、Agent），而不是文档的章节时，不铺 `bg-sidebar`、不画 `edge-r`，与正文同底；顶部内边距与正文列相同，第一行和正文标题对齐。
- 页面与会话页共用页头规则（§1.2）。设置不是页面，是 §1.3 的工作区弹窗。
- 看板页的概览区、统计和项目主页是概览面，可以用数据色、一处渐变和一次性的图形绘制；会话页、文档页和各页里的列表是阅读面。两类面的上限见[基础](foundations.md) §12。

**现状**：

- 扩展管理（`extensions/ExtensionsPage.tsx`）仍用 `PageHeader` 自建双栏，目录带 1080 的上限；尚未改用 `aside`。

#### 看板概览

- 概览放在筛选工具栏下方，使用 `ChartCard`。趋势图占主区域，状态构成在侧栏，窄屏排到趋势图下方。
- 两条趋势线共用日期轴和从零开始的数量轴。填色只标示完成趋势，另一条用虚线区分。跨天查看时，参考线、数据点和读数对应同一天，支持指针、键盘和触屏。
- 状态构成用实心的水平堆叠条表示占比，沿用状态色，中性状态可用不同深浅区分。图例的标签和数字共用文字基线，状态数量右对齐。筛选时条段原位过渡，开启减少动态效果时即时更新。
- 卡片、列表和图表使用同一筛选范围。收件箱等与状态重叠的数量放在概览标题旁。

#### 看板任务卡

- 列和页面同底，靠列头和间距分组。卡片浅色用 `bg-subtle`、深色用 `bg-elevated`，圆角 12。焦点沿用焦点环，选中和拖放目标有单独的底色。
- 悬停时卡片轻微上移，快捷操作与时间共用尾部位置。减少动态效果时保留底色反馈。普通卡片标题用中等字重，已结束的任务降为次要文字色。

### 1.5 首次启动与未连接

各端客户端（Mac、Android、iPhone）不连接服务器也进入主界面；第一次启动先走一遍全屏引导。Web 由服务器提供，打开页面即已连接，「未连接的主界面」不适用；全屏引导去掉「服务器」页照样走。稿件见 [onboarding-demo.html](../onboarding-demo.html)。

**全屏引导**

- 只在这台设备第一次启动、且没有保存过任何服务器时出现。已配对或已有本机服务器的设备（老用户、升级）不出现。
- Web：只在这个浏览器没走过引导、服务器上还没有任何会话、服务器不由 Mac App 运行时出现。其中一条不满足，就记为已走过，以后也不出现。
- 铺满窗口（Mac 连侧栏一起遮住），一页一个决定。只有需要读者决定的页才出现：Agent 只有一个就跳过这页，手机通知已授权就跳过这页。进度条的格数按实际页数。
- 页面结构：顶栏中间进度条、右侧「跳过」，桌面从第二页起在左侧加返回（手机的每一页都在完成上一步后才出现，不设返回）；内容列 440 居中，标题用该端最大的页面标题档（Mac `RiffetFont.pageTitle`），下面一句说明（`fg-3`，只写读者推断不出的事），内容与说明、按钮与内容相距 28；主按钮满宽，高 40、圆角 12，桌面上带一个弱化的 ↩，回车前进。手机按平台字号放大，主按钮在底部。
- 欢迎页的标志在原位描画一次（品牌动效只用在标志位置），之后是品牌名、一句说明和「开始」。
- 桌面：欢迎 → 服务器（这台 Mac / 其他服务器）→ Agent（多个时选默认；没有时给安装命令和「重新检测」）→ 项目（在服务器上选目录，可「先不选」）→ 手机（配对二维码，可「以后再说」；本机服务器只听本机时，先给主按钮「允许同一网络的设备连接」，重启后再显示二维码；配对的手机能被 Agent 操作时，在下方说明入口在「技能与工具」）。
- Web：欢迎 → Agent → 项目 → 手机，同桌面去掉「服务器」页。Agent 只有一个时跳过这页，并在服务器没有默认 Agent 时把它设为默认（Mac 同样）。项目页在服务器已有一个项目时预先选中它。手机页只在服务器已对网络开放时出现；网页里不提供开放局域网的开关。
- 手机：欢迎 → 连接你的电脑（扫码为主，同一网络里发现的服务器列在上面，可输入地址）→ 通知权限 → 新会话页。手机通常是第二台设备，不再问 Agent 和项目。
- 跳过或完成都直接进入主界面，已完成的步骤带过去，剩下的由新会话页的设置卡片接着完成。完成后落在平常的新会话页，不放示例会话、起手任务或欢迎页。
- 只在本机记一项「已走过引导」，不写进服务器的设置；Web 记在浏览器里。
- 没有人选过 Agent（这台设备没选过、服务器没有默认）时，新会话页从第一个可用的 Agent 开始，不停在不可用的内置默认上。

**未连接的主界面**

- 新会话页在输入框的位置放设置卡片：同样的外形（桌面 `shadow-composer` 圆角 16；手机为悬浮玻璃输入框），顶行是「服务器 · Agent · 项目」三步，完成的一步打勾并换成结果（这台 Mac、Claude Code、kiln），当前一步在下面展开一句话和动作。三步完成后卡片在原位变成输入框。
- 侧栏、标签栏的去处照常显示。需要服务器的页面显示 `EmptyState`：服务器图标、「需要连接服务器」、「连接」按钮；「连接」回到新会话页。
- 设置里本机的项照常可用；需要服务器的项打开后显示同一个空状态，手机的设置行在行尾写「未连接」。
- 使用中不插一次性提示（教学浮层、计数提示、「知道了」）。需要解释的行为放在后果出现的地方，例如排队消息栏自带「补充到当前任务」。

**现状**：

- 手机上列出的局域网服务器点「连接」后仍要输入配对码，服务器端还没有「在电脑上允许这台手机」的确认流程。
- 设置卡片的「跳过」（不选项目）：Android 转到快速对话，服务器没有快速对话项目时不显示「跳过」；iPhone 只在页面重建前有效。两端都还没有「无项目」的完成态。
- Mac 菜单栏里跳转页面的命令在未连接时不响应，不会落到「需要连接服务器」。
- 引导页和设置卡片还没有加进 Mac、Android、iPhone 的设计规范页样张（Mac 原生规范页尚未建成）。Web 的引导页样张在「模式 · 页面」。
- Web 跳过引导后没有设置卡片：Agent 不可用时仍只在输入框下给出原因和「重新检测」。

## 2. 浮层

### 2.1 选哪一种

| 需要 | 用 | 关闭方式 |
|---|---|---|
| 给纯图标按钮一个名称和快捷键 | `Tip` | 指针或焦点离开 |
| 从一个触发点执行操作，或在一组命令里选一个 | `DropdownMenu` | 选中、Esc、点外部 |
| 锚定在触发点旁的小块可交互内容，改动即时生效 | `Popover` | Esc、点外部 |
| 需要集中处理、有提交和取消的任务 | `Dialog` | 提交、取消、Esc |
| 确认一次不可逆的操作，或输入一个值 | `confirmDialog` / `promptDialog` | 确认、取消 |
| 报告一次操作的结果 | `toast` | 自动消失（成功 2.8 s、信息 3.5 s、错误 6.5 s），悬停时暂停 |
| 一个持续存在、需要读者知道的状态 | `Notice`（行内，非浮层） | 状态解除 |

- 一次操作只出现一个浮层。菜单里的命令需要更多输入时，关闭菜单再打开弹窗，两者不叠放。
- 浮层从触发它的控件展开，原点在触发点一侧；关闭时收回同一位置（[原则](README.md) §2 第 3 条）。

### 2.2 弹窗

- **宽度**分四档：

| 档 | 宽度 | 用于 |
|---|---|---|
| 确认 | 420 | `confirmDialog`、`promptDialog` |
| 表单 | 448（`max-w-md`，默认） | 新建、重命名、单个表单 |
| 内容 | 768（`max-w-3xl`） | 预览、差异、带列表的选择；正文与设置分两栏的编辑表单（自动化：左栏名称与任务，右栏 Agent、项目、时间、运行方式，手机上上下排）；搜索、命令面板、快速打开（列表高 `min(480px, 56dvh)`，切换范围时总高不变） |
| 工作区 | 1080 | 设置这类有自己导航的弹窗 |

- **结构**：页头（标题 `text-lg font-semibold`，可选一句说明 `text-sm text-fg-3`）、正文、页脚。左右内边距 20；页头上 20 下 12，页脚上 16 下 20。关闭按钮在右上角，桌面 28、手机 44。
- **页脚按钮**靠右排列，主操作在最右，取消紧挨在它左边。两者同尺寸；取消用 `ghost`。不可逆的确认用 `danger`，打开时焦点落在取消上。主操作的文字是动词加对象（「删除会话」「添加项目」），标题陈述要发生的事（「删除这个会话？」）。
- **手机**：确认、输入和小表单用底部弹层（`mobileSheet`），页脚按钮高 44、等宽铺满一行；大任务（设置、面板）全屏（`mobileFullscreen`）。
- **底与层**：弹窗 `bg-elevated`、圆角 16（`rounded-2xl`）、`shadow-pop`；遮罩 `bg-black/25`（深色 50%）加 1.5px 模糊。
- **动效**：进入取 `fast`、减速曲线，从 `--enter-scale` 放大；退出取 `exitFast`、加速曲线。

- **实现**：宽度用 `DialogContent` 的 `size`（`confirm` / `form` / `content` / `workspace`，默认 `form`），调用处不写 `max-w-*`。底部弹层里 `DialogFooter` 的按钮由样式表拉成等宽、高 44，调用处不再各写一遍。
- 需要等待请求结果、并在弹窗里显示错误的确认（删除会话：先读删除范围，提交失败时留在弹窗里重试）自己写弹窗，结构、宽度和按钮与 `confirmDialog` 相同。

**现状**：

- 图片与可视化预览、侧边面板抽屉是专用浮层，宽度和位置自定，不套四档。
- 目录选择器用 `min(720px, 94vw)` 的固定宽度，Git 面板与文件差异仍是 `max-w-5xl`。

### 2.3 菜单与弹出层

- 共用一种浮层：`bg-popover`、圆角 12、内边距 4、`shadow-pop`，离触发点 6，离窗口边缘至少 8。行高 32（手机 44），行圆角 8，左侧图标 16 用 `fg-3`。危险项放在最后，前面加分隔线，文字用 `danger`。
- 菜单项是命令时以动词开头；是选项时用名词，当前项打勾（`DropdownMenuRadioItem`）。
- **手机**：菜单（含 `Select` 和子菜单）从底部升起成弹层，铺满宽度，上圆角 18，背后加和弹窗相同的遮罩，行高 44。弹出层按内容决定：一组筛选或选项（统计的自定义时间、扩展筛选、头像风格）用 `mobileSheet` 变成底部弹层；锚定在内容某一处的（选中的文字、输入光标、图表上的点、模型选择器）留在原位。
- 只有必须贴着锚点的菜单才传 `mobileSheet={false}`。

#### 侧栏导航

- 导航行分两类。**动作**：新会话、搜索内容，固定在最上面，不能隐藏或调换。**去处**：个人助理、任务看板、自动化、收藏夹、插件、扩展管理、数据统计（Mac 另有活动），每项要么是一行，要么收在「更多」里。
- 去处的行排在动作之后，顺序由用户定；没固定的按上面的顺序列在「更多」菜单里。默认固定个人助理、任务看板、自动化。这台客户端没有的去处（服务器不支持任务、还没有个人助理）不出现。
- 「更多」是最后一行，图标是省略号。点开是菜单，不在原地展开，以免推开下面的会话列表；桌面在行的右侧展开，手机沿用底部弹层。菜单末尾隔一条线放「自定义侧栏」，打开设置的「侧栏」页。当前页面收在「更多」里时，「更多」这一行显示选中态。
- 设置的「侧栏」页分「固定显示」和「更多」两组：行尾是图钉按钮（实心为已固定，点击移到「更多」；空心为在「更多」里，点击固定到侧栏），固定的行拖把手排序（[可排序列表](components/navigation.md)）。保存在服务器（`AppSettings.sidebarPinned`），所有设备生效；某端不认识的去处保留原位、跳过不显示。
- 新的一级页面加进 `SIDEBAR_DESTINATIONS`（`packages/contracts/src/settings.ts`），默认不固定。
- Web 实现在 `apps/web/src/app/Sidebar.tsx`、`sidebarDestinations.ts`、`settings/SidebarSection.tsx`。

#### 侧栏个人菜单

- 底部只留头像，合并原来的更多、设置与连接入口。桌面菜单在头像上方展开，左对齐，宽 256；手机 Web 不弹菜单，点头像直接进入设置（设置首页就是个人资料与主题）。
- 顶部整行进入个人资料：36 的头像、昵称与次要色的「个人资料」、行尾箭头；没有昵称时只显示「个人资料」。行内左右 8、上下 12，头像与文字间距 12。
- 分隔线后是主题（Mac 为外观）与设置；页面入口都在侧栏导航里，不在这里。主题保留子菜单，Mac 设置保留 ⌘, 快捷键。不另加「更多」层级或分组标题。
- 远端连接或离线时，连接信息收进菜单，地址与复制入口仍可达。只有连接或后端异常时头像带提醒点，菜单中对应入口显示具体问题；健康时不显示状态点。
- 个人资料、设置沿用现有页面，选中后先收起菜单。用户信息只使用昵称与头像，不添加账号、邮箱或套餐字段。
- 有新发布版本时，底部右侧出现更新提示：`quiet` 按钮，强调色，上箭头加版本号，高度与头像按钮一致；说明只放在提示气泡与无障碍名称里。点击打开「设置 › 关于 Riffet」。关于页看过该版本后只留箭头，更新后消失。它不是常驻入口，没有新版本时这一侧留空。
- Web 实现在 `apps/web/src/app/SidebarUserMenu.tsx`、`SidebarUpdateButton.tsx`，样张在 `/design/patterns/overlays`。

### 2.4 层级

叠放顺序只用 `--z-*`：侧边条 10、面板 20、终端 30、全屏 60、拖放 65、遮罩 69、弹窗 70、菜单 75、提示 80、通知 90。菜单高于弹窗，所以弹窗里的菜单能盖住弹窗；通知最高，弹窗打开时仍然可见。

## 3. 选择控件

按两个问题选：选的是一个**值**，还是在切换**下方内容所属的对象或视图**？选项是**固定的几个**，还是**数量随数据变化**？

| 选什么 | 选项 | 用 |
|---|---|---|
| 值 | 2–4 个，固定，标签不超过 4 个汉字或一个英文词 | `Segmented` |
| 值 | 5 个以上，或数量随数据变化（Agent、模型、插件） | `Select`（应用的菜单，选项可带图标） |
| 值 | 需要看描述或预览才能选（主题、布局） | 带缩略图的单选卡片（`SettingsThumbChoice`） |
| 开或关 | — | `Switch` |
| 视图 | 页面的一级视图，2–5 个 | `UnderlineTabs` |
| 视图 | 一级视图内部的子视图，2–4 个 | `Segmented` |
| 下方内容所属的对象 | 任意个 | 标题式 `Select`（`appearance="heading"`）：对象名作为下方各组的标题，点开切换 |
| Agent 配置对象 | Agent 页和模型提供商页，名称直接可见 | 可横向滚动的 `UnderlineTabs` |
| 下方内容所属的对象 | 需要并排比较各对象的状态 | 对象列表，每行进入二级页 |

- `Segmented` 的总宽超过所在行的一半，或者在 360 宽的手机上放不下，就换成 `Select`。
- 同一行只放一种选择控件。同一种选择在不同页面用同一种控件；Agent 页和模型提供商页的对象导航按 §1.3 使用相同横向页签；「默认 Agent」仍用 Select。

- 插件详情的「配置」页由插件决定有几个，用标题式 `Select` 切换。

在选择控件的选用上，2026-11-14 的决定见 [DECISIONS](../DECISIONS.md)「选项多或切换所属对象时改用 Select」。

## 4. 导航

读者经过四层：会话、盖在会话上的页面、浮层，以及通往会话的两条路径（侧栏与标签页）。上层关闭后回到下层，不改变下层的状态。

| 层 | 组件 | 地址 | 关闭或离开 |
|---|---|---|---|
| 侧栏 | `Sidebar.tsx`：顶部是导航行（新会话、搜索内容、固定的去处、更多，见「侧栏导航」），下面是按项目或时间分组的会话，项目可折叠 | 无 | ⌘B 收起；收起后悬停边缘浮出；手机上是抽屉 |
| 会话标签页 | `tabs/TabBar.tsx`、`tabs/tabsStore.ts` | 当前会话的 `/c/<sessionId>` | ⌥W；点标签的关闭按钮 |
| 页面 | `PageScaffold` | `/tasks`（任务）、`/automations`（自动化）、`/marks`、`/stats`、`/extensions`、`/plugins?id=…`、`/design/<章节>` | Back、Escape |
| 浮层 | 搜索、命令面板与 §2 的各种浮层 | 无 | Escape、Back |

### 4.1 会话标签页

- 标签有两种：**已保留**（实线）和**临时**（虚线）。临时标签被下一个打开的会话替换，所以浏览不会留下一排标签。
- 两项设置决定新标签的状态（`tabs/tabsStore.ts`）：「打开会话时」`preview`（默认）、`keep`；「新建会话时」`keep`（默认）、`preview`，「打开会话时」为 `keep` 时覆盖它。
- 临时标签只靠读者自己的保留动作变成保留标签：双击、「加入标签栏」、⌘ 点击、置顶。发送消息、会话开始运行都不保留它。
- 标签栏有三种样式：关闭、标题栏（标签取代标题行）、独立一行（标签在主区上方的画布上）。
- 个人助理的主对话不成为标签，也不在侧栏的会话列表里：它从侧栏导航的「个人助理」一行进入，页头是标题行（[个人助理](../../ASSISTANT.md) §3）。

### 4.2 页面与地址

- 页面盖在会话上，地址不含会话 ID；刷新后下层的会话由上次的选择恢复。会话是 `/c/<sessionId>`（`?mark=<markId>` 定位到一条收藏），项目主页是 `/p/<projectId>`。地址由 `state/page-url.ts` 的 `readPageAddress` / `pageAddressUrl` 读写，用 `replaceState` 同步，不为每次切换增加历史记录。
- 插件 ID 含点，服务端把带扩展名的路径当文件，所以 ID 放在查询参数里（`/plugins?id=…`）。
- 页面经 `PageScaffold` 登记为一层，Back 与 Escape 都到 `onClose`（`lib/overlay-navigation.ts`）。

### 4.3 视图层级

- 页面的一级视图用 `UnderlineTabs`，放在内容列顶部；视图内的筛选与子视图用 `Segmented`。两层不用同一种控件，才读得出层级。选用规则见 §3。

### 4.4 搜索与命令面板

- 同一个浮层（`CommandPalette.tsx`）有两个范围：⌘K 是「会话」，按标题或内容找会话；⌘⇧P 是「命令」，动作、会话和项目排在一个列表里，排序规则在 `lib/command-search.ts`。
- 焦点始终在查询框里，当前行用 `aria-activedescendant` 标出，所以输入不被打断。切换范围时列表高度不变（§2.2）。侧栏的「搜索内容」是同一入口。

## 5. 反馈与加载

### 5.1 反馈放在哪里

| 情形 | 用 | 位置与时长 |
|---|---|---|
| 字段或步骤的错误 | 行内 `<p role="alert" class="text-danger">` | 紧挨出错处，随修正消失 |
| 一次操作的结果 | `toast` | 顶部居中，最多 4 条；成功 2.8 s、信息 3.5 s、错误 6.5 s，带撤销的至少 6 s，悬停暂停 |
| 持续存在的状态 | `Notice`（行内） | 留在所属内容里，状态解除才消失 |
| 输入框里的提示 | `FeedbackNotices`（`components/ui/feedback-notice.tsx`） | 输入框上方；出现后至少可见 1500 ms |
| 会话中的失败 | `FailureDetails`（`session/FailureDetails.tsx`） | 在时间线的失败记录里；原因可见，诊断折叠在 `Collapse` 里 |

- **同一次失败只显示一处**（DECISIONS 2026-11-12）：已加载的失败记录负责展示，消息下方不重复。
- **提示条跟随主题**（DECISIONS 2026-11-13）：`toast` 与提示条用浮层底色、细描边与阴影；成功与失败只体现在图标颜色上，失败时整条不染红。`Notice` 是行内的浅色底，不是浮层。
- 正常操作不增加成功通知；展示时序、最短时长与适用范围见 [feedback-presentation.md](../feedback-presentation.md)，不在此重复。
- 等待不是提示：加载、保存、同步这类状态只由正在等待的控件表达，结束后不留下「已完成」。

### 5.2 加载

- **原地**：`Spinner`（14）放在正在等待的控件内，替换它的图标位；按钮宽度不变，邻近控件不移动。
- **骨架**：`Skeleton`（`components/ui/skeleton.tsx`），尺寸与真实内容一致，数据到达时页面不跳动；用在统计页、服务状态页与模型协作（起始页、打开一场讨论）。
- **转圈还是骨架**：读完之前就知道长什么样（几个席位、几行、几张卡）的，按最终结构画骨架；形状要等数据才知道的，用转圈。骨架只替换待读的部分，读前就确定的文字（角色、分组名、按钮）照常显示；不能只画出装饰而缺了它们所属的主体，例如只剩一个 `VS`、一条分隔线或一个空标题。读取中能改变结果的操作（提交、添加、移除）不可用，或者不显示。
- **切换设置对象**：已读取的提供商、模型目录和能力按 Agent／提供商保留，刷新不清空表单。首次读取新对象时，`SettingsGroup loading` 暂时保留该分组最近一次完成布局的高度；模型目录就绪后再显示完整模型行与参数，不先收缩成一个 spinner 再逐行展开。不同对象实际字段数不同时，最终高度可以不同。
- **会话里**：`WorkingIndicator`（`session/Timeline.tsx`）：一个脉动圆点、「正在处理」的流光文字与已用时间；已用时间的槽位一开始就存在，计时增长不挤动旁边的输出速率。
- 整页加载时，`Spinner` 居中，不带文字。

### 5.3 空状态

- 用 `EmptyState`：图标块、标题（现状是什么）、可选一句说明、可选一个下一步按钮。失败的空状态（无法读取设备）附「重试」；没有下一步时只有标题。

**现状**：

- 没有共用的加载延迟阈值；`Spinner` 立即出现。`feedback-presentation.md` 称各入口沿用自身的延迟，代码中未找到共用实现。
- `Field` 已有 `error` 槽；`plugins/PluginFlowDialog.tsx` 的 `<p role="alert">` 是流程级失败，不属字段错误，保持手写。

## 6. 确认与撤销

按「能否取回」选：

| 操作 | 用 |
|---|---|
| 可恢复 | 立即执行，`toast` 带「撤销」 |
| 不可恢复 | `confirmDialog({ destructive: true })` |
| 会丢失未保存的输入 | `useDiscardGuard`：干净时直接关闭，有改动时确认「放弃修改」 |
| 输入一个值 | `promptDialog`（重命名） |

- Git 面板的丢弃是同一动作两条路径：能先备份检查点时，立即丢弃并给「撤销」（`panels/GitPanel.tsx` 的 `discarded`）；无法备份（`DISCARD_UNRECOVERABLE`）时先 `confirmDialog`，说明「无法恢复」。清空评论同理，立即清空并给「撤销」。
- `confirmDialog` 的 `destructive: true` 使用 `danger` 按钮，打开时焦点落在取消上；非危险确认的焦点在主操作上。
- **措辞**：标题陈述要发生的事（「删除这个会话？」），说明写后果与范围，主按钮是动词加对象（「删除会话」「放弃修改」），不写「确定」「确认」。取消永远叫「取消」。
- 需要等待请求结果、并在弹窗里显示错误的确认自己写弹窗（§2.2）。

**现状**：

- `promptDialog` 不传 `confirmLabel` 时主按钮仍默认「确定」（`confirmDialog` 已要求必填）。

## 7. 表单与设置

### 7.1 设置行

- `SettingsGroup`：组标题（`text-xs font-medium fg-3`，高 28）加一张卡片（`rounded-xl border-line bg-elevated`，横向内边距 16，手机 12，行间 `edge-t`），卡片下可有一行 `note`（`text-xs fg-3`）。无标题的组直接以卡片开始。
- `SettingsRow`：左侧名称（`text-sm font-medium`）与可选说明（`text-xs fg-3`），右侧控件；纵向内边距 14。手机上纵向堆叠，控件行高至少 44，开关除外。
- `SettingsLinkRow`：进入二级页，高 48，右侧 `IconChevronRight`（`fg-4`）。
- 这三个组件由 `app/settings/SettingsLayout.tsx` 导出，同时供插件页使用。

### 7.2 字段

- `Field` 是标签（`text-sm font-medium`）、控件、可选提示（`text-xs fg-3`）的纵向组合，间距 6。
- 校验在提交时进行，错误显示在字段下方，用 `role="alert"`，字段带 `aria-invalid`；错误文字说明如何修正。离开字段时不弹出错误。

### 7.3 保存

| 位置 | 保存 | 离开时 |
|---|---|---|
| 设置页、`Popover` | 改动立即生效 | 无需确认 |
| `Dialog` 表单 | 提交时保存，页脚「取消」与主操作 | 有改动时经 `useDiscardGuard` 确认 |

### 7.4 说明文字

- 只写读者推断不出的信息：存储位置（「仅保存在这台设备」）、是否需要重启、是否跨设备、计费与权限；每条一句。不复述控件的名称或显然的行为。

## 8. 列表

- **行**：`ListRow`（`components/ui/list-row.tsx`）：高 32（触屏 44），横向内边距 10，圆角 `lg`；依次是前置图标（16，`fg-3`）、标题（单行截断）、元信息（`text-xs fg-4`，`tabular-nums`）、尾部操作。
- **并列分组**：相同的行尾字段占用同一组列宽。项目和标题用可伸缩的区域，行尾元信息过长时截断，时间和操作共用末列。
- **尾部操作**：指针停留（`group-hover`）或键盘进入（`group-focus-within`）时出现，触屏（`no-hover`）上常驻。用 `RowActions`（或 `rowReveal`），分组名固定 `group/row`，菜单打开时也保持显示。操作藏起来时仍占位，行宽不变，也不拦截点击。
- **更多**：溢出操作收进 `IconEllipsis` 的 `Button size="icon-sm" variant="quiet"`，`aria-label` 为「更多操作」，菜单靠右对齐；删除放在最后，用分隔线隔开（§2.3）。
- **当前行**：`bg-active`，文字 `fg`；悬停行 `bg-hover`。当前与悬停不同时靠描边或阴影表示。
- **空列表**：`EmptyState`（§5.3）。

## 9. 搜索与筛选

- **搜索框**：`SearchField`（`components/ui/search-field.tsx`）：`Input` 加左侧 `IconSearch`（16，`fg-4`），`pl-8 pr-8`；右侧空时显示聚焦键 `Kbd`，有内容时换成清除按钮（`IconX`，`Button size="icon-xs" variant="quiet"`，`aria-label` 为「清除搜索」）。
- **Escape**：有内容时先清空；已空时失焦，浮层里的查询行按浮层规则关闭。输入法组词期间不响应（`isComposingKey`）。
- **筛选**：固定且少的选项用 `Segmented`；更多条件收进 `IconListFilter` 图标按钮的弹出层，有启用项时按钮变 `secondary` 并显示数量。
- **无结果**：`EmptyState`，标题写明没有符合什么（「没有符合条件的收藏」），不重复输入的关键词。
- **匹配**：`lib/command-search.ts` 的 `matchCommands` 要求每个以空白分隔的词都命中标签或关键词，标签前缀命中排最前；当前不在结果里高亮命中的文字。

**现状**：

- 浮层里的查询行（`CommandPalette.tsx`、`SessionSearchDialog.tsx`、`ImportSessionDialog.tsx` 的 `QuickInput`）是组合框，外观与 Escape（关闭浮层）都不同于 `SearchField`。
- `Sidebar.tsx` 的「搜索内容」是打开浮层的按钮，不是输入框。

## 10. 键盘

### 10.1 快捷键

| 范围 | 键 | 来源 |
|---|---|---|
| 工作台 | ⌘K 搜索会话 · ⌘⇧P 命令面板 · ⌘B 侧栏 · Ctrl+\` 终端 | `app/use-global-shortcuts.ts` |
| 会话标签页 | ⌥1–8 · ⌥9 · ⌥[ · ⌥] · ⌥W · ⌥⇧T · ⌥T · ⌥I · ⌥⇧1–3 | `app/tabs/keys.ts`（显示）、`use-global-shortcuts.ts`（实现） |
| 输入框 | 发送 ⌘↵ 或 ↵（随「回车键行为」）· ⇧↵ 换行 · Esc 关闭菜单 | `session/composerKeyboard.ts` |

- Mac 的命令键是 ⌘，其他平台是 Ctrl。Mac 上 Ctrl+K、Ctrl+B 是文本框自己的编辑键，只有 ⌘ 能触发工作台快捷键。标签页用 ⌥（Alt），因为浏览器占着 ⌘/Ctrl 加 T、W、数字；终端内的 ⌥ 留给终端。
- 快捷键按物理键（`event.code`）匹配，使用 ⌥ 输入字符的键盘布局仍然有效。输入法组词期间一律不触发。
- **显示**：纯图标按钮的 `Tip` 带 `kbd`；列表中的快捷键用 `Kbd`；行文里用 `shortcutLabel`（Mac「⌘K」，其他「Ctrl+K」）。

### 10.2 焦点与 Escape

- 键盘焦点显示 2px 的焦点环（`:focus-visible`，偏移 1px）；输入框改用强调色边框加 3px 的 15% 光晕。焦点环只跟着导航键（Tab、方向键等）出现，点击、脚本移动焦点和之后的按键都不显示（`lib/focus-ring.ts`）。
- Escape 关闭最上面的一层，一次只关一层：菜单、弹窗、页面，依次向下（`lib/overlay-navigation.ts`）；输入框里先关闭菜单，再轮到下一层（`resolveEscapeLayer`）。浏览器的 Back 走同一栈。
- 浮层在用户正输入时打开，关闭后把光标还给原来的输入框，而不是触发它的按钮，否则下一次空格会再次打开它（`components/ui/focus-return.ts`）；手机上沿用各浮层原本的归还，避免弹出键盘。
- 弹窗按 Tab 在其内部循环；危险确认的初始焦点在取消上（§2.2）。

### 10.3 插件快捷键

- 插件命令只声明默认组合（`Mod+Shift+K` 的写法，`Mod` 即 ⌘ 或 Ctrl），必须含 Ctrl、Alt 或 ⌘ 之一。工作台已占用的组合（上表，加浏览器的 ⌘/Ctrl 加 T、W、N、Q、R、L 与数字）和先注册的命令占用的组合会被拒绝并记录原因（`app/pluginKeybindings.ts` 的 `registerKeybindings`）；插件不能覆盖工作台的键。

**现状**：

- 输入框的键（`composerKeyboard.ts`）不在登记表里，随「回车键行为」设置变化。
- 登记表（`app/hostShortcuts.ts`）只记键位，处理仍分在 `use-global-shortcuts.ts` 与 `session/ViewDots.tsx`（⌥⇧1–3）；新增工作台快捷键要在两处同时加。
