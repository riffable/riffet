# 设计决策

只追加，不改写。已定的界面取向写在这里，连同被否掉的做法；具体规则留在各自的文档，这里只给结论和出处。要推翻一条，追加一条新的并写明替代哪条。

格式：日期 · 标题，然后是决定、原因、否决过的做法、规则所在。

---

## 2026-10-27 · 克制是降噪，不是删减

- **决定**：去重复、去复述、只在异常时显示状态；保留有价值的入口、品牌元素和已经好用的交互。名称取自然、一致的说法，开发者熟悉的英文标识（工具名等）保留原文。
- **原因**：一轮全端克制改造后，新会话页只剩输入框，侧栏名称被硬缩成两个字，工具名被逐个翻成中文，内部滚动被换成整段展开，反而更难用。
- **否决**：为凑字数统一改名；把职责不同的设置硬并到一页；用规则文档代替看实际画面。

## 2026-11-03 · 阅读配色接近无彩

- **决定**：正文用接近无彩的墨色（浅色约 15–17:1），纸底色度很低，次级文字约 10:1，强调色中等饱和、取自天然材质，状态色深而沉。内置 12 套主题。
- **原因**：借来的终端配色（Solarized、Catppuccin 等）的浅色版带色中灰正文、层级塌缩、墨与纸色相冲突，显得廉价。
- **否决**：高饱和强调色；带色正文。
- **规则**：`docs/THEMES.md` §2。

## 2026-11-04 · 原生风格的主区满铺

- **决定**：原生风格里会话和详情栏保持满铺。玻璃感只通过底层材质、透明度和标题栏连续性来做。
- **原因**：侧栏已经是系统的浮动玻璃，主区再做一层卡片就是卡片叠卡片，显得拼凑。
- **否决**：主区四周留玻璃边、做成内缩圆角卡片。
- **注**：Riffet 风格照 Web 使用内缩卡片，这是那种风格自己的范式，见下一条。

## 2026-11-10 · 三种界面风格：差异在组件和范式

- **决定**：原生（系统组件）、Riffet（自绘，以 Web 为准）、Claude（自绘，满铺加分隔线，分区用线条不用阴影）。两种自绘风格共用一套组件，只换配方。
- **原因**：只换圆角、行高、选中色的几套风格看不出本质差异。
- **否决**：只在参数层面做差异的「经典 / 原生 / 色调」三套。
- **规则**：`docs/design/interface-styles/`。

## 2026-11-10 · Agent 能力按对话选择

- **决定**：Skill、MCP、手机控制等能力都放进输入框的「技能与工具」，新对话沿用这台设备上一次的选择。唯一例外是设备上的「允许 Agent 操作这台手机」，这需要本人在设备上同意。
- **原因**：按端默认、会话快照、按会话覆盖三层配置，对用户来说难以理解。
- **否决**：为单个功能另设开关；按端（Web、Mac、Android、iOS）分别配置默认值。

## 2026-11-11 · 输入框是悬浮的玻璃岛

- **决定**：输入框是一块悬浮的玻璃，内容在它四周和下方照常滚过、照常可见。可读性只在输入框自己的形状里解决：框内磨砂，iOS 上用 material 加 glass。
- **否决**：给输入区铺实底或整块渐变；把整个底部区域一起模糊。

## 2026-11-11 · 动态标志只做氛围

- **决定**：动态标志只出现在标志本来就在的位置（新会话页、启动、关于），由时间、场景等环境因素驱动，用来营造放松和灵动的气氛。
- **否决**：用它兼任会话列表、对话末尾、菜单栏里的运行或等待指示。状态指示另有自己的组件。
- **规则**：`docs/design/macos-native.md` §3.3（循环动画）。

## 2026-11-12 · 图标描边以 Web 为准

- **决定**：Web 用 Lucide 一个家族；移动端和 Mac 的 Lucide 图标包与它一致（Mac 默认仍是 SF Symbols，其他图标包照作者原样）。Lucide 描边以 Web 为准：任何尺寸都是 1.25 屏幕像素（`apps/web/src/components/icons-base.tsx`，配合 `non-scaling-stroke`）。Android 按渲染尺寸换算线宽；Mac 的符号随字号缩放，以 16pt 的框为基准对齐。主导航图标 18px，颜色跟随所在行的文字。实心只用于表示状态。
- **原因**：清晰感来自尺寸、对比度，以及描边与文字笔画相当。
- **否决**：16px、中灰色的粗描边图标；为了清晰去换图标库。

## 2026-11-12 · 设置页保留原有分类

- **决定**：改设置页时保留原有分组，每项设置一行。只改善每一页的样子，不重新分组。二级页隐藏底部标签栏；整页加载时只在中间放一个不带文字的指示器。
- **否决**：把主题、显示模式、应用图标收进一个「外观」大页。东西堆在一页里，用起来反而慢。

## 2026-11-12 · 输入框不默认加常驻按钮

- **决定**：给输入框加入口，先看能不能放进已有菜单。必须常驻的非核心功能做成设置开关，默认关闭；开启后用左侧工具按钮的样式。
- **原因**：输入框工具栏是最常被看到的区域，发送键旁边不能出现同等视觉权重的东西。
- **否决**：在发送键旁常驻「稍后发送」按钮。

## 2026-11-12 · Git 面板全英文

- **决定**：Git 面板里所有可见文案都用英文，中文界面下也一样，复数要写对（1 file / 2 files）。Git 面板以外照常本地化。
- **原因**：只把术语换成英文，会出现「改动 / 历史 / Checkpoint」「176 个文件」这样的中英混排，比全中文或全英文都难读。
- **否决**：只翻译部分术语。

## 2026-11-12 · 同一次失败只显示一处

- **决定**：会话中已加载的失败记录负责展示该次错误，消息下方不再重复任务失败及诊断详情；没有对应记录时仍保留消息处的错误。按命令和原生回合身份关联，不按文案合并。结果未知与恢复操作保留。只有结果、没有执行过程的块不加「已处理」标题。
- **原因**：时间线已经合并了重复的失败事件，发送恢复功能却又从同一命令的状态展示一份，导致一条错误在两个组件中重复。
- **否决**：仅在事件列表内去重；无条件隐藏已收件命令的错误；把展示去重写回执行状态。

## 2026-11-12 · 回合结果独立于执行过程

- **决定**：补充上一条：失败、停止等回合结果由行规划放在过程折叠之外。工具和思考仍按用户选择折叠；没有明确最终回答时，结果承接原有回合操作、正文复制与时间。
- **原因**：已加载的错误行仍可能藏在折叠过程里，此时移除消息处的重复提示会让失败完全不可见。
- **否决**：各端分别判断「只有状态时隐藏过程标题」；靠强制展开过程保证错误可见。

## 2026-11-13 · Web 模型菜单的额度栏保留缓存

- **决定**：能返回账号额度的提供商，在模型菜单底部固定显示最近一次成功读数；刷新时保留内容，用就地 loading 表示。暂时读取失败仍保留同一提供商的缓存，切换提供商或会话时不混用读数。
- **原因**：额度读取比菜单打开慢，刷新时清空或隐藏读数会让用户反复等候，也让菜单高度变化。
- **否决**：每次刷新先清空额度；失败后删除成功缓存；在输入框旁新增常驻额度入口。
- **规则**：`apps/web/src/app/session/ModelPicker.tsx`。

## 2026-11-13 · 原生审批使用摘要和有边界的详情

- **决定**：Mac 菜单、Mac 会话和手机中的审批摘要限制标题、正文与选项的展示行数。内容放不下时进入详情；详情顶部使用短导航标题，完整标题、命令和授权规则在同一个正文区滚动，确认操作留在正文区外。长路径自动换行，原文可选择和复制。
- **决定**：动作名与授权规则分开。记住规则前展示后端给出的实际范围；原始标签保留给旧客户端和无法识别的选项。摘要中不能看全的请求进入详情后确认，关闭详情不回答请求。
- **原因**：完整命令拼进按钮名称会撑高菜单和卡片；只限制正文高度仍会被长标题、长选项撑开，整个卡片滚动则会把操作藏起来。
- **否决**：缩小字号容纳长内容；截断授权规则后直接批准；从英文标签猜测授权范围；为详情另建一套提交状态。

## 2026-11-13 · 浏览器是内置插件，画面原生

- **决定**：Agent 的浏览器是可关闭的内置插件 `riffet.browser`：服务端用 Chromium（playwright-core）驱动，工具经 Riffet MCP 按对话注入，入口是「技能与工具」里的「浏览器」。Web 和 Mac 在侧边面板显示实时画面并可接手；Mac 用原生视图画帧，不套 WKWebView。
- **原因**：浏览器跑在 Agent 所在的机器上，远程服务器和本机两种部署都成立；画面与 Agent 操作的是同一个实例。
- **否决**：WKWebView 作引擎（没有 CDP，合成点击不可信）；在 Mac 里内嵌 CEF；默认连接用户日常的 Chrome；另外注入一个 playwright-mcp；为浏览器单设开关。
- **规则**：`docs/BROWSER.md`。

## 2026-11-13 · 插件详情：介绍、插件自己的页、管理

- **决定**：插件详情分三个页签。「介绍」显示包里的 README，下方列出插件提供的功能入口；第二个页签是插件自己的页，由插件在运行时用声明式结构构建，可以包含设置、检测结果、数据和操作，各端用原生控件绘制；「管理」合并原来的管理和诊断。插件没有页面、设置或设置视图时，不显示第二个页签。
- **原因**：原来的「功能」页只有徽章和跳转按钮，「配置」只有文本框，选择类设置只能手填约定值（浏览器只能在文本框里输入 `chrome`）。插件需要展示检测结果和自己的数据，而 Mac 和手机不应为每个插件嵌入网页或单独编写界面。
- **否决**：给每个插件写自定义网页视图作为主要形式（Mac 只能套 WKWebView，手机端无法显示）；只扩展静态的 `settings` 字段类型（无法表达检测结果和数据）；把管理和诊断拆成两个低频页签。
- **规则**：`docs/PLUGIN_ARCHITECTURE.md`「插件详情」。

## 2026-11-13 · Riffet 浏览器由用户和 Agent 共同操作

- **决定**：浏览器面板不分控制权，用户随时可以直接操作，不会打断 Agent；Agent 的下一次结果会提示用户操作过页面。Agent 通过 `browser_handoff` 请用户处理登录、验证码或付款时，面板显示请求条，用户做完点「完成」。「技能与工具」里的条目叫「Riffet 浏览器」，与 Agent 自带的其他浏览器工具区分开。
- **原因**：「接手 / 交还」是从系统视角起的名字，用户不会觉得自己在「交还」什么；而且操作一下就让 Agent 停下，限制过严，只会多出一步。
- **否决**：用户一操作就独占页面、要「交还」后 Agent 才能继续；常驻的「接手」按钮。
- **规则**：`docs/BROWSER.md` §5。


## 2026-11-13 · Mac 侧栏会话行不放 Agent 图标

- **决定**：Mac 侧栏的所有分组（按时间、按项目、分区）及原生样式，会话行都不再以 Agent 图标开头；运行中由行尾的 spinner 表示，Agent 在悬停卡片和标签栏里看。项目树里的会话标题仍对齐项目名。侧栏默认宽度收窄（Riffet 236、Line 248、原生 248 pt），阅读栏默认宽度放宽到 760 pt；双击侧栏边缘恢复默认宽度。
- **原因**：每行一个彩色图标让左侧显得很重，侧栏偏宽、阅读栏偏窄进一步加重这种失衡。
- **否决**：用图标呼吸表示运行中（去掉图标后改用 spinner）。

## 2026-11-13 · 提示条跟随主题，不再反色

- **决定**：web 与 Mac 的提示条改用和弹出菜单、对话框相同的浮层：主题浮层底色、细描边与阴影、正文色；成功和失败只体现在图标颜色上（`--success` / `--danger`）。web 的工具提示仍是深色小标签。
- **原因**：深色反色提示条来自 Material snackbar，在浅色界面里显得重，和其他浮层不是一套视觉语言。工具型 web 产品的默认做法是跟随主题的浅色浮层（Sonner / shadcn、Fluent 2），反色只作为可选变体。
- **否决**：浅色模式下的深色反色提示条；失败时整条染红。

## 2026-11-13 · 审批摘要「看全」指没被截断，换行不算

- **决定**：Mac 审批摘要里，标题和命令只要没被行数上限截断，就直接给「拒绝」和「允许」；折行显示完整的长命令也算看全。带记忆规则的选项不做快捷按钮，只在详情里选；有这类选项不再连带隐藏「允许一次」。菜单栏里，会话名作为卡片的第一行，命令放进代码块，「查看详情」、拒绝、允许依次靠右。
- **原因**：原规则要求整条命令不换行才能批准，菜单栏只有 360pt，带路径的命令几乎都会折行，结果只剩拒绝。
- **否决**：为了出现允许按钮而缩小字号或加宽菜单。

## 2026-11-13 · 「产出」包含 shell 命令改动的文件

- **决定**：编辑工具自带的 diff 仍是主来源；shell 命令的改动由驱动在命令前后各拍一次工作树快照来观测，作为 `observed: true` 的 diff 并入该命令的工具结果，「产出」和命令行的 diff 卡片直接复用。快照存在状态目录的影子 git 仓库里，借用项目对象库，不写项目的 `.git`；只观测 git 工作树。Claude 先接入（PreToolUse / PostToolUse hook），其他驱动按同一接口接入。
- **原因**：只认编辑工具时，agent 用 `sed`、脚本、格式化或代码生成改的文件全部缺席。据 anthropics/claude-code#94657，Claude Code 在 auto 和 bypass 模式下也开始倾向用 Bash 改文件。窗口缩到单条命令后，同目录其他会话或编辑器的写入只在命令执行的那几秒里混入。
- **否决**：每回合或每一步拍快照（opencode、Cline 的做法，同目录多会话互相串）；每会话一个 worktree（改变产品形态）；从命令文本猜测改了哪些文件；直接使用项目的 index 或往项目对象库里写入。
- **决定**：子 agent 的改动（编辑和命令）由服务端从它的 lane 汇总成按文件的统计，挂在启动它的那一行的 `subagent.changes` 上，「产出」据此并入。异步子 agent 的结果行在它开始干活之前就写下了，所以不在结果行上汇总。
- **决定**：Codex 用启动时注入的 PreToolUse / PostToolUse hook；hook 须由用户在 Codex 的信任机制里确认才生效，Riffet 不伪造信任记录。PostToolUse 晚于命令完成通知，所以已开窗的命令的完成事件最多延后 4.5 秒等观测结果。Cursor 的 hook id 与转录里的调用 id 不同，在 postToolUse 时从它的 chat store 找命令相同、尚无结果的唯一调用，按真实 id 记录；找不到唯一的一条就不记录。
- **规则**：`apps/server/src/backends/shared/workspace-observer.ts`；子 agent 汇总在 `apps/server/src/timeline/service.ts` 的 `subagentFileChanges`。

## 2026-11-13 · Mac 服务器状态提示用 NoticeBar

- **决定**：主窗口和菜单栏的服务器提示（已停止、版本不一致、重启被会话阻塞）统一用 `NoticeBar`。主窗口里是内缩的浮起卡片，图标、说明、操作在同一行，主操作靠右；说明与阻塞原因并入正文，不另起行。
- **原因**：原来的横幅是手写的通栏色带，标题、按钮、说明各占一行，和其他提示不是一套样式。
- **否决**：整宽色带；把说明放在按钮下面。

## 2026-11-13 · Riffet 风格是主风格，先打磨它

- **决定**：Riffet 风格是主风格，先按一页视觉规则整页打磨，Mac 与 Web 共用这套规则。原生和线条风格保留，界面风格的扩展能力不变；打磨 Riffet 风格得到的规则，之后再套用到其他风格。规则只引用颜色角色和尺寸档位，主题、字体和缩放仍由用户决定。
- **原因**：Mac 端按风格配方分支的地方约 100 处，分布在 28 个文件里。打磨的精力分摊到三种风格上，没有一种被做到位，App 也就没有统一的样子。参照的 Multica 桌面端只有一种字体、三档字号、两种字重、一种分隔线，看起来整齐，是因为没有例外。
- **否决**：删掉其他风格，只留一种；三种风格同时推进；逐条修缺陷，不先定规则。
- **规则**：`docs/design/riffet-style.md`；稿件在 `docs/design/interface-styles/pages/riffet-next/`。

## 2026-11-13 · 侧边面板可以悬浮

- **决定**：侧边面板除了停靠和全屏，还可以悬浮在会话上方。整块面板连同页签一起悬浮，不按视图单独弹出。拖标题栏移动，四边和四角都能调整大小；靠近会话区边缘 16 以内时吸附，Web 内缩 16（会话卡片自带 8 的外边距），Mac 内缩 8。吸附的边在窗口缩放时保持贴住。悬浮是全局布局偏好，位置跨会话记住；是否打开仍按会话。悬浮和全屏互斥。窄窗口和手机仍用底部面板。
- **原因**：浏览器、Logcat 这类视图要和对话同时看，停靠时被侧栏宽度限制，全屏又挡住对话。
- **否决**：开独立的系统窗口（用户要的是窗口内的悬浮效果）；只给浏览器加悬浮（各面板的需求相同）。

## 2026-11-13 · 弹窗共用一种浮层

- **决定**：Riffet 风格下，菜单、弹出层、`/` 和 `@` 菜单、模型选择器、工具栏的子 Agent / 任务列表共用一种浮层，圆角 12（新增配方 `radii.menu`，对齐 Web 的 `rounded-xl`；输入框仍是 16），阴影取 Web 的 `shadow-pop`，行圆角按内边距嵌套。Git 分支菜单改用应用自己的菜单。弹窗里的选择改成不带边框的胶囊，开关用墨色。标签栏的 agent 标志保留品牌色。
- **原因**：菜单用的是输入框那档 16 的圆角，内边距 4、行圆角 10，内外对不上；阴影有四五种写法，模型选择器没有自己的阴影，`/` 菜单还在用系统磨砂。
- **否决**：每个弹窗单独调参数；标签栏的 agent 标志改成单色（用户认为彩色没有问题）。
- **规则**：`docs/design/riffet-style.md` §6。

## 2026-11-14 · Web 组件收紧为墨色与浅底

- **决定**：Web 的按钮只用三种画法：`primary` 墨色实心，`secondary` 半透明墨色浅底（7%，悬停 11%）、不带描边和阴影，`ghost` / `quiet` 透明。`danger` 改为红色浅底加红字，`danger-ghost` 悬停时出现同色浅底。开关打开时轨道用 `primary`、滑钮用 `primary-fg`。按下时按钮缩放到 0.97。`accent` 变体只为插件 SDK 的 `ButtonProps` 保留，画法同 `primary`。
- **原因**：原来同一页里同时出现黑色主按钮、蓝色强调按钮、蓝色开关、白底描边的次级按钮和红底黑字的危险按钮，五种画法互不相干。`riffet-style.md` §4 本来就规定强调色只用于焦点环、选区和链接，Mac 端也已改用墨色开关，Web 没有跟上。参照的 Astryx（meta/astryx）也只用墨色、中性浅底和状态色三类。
- **否决**：次级按钮保留描边；危险按钮用实心红底；为插件删掉 `accent` 变体（会破坏 SDK 类型）。
- **补充**：输入框和快速新建的发送键也改为 `primary`；发送与停止靠图标区分（箭头 / 方块），禁用时为 8% 墨色浅底。

## 2026-11-14 · 选项多或切换所属对象时改用 Select

- **决定**：选择控件按「选的是值还是所属对象」与「选项是否固定」选用，规则见 `docs/design/system/patterns.md` §3。分段控件只用于 2–4 个固定的短选项；5 个以上或数量随数据变化时用 `Select`。切换下方内容所属的对象（如模型设置里配置哪个 Agent）用标题式选择：`Select` 新增 `appearance="heading"`，对象名作为下方各组的标题，点开是应用的菜单。模型设置的「CLI」分段控件已改为这种写法。
- **原因**：Agent 数量随插件增加，8 个时分段控件已经撑满设置行，再加就放不下；而且这一行切换的是下面整页配置的对象，放在「Agent」组里的一行，读起来像一项设置。
- **否决**：可横向滚动的分段控件（看不全选项）；折行的胶囊组（行高随选项数变化）；为此新建组件（`Select` 加一个外观参数即可）。

## 2026-11-14 · Web 手机上的菜单改为底部弹层

- **决定**：手机布局下，`DropdownMenuContent`（含 `Select` 与子菜单）默认从底部升起，铺满宽度，带遮罩；弹出层由调用处用 `mobileSheet` 选择。锚定在内容某一处的弹出层留在原位。规则见 `docs/design/system/patterns.md` §2.3。
- **原因**：锚定在触发点的菜单在 360 宽的屏幕上被挤到边缘，行宽和触控高度都不够；输入框、底部工具栏旁的菜单还会和键盘、安全区重叠。
- **否决**：逐个菜单改成 `Dialog`。四十多处调用会各写一遍，键盘导航和单选状态也要重做。


## 2026-11-14 · Web 新建会话的 Agent 并入模型菜单

- **决定**：桌面端新建会话的输入框只留一个模型按钮，显示 Agent 标志、模型名与推理档位。菜单分三栏：Agent、所选 Agent 的提供商、所选提供商的模型，各栏分别滚动；没有哪个 Agent 配了多个提供商时省掉中间一栏。打开时停在生效的那一项，选另一个 Agent 时停在它保存的默认提供商。选中模型时 Agent、提供商、模型一起保存。搜索在左栏所有已读到的列表里找，结果按 Agent 分组。其他 Agent 的模型列表先用缓存显示，预览时再读取。已开始的会话仍是原来的模型菜单。手机暂保留设置弹层里的 Agent 一行。
- **原因**：先在 Agent 菜单里选 Agent、再打开模型菜单选模型，常用的切换要点四下；模型菜单本来就有提供商一栏，往上扩一层就能一次选完。
- **否决**：菜单顶部放一排 Agent 图标页签：插件提供的 Agent 多半没有可辨认的标志，数量会增长，也放不下提供商这一层。把提供商缩进在 Agent 名下排成一栏：提供商一多，后面的 Agent 就被挤出可见范围。
- **规则**：`apps/web/src/app/session/ModelPicker.tsx`（`ModelProviderChoices.agent`）、`apps/web/src/app/ProjectHome.tsx`。

## 2026-11-14 · Mac 的行为跟平台，数值跟 Web

- **决定**：Mac 的设置在所有风格下都是独立窗口（⌘,）；弹窗用附着在窗口上的 sheet，由新组件 `SheetScaffold` 统一结构，宽度取 Web 的四档（420 / 448 / 768 / 1080）；右键菜单和设置表单里的选择保持系统控件，工作台控件弹出的菜单经 `popUpStyled`，在绘制风格下画成应用的浮层；提示气泡用 `.help`。页面骨架、内容列档位、文字角色、间距与按钮画法和 Web 取同样的值。不可逆确认里危险按钮不做默认按钮。
- **原因**：Mac 上同一种东西有多种写法：41 处 sheet 有约 15 种宽度，确认有 `.confirmationDialog`、`.alert`、`NSAlert` 三种写法，调用处直接写的字号约 1100 处。窗口、sheet、右键菜单和键盘约定是用户在 Mac 上已有的预期，照搬 Web 的大弹窗设置和自绘右键菜单会和系统打架。
- **否决**：Mac 设置也做成窗口内的大弹窗（配方的 `settings: .modal` 只对 Web 生效）；sheet 按内容自定宽度；所有菜单都画成应用的浮层，包括右键菜单。
- **规则**：`docs/design/system/macos.md`。

## 2026-11-14 · 设计规范按层分类，一章一页

- **决定**：设计规范从小到大分为基础、组件、模式、界面四层，每层只用前面的层，前后加总览与扩展与工程两组；动效、无障碍、文案不单独成层，基础给取值，各层写自己的部分。平台和风格是另两条轴，切换平台时分组不变。设计规范页改为左侧目录加正文、一次显示一章，地址 `/design/<组>/<章>`；文档按同样的组分文件。
- **原因**：原来 11 章平铺在一条长卷里，原则、取值、组件、布局、架构交替出现，说不清一条规则该放哪里；补齐模式和会话界面后章节会超过 30 个，长卷无法浏览。
- **否决**：按「整体与局部」或「视觉与动效」分；动效单独成一组；保留长卷，只在顶部加分组目录。
- **规则**：`docs/design/system/README.md` §1、`apps/web/src/app/design/catalog.tsx`。

## 2026-11-14 · 行内代码用次一档墨色

- **决定**：Riffet 风格的行内代码（`inlineCode: plain`）不加底色和内边距，用等宽字体、0.86em，颜色取 `fg-2`，比正文弱一档。
- **原因**：去掉底色以后只剩字体一处区别，降一档墨色让它与正文分开，又不像底色块那样打断段落。
- **否决**：保留 `bg-subtle` 底色块；与正文同色。
- **规则**：`docs/design/system/foundations.md` §2.4、`apps/web/src/styles/index.css` 的 `.md :not(pre) > code`。Mac 随 Riffet 风格迁移时跟上。

## 2026-11-14 · 悬浮玻璃输入框只用于移动端

- **决定**：2026-11-11 的悬浮玻璃输入框只用于 iOS 与 Android。Web 和 Mac 的输入框是实底卡片（`bg-elevated` 加 `shadow-composer`），停在转录列下方。
- **原因**：2026-11-11 的决定是为手机定的，那里屏幕矮，内容需要从输入框四周透出来；桌面端不需要这个效果。
- **否决**：在 Web 和 Mac 上补做磨砂和透底。
- **规则**：`docs/design/system/surfaces.md` §1.8。


## 2026-11-14 · 发送消息自动恢复会话

- **决定**：待恢复的会话可以直接发送。复用持久化消息与服务端恢复链路，消息先进入时间线，气泡下在实际恢复期间显示「恢复中」，随后继续发送。手动恢复仍可单独使用。
- **原因**：恢复是发送所需的准备步骤，要求先恢复再发送会打断输入；由服务端执行可沿用已有的幂等与发送边界，页面关闭后也不依赖客户端接续。
- **否决**：因终端离线禁用发送；客户端先调用恢复、完成后再提交消息；恢复时另开弹窗或常驻提示条。
- **规则**：`docs/design/system/surfaces.md` §1.3。

## 2026-11-15 · 移动端页面先定页面类型

- **决定**：手机上的二级页面、浮层和面板按页面类型组织：目录页、详情页、编辑页、设置分类页、选择面板、弹窗、面板，一页一件事，往下钻而不原地切换，第一屏给来意，搜索、添加和低频工具进顶栏，行里不放与标题同名的按钮。iPhone 重做后的「Agent 扩展」页是范例，Android 按同一结构重做。
- **原因**：手机一屏一列，组件规范对了，页面仍然难用。Android 的扩展管理在一页里用状态切换列表、详情和编辑器，第一屏是表单和工具；其他设置子页、Git 面板、会话详情面板和多处弹窗有同样的问题。
- **否决**：沿用桌面的页面结构，只把组件换成移动端样式。
- **规则**：`docs/design/system/mobile.md`。
