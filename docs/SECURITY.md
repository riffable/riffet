# 威胁模型

本文说明 Riffet 的信任边界、现有防护和已知缺口。它描述的是**当前实现**，不是目标态；未实现的能力在「已知缺口」里明确写出。

## 部署形态

- **本机模式（默认）**：服务只监听 `127.0.0.1`，浏览器与 macOS App 在同一台机器上访问。本机用户本来就能读项目文件、运行命令，服务不扩大其权限。
- **网络模式**：显式 `--host 0.0.0.0` 并启用鉴权。服务器可以是任意一台 Mac 或 Linux 机器；网页、Mac App 和手机在同一局域网、VPN 或 Tailscale 内通过配对获得设备令牌后访问。
- **反向代理 / Tailscale**：由用户自己提供 TLS 与网络隔离；Riffet 不终止 TLS。

## 资产与权限

| 资产 | 位置 | 拿到后的能力 |
| --- | --- | --- |
| 访问令牌（access token） | 数据目录 `access-token`，0600 | 本机浏览器的登录凭据；等同本机用户对 API 的权限 |
| 设备令牌 | 配对后签发，客户端存 Keychain / 平台安全存储 | 与访问令牌**当前完全相同**：读写会话、开终端、注册目录、改设置 |
| 模型源密钥 | 服务端设置文件，0600 | 以该账号调用模型网关 |
| 会话转写、文件、终端 | 数据目录与项目目录 | 读取项目内容、执行命令 |
| CLI 登录态 | 各 CLI 自己的配置 | 以本机用户身份调用对应 Agent |

**关键结论：配对一个新的设备，等于把本机用户的 Agent 权限交给那台设备。** 目前没有只读或“仅对话”的配对级别。

## 信任边界

1. **本机回环**：视为可信。免令牌模式只允许绑定回环地址。
2. **局域网**：不可信网络。请求必须带访问令牌或设备令牌；配对码一次性、短时有效；登录与配对接口有请求体上限与限流。
3. **已配对设备**：受信任的设备，但**不是**受限的设备。任何持有设备令牌的客户端可以调用全部 API，包括终端 WebSocket。
4. **浏览器页面**：同源脚本可信；跨站请求靠 CSRF 令牌、`Origin` 校验与 SameSite Cookie 阻止。
5. **可视化预览**：在 `sandbox allow-scripts` 的 opaque origin iframe 中运行，无 Riffet API、无凭据、`connect-src 'none'`。预览运行时自身只使用内联脚本；artifact 内容引用远程脚本/样式/字体时仍受 CSP 白名单（unpkg、jsDelivr 等）限制。
6. **CLI 子进程**：以本机用户身份运行，继承终端环境；Riffet 不额外提权，也不隔离它们的文件访问。
7. **项目外文件读取**：默认跟随监听地址——回环监听默认允许，局域网监听或经代理转发的请求默认关闭；开启后仍拒绝工作台数据目录、常见凭证目录（含 `.trae` 等 CLI 凭证位置）、CLI 认证文件与私钥。

## 现有防护

- 所有非公开 API 统一鉴权；鉴权按**路由匹配结果**判断，百分号编码路径与绝对形式请求目标不能绕过。
- 设备令牌可撤销；撤销后该设备的流连接关闭。
- 配对码一次性、短时有效；配对请求体上限 4 KB；限流表满时淘汰最早条目。
- 项目外文件读取跟随监听地址：回环默认开启，局域网/代理默认关闭；凭证与私钥路径始终拒绝。
- 设置文件、访问令牌、Cookie 密钥以 0600 写入；集成密钥只返回“是否已设置”。
- 可视化预览使用不透明源沙箱与严格 CSP，不注入 Riffet API。
- 分享产物在服务端生成，发布端只拿到产物与状态，不拿到本机文件路径。

## 已知缺口

1. **局域网没有 TLS**：令牌与会话内容在局域网内明文传输。同一网络上的攻击者可以嗅探令牌并冒充该用户。部署建议：只用 Tailscale、SSH 隧道或自带 TLS 的反向代理暴露服务；不要在不可信 Wi-Fi 上直接监听 `0.0.0.0`。这与 [MOBILE.md](MOBILE.md) 的既有取舍一致（不自建 TLS，也不做证书固定），F 计划中的自签名证书方案尚未实施。
2. **没有设备权限分级**：所有设备令牌权限相同。计划中的只读、可对话、可开终端与注册目录等级尚未实现。
3. **模型源密钥不在系统钥匙串**：目前只有 0600 文件；同用户下的其他进程、备份或误拷贝可以读取。计划中的 Keychain / libsecret 引用模型尚未实现，doctor 也不会提示。
4. **没有审计日志**：设备操作、终端命令与设置变更不记录到单独的安全审计流；`server.log` 只用于诊断。
5. **本机即最高权限**：能读数据目录或项目文件的进程不需要绕过 Riffet；服务不防御已在本机取得用户权限的攻击者。
6. **Agent 提示注入**：会话内容、仓库文件与工具输出都会进入 Agent 上下文。Riffet 不承诺阻止模型被内容诱导执行命令；审批模式（`allowlist`、审批卡片）是主要控制点。
7. **第三方 CLI 自身的安全边界**：Cursor、Codex、Claude Code、DSH、Droid、TRAE 的登录态、网络访问与命令执行由各自实现负责。

## 部署建议

- 默认只用回环监听；需要手机访问时优先 Tailscale 等加密覆盖网络。
- 只配对自己控制的设备；不再使用时在设置里撤销设备令牌。
- 不要把数据目录放进云盘同步；模型密钥与访问令牌都在里面。
- 在共享机器上使用独立系统账号运行 Riffet。
- 发现安全问题请按 [SECURITY.md](../SECURITY.md) 私下报告，不要在公开 issue 中贴令牌或会话内容。
