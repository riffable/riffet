# 个人助理查询与设置 Riffet 工作台的能力设计

助理主对话通过 Riffet MCP 查询工作台、修改已授权设置，并可把任务状态变化登记为委托。本文记录领域声明、调用方权限、各端生效位置和验收条件。[工具清单](ASSISTANT.md#6-工具)

常见问题对应的领域查询如下。先用 `capability_find` 查当前服务提供的参数，再使用 `capability_read`。

| 问题 | 能力 ID |
|---|---|
| 主人的昵称和时区、当前助理与模型 | `workbench.identity` |
| 今天有哪些问题、审批或交付等我处理 | `workbench.attention` |
| 在本实例上装了什么插件、这条会话为什么用不了 | `plugins.list`、`plugins.inspect` |
| 现在重启会中断什么 | `service.restart_impact` |
| Riffet Web 的内置主题、实例共享主题和插件配色 | `settings.web_themes` |
| 实例设置的操作、插件设置位置、共享主题版本、默认 Agent 与可用模型 | `settings.catalog`、`settings.plugin`、`settings.shared_themes`、`settings.agent_defaults` |

新增只读能力时，在所属领域用 `defineRead` 声明稳定 ID、说明、检索词、参数和处理函数，在应用组装处加入目录即可。新增项不会改变 MCP 顶层工具定义和 CLI 预热签名。一次可修改的实例设置须另行登记写操作。它不能通过 `capability_read` 调用。[声明接口](../apps/server/src/assistant-capability.ts) · [能力目录](../apps/server/src/riffet-mcp/capability-catalog.ts) · [领域接入示例](../apps/server/src/assistant/workbench-queries.ts)


## 1. 接入位置

个人助理通过现有 Riffet MCP 读取工作台。服务、主人资料、会话、任务和插件各自负责解释本领域的状态。助理按问题取数，系统提示只说明何时查、去哪里查。工作台的实时状态随查询返回。助理记忆继续保存用户的长期偏好。

看板工具在领域模块中登记可见角色、描述和处理函数。MCP 列举和调用都读取这份声明。`server_status` 保留已有结果字段，三个来源分别标记观测时间和查询失败。转接层声明 `listChanged: false`，预热按实际工具定义计算签名；服务升级后主对话的顶层工具有变化时，服务端安排空闲重启并恢复。[MCP 服务](../apps/server/src/riffet-mcp/service.ts) · [stdio 转接层](../apps/server/src/riffet-mcp/riffet-mcp.mjs) · [现有看板和查询实现](../apps/server/src/work-items/assistant.ts)

| 位置 | 职责 | 首次实现的落点 |
|---|---|---|
| 领域模块 | 定义状态含义、对象可见范围和可返回的字段，按需读取详情 | 插件模块给出启用和激活状态，任务模块给出待回答的问题 |
| 服务组装 | 传入查询所需的窄接口，组合跨领域查询 | 在现有 `app.ts` 组装处连接任务与会话。MCP 层和各领域模块维持现有导入方向 |
| Riffet MCP | 解析会话凭据，从能力声明生成目录，检查权限和参数后分发 | 收拢现有的清单与调用分支，沿用当前传输、错误结果和会话绑定 |
| 助理 Skill | 把用户的问题对应到查询，指导模型解释结果 | 更新已有的 Riffet 帮助、进展和简报 Skill。状态、版本和权限以本次查询为准 |

能力目录随服务进程加载。目录使用 TypeScript 声明和已有服务实例。跨模块组合遵循[服务端分层](guide/architecture.md)，插件自己的工具仍通过[插件扩展点](PLUGIN_ARCHITECTURE.md)提供。

## 2. 一项能力怎样声明和发布

一项声明包括稳定的能力 ID、面向用户问题的描述、输入 schema、结果类型、读取或操作、暴露方式、调用方可见条件和处理函数。核心使用「领域.用途」形式的 ID，如 `service.restart_impact`。已有顶层工具保留名字和参数。组装时检查 ID、顶层名字和保留前缀的冲突。新增查询从同一参数定义导出公开 schema 并执行校验，迁移旧工具时先用既有合法输入和错误结果核对兼容性。同一个查询即使有两个入口，也共用字段投影、权限判断和处理函数。声明贴近领域实现，跨模块接口由组装处传入。只供服务端使用的类型放在服务端。客户端实际需要共享时再提升到 contracts。

| 暴露方式 | 使用条件 | 例子 |
|---|---|---|
| 顶层读取工具 | 常见问题可由模型一步识别，或已有 CLI、Skill 依赖该名字 | `server_status`、`session_list`、`task_get` |
| 按需发现的读取能力 | 领域细节较多、使用频率低，单独占用顶层清单收益有限 | 重启影响、指定插件的激活情况 |
| 独立操作工具 | 会创建、修改、投递、启动或终止工作 | 已有的 `task_start` 沿用任务调度策略，跟进工具沿用任务绑定 |

按需发现启用后，MCP 只为这一类查询增加两个顶层工具。

| 工具 | 输入 | 输出和约束 |
|---|---|---|
| `capability_find` | 可选领域、关键词、游标 | 返回当前调用方可发现的能力 ID、描述和输入 schema。只填领域即可浏览，也可按用户常用词匹配。只查声明，分页返回 |
| `capability_read` | 能力 ID 和该能力的参数 | 仅分发到已注册的读取能力。先复核当前权限，再用目标能力的 schema 校验参数，最后由领域查询检查目标对象 |

例如，用户问“现在重启会打断什么”，助理在服务领域检索“重启”，再调用下面的查询。

```json
{"id":"service.restart_impact","arguments":{}}
```

处理函数读取现有 `restartability()`，可报告当前是否可重启、影响原因，以及调用方有权看到的会话引用。如果存在不可披露的阻塞项，保留服务级“暂不可重启”的判断，隐藏对象细节。查询仅取评估结果，不调用停收新任务或重启命令。[重启评估实现](../apps/server/src/native/dispatch.ts)

成功响应示例中，`turn` 表示重启会中断仍在执行的一轮。对象引用可用于后续会话查询。示例值仅用于说明契约。

```json
{
  "observedAt": "2026-11-18T03:00:00Z",
  "restartable": false,
  "draining": false,
  "blockers": [{"sessionId": "session-example", "reason": "turn"}]
}
```

发现工具属于 Riffet 自身的只读查询。插件继续通过声明工具组提供可执行能力。插件市场、管理路由、SQL 或任意 URL 均不能作为读取工具的分发目标。插件若只提供客户端界面，其已安装状态仍可查询，结果中可调用的工具组为空。

## 3. 首批查询与事实来源

| 用户问题 | 事实来源 | 建议返回 |
|---|---|---|
| “这台服务怎么样？” | 现有服务版本、运行时长、后端目录和会话状态计算 | 扩展 `server_status`，分别说明各部分的观测时间和可用性。耗时探测、进程详情和重启评估按需查询 |
| “我在这里叫什么？你当前用的是什么模型？” | `OwnerService`、助理时区设置、当前会话及可取得的运行时报告 | 主对话可按需读取昵称，未填写时返回空。时区标明用户设置或服务端回退。区分会话配置的模型和运行时已确认的模型。主人资料规范随实现补充这一访问范围。[个人资料](OWNER.md) |
| “哪个项目在等我？之前怎么决定的？” | 项目、会话、时间线和搜索 | 沿用项目与会话工具，摘要返回 ID、状态、关联任务和已知等待原因。正文按需取有界页。沿用各查询现有的可见范围。例如列表及详情排除归档会话，历史检索可返回带归档标记的命中。[助理读取范围](ASSISTANT.md#6-工具) |
| “今天要我处理什么？” | 看板任务的问题、交付、跟进结果，以及关联会话的等待状态 | 返回待回答、待验收、跟进受阻和独立会话待处理项，附任务或会话引用。沿用 `WorkItem`、会话与具体问题的关联。[任务契约](../packages/contracts/src/work-items.ts) |
| “浏览器插件装了吗？为什么这条会话用不了？” | 插件注册表、当前会话选中的工具组、MCP 调用时的授权和已有的 CLI 运行时报告 | 分别报告安装、启用、激活、是否提供工具组、会话是否选中、服务端当前是否允许、当前 CLI 是否已加载。返回宿主能够确认的原因。清单读取注册表已知状态，详细探测由单项查询承担。[插件注册表](../apps/server/src/plugins/registry.ts) |

例如，某个插件已激活，声明了浏览器工具组，当前会话尚未选中该组。助理据此回答“浏览器插件已启用。这条会话尚未授权浏览器工具”，并指出已有授权入口。如果用户刚为正在运行的会话添加授权，服务端会按新授权检查调用，而旧 CLI 仍需下次启动才会列出工具。能取得实际启动清单时据此判断，否则将加载状态标为未知。已列出的工具若在执行时遇到依赖故障，则报告该次错误。插件的启停、会话授权和单次执行结果有各自的事实来源。CLI 自己加载的 Skill、外部 MCP 和助理能力包继续由[扩展目录](EXTENSIONS.md)和[助理能力包](ASSISTANT.md)描述。

待处理事项按具体事件合并。执行者用 `task_ask` 提问后，即使 CLI 已空闲，未答问题仍应入列。同一条会话如果另有一项权限审批，问题和审批要分别呈现。任务问题记录与会话等待指向同一问题时返回一项，同时保留任务和会话引用。同一任务下的两个独立问题分别返回。关联依据不足时保留两项，避免模型根据相近的标题合并。项目构建进程、定时自动化、助理委托保留各自的生命周期。查询结果可附上相关任务或会话的引用。

## 4. 身份与数据边界

服务端从会话凭据解析 session，再读取项目的主对话 ID、会话 origin、运行记录和目标关联。模型提供的角色名、用户昵称、设备名和聊天正文都不能授予权限。下表规定新增工作台查询的范围。迁移现有工具时，先保持已有调用行为，按作业核对依赖后再调整范围。

| 调用方 | 新增查询的默认范围 |
|---|---|
| 助理主对话 | 本实例允许助理读取的工作台摘要和对象，可按需查主人昵称。定时唤醒也在主对话中执行。需要用户确认的操作须核对本次操作对应的确认记录，单凭会话身份无法确认用户意图 |
| 任务跟进运行 | 服务端绑定的任务、关联会话及跟进所需的交付证据 |
| 委托、记忆整理运行 | 按作业分别授予完成该委托或整理所需的读取范围。缺少可信目标绑定时，默认关闭相应的新查询 |
| 普通项目会话、任务执行会话 | 沿用本会话已有能力。工作台全局查询和拥有者资料只对获准角色开放 |
| 尚未绑定的预热进程 | 只能列拟启动会话的工具定义。绑定前的所有调用均拒绝，包括发现和读取 |

`tools/list`、能力发现和实际调用共用可见条件。调用时从服务端重新读取授权，并在领域层检查目标 ID。列表、搜索、计数先应用各自的可见范围，再排序、截断和分页。直接猜测不可见能力或对象的 ID，返回与未知 ID 相同的对外结果。插件停用、设备撤销或会话归档后，即使 CLI 还持有旧工具定义，服务端仍按当前状态拒绝调用。[凭据与调用入口](../apps/server/src/riffet-mcp/service.ts) · [后台运行](../apps/server/src/assistant/runs.ts)

结果字段按问题选取。插件管理响应里的配置值、开发路径，设备凭据以及诊断中的进程参数不进入工作台摘要。会话消息、任务描述和插件自由文本标为外部内容，模型可以引用，权限判断只读服务端记录。

## 5. 结果、资源预算与兼容

新增查询区分三种结果。成功且列表为空表示确实没有匹配项。某个来源失败时，组合查询保留已取到的数据，并给失败部分标明不可用或未知。整个查询无法执行时，走现有 MCP 错误结果，返回可区分的参数、权限或暂时不可用错误。复用历史采样时带上采样时间，读缓存的时间不能冒充采样时间。

列表提供稳定对象 ID 和分页游标，详情对单页字节数和文本长度设上限。`session_read` 先读限时且有字节预算的后端转录，再回退到有界的 journal 或消息索引查询。插件列表只读宿主快照，避免一次普通概览触发所有插件的状态回调。预算优先取已有值，需要增加预算时在[共享预算](../packages/contracts/src/budgets.ts)定义，并按[性能规范](guide/performance.md)验证。

已发布的工具名、必填参数和既有结果字段语义构成兼容契约。扩展 `server_status` 时保留原字段与类型，分项可用性作为可选字段追加。破坏性变更提供新名字或新 ID，旧入口在兼容期转调同一实现。目录顺序确定，只有工具定义影响预热签名。状态、观测时间和运行结果放在调用响应中。变更顶层清单时，同步核对 `draftOf`、工具签名和各后端的预热匹配。签名不同走冷启动。

已持有发现入口的长期 CLI 可在下一次查询中看到服务端新增的低频能力。首次发布发现入口时，已启动的旧 CLI 可能仍只有旧清单，应通过已有空闲重启与恢复机制在下次启动时获得入口。升级和回滚均需验证既有会话可以继续使用旧工具。Skill 的帮助文字要兼容过渡期的两种清单。

## 6. 已实现的阶段和验收

| 阶段 | 已接入的功能 | 验收条件 |
|---|---|---|
| 1. 归一现有声明 | `server_status` 和限定跟进目标的 `task_continue` 在领域声明上直接绑定处理函数。集中生成可见工具及调用分发，保持公开协议 | 同一角色迁移前后的工具名、输入和关键结果兼容，跟进运行只能向绑定的任务投递。普通会话直接调用受限工具时收到拒绝结果。预热只列工具，绑定后按真实会话调用 |
| 2. 补工作台读取 | 在同一套声明上实现主人及当前会话查询、插件清单及会话可用原因，改善服务状态的分项错误。更新相关 Skill 和个人资料约定 | 用 Claude Code、Codex 的助理主对话分别核对空昵称、已启用但未授权的浏览器工具、授权后等待旧 CLI 重载、撤销后直调失败，以及单个状态来源不可用 |
| 3. 发现与组合查询 | 低频读取通过 `capability_find` 和 `capability_read` 暴露。以重启影响验证按需发现，以待处理事项验证领域组合 | 在已加载发现入口的会话中新增一项读取能力，顶层 schema 和预热签名保持一致。直调读取入口仍受角色及目标限制。同一问题只报告一次，独立问题分别保留 |
| 4. 按用户委托订阅变化 | 将已能正确查询的状态接入已有委托和后台运行。由服务端检测目标状态变化，以委托 ID 和任务事件 ID 去重，将消费游标和运行入队写入同一事务 | 用户委托“这个任务待验收时提醒我”，任务状态已提交、运行尚未入队时重启，恢复后重放该事件。同一次变化只生成一条运行和一条工作台提醒。设备推送沿用现有重试机制，发送成功后、确认写入前重启可能再次推送。[后台运行与恢复](ASSISTANT.md#7-后台运行) |

功能 PR 应说明用户会怎样向助理询问这项功能，引用已覆盖的查询，或提出新增能力及其可见范围。无需助理参与的功能可简要说明适用范围。维护者据此决定是否进入能力目录。契约检查负责发现重复 ID、名称冲突、既有必填项和字段的不兼容变更，并验证通用读取入口只能分发只读能力。能力描述和 Skill 由声明及实际用户问题校对。

首期记录迁移前后各角色的顶层工具数、序列化 schema 字节数，以及代表问题能否找到正确工具。后续低频能力走发现入口时，应能验证顶层清单开销保持稳定。发现失败的案例先检查描述、领域和同义词。高频问题确实需要每次多走一步时，再将它提升为顶层读取工具。协议与权限用服务端核心测试验证，模型选择用已有[Claude Code 助理探针](../scripts/probe-assistant-e2e.ts)及[Codex 助理探针](../scripts/probe-codex-assistant.ts)验证。

[工作台探针](../scripts/probe-assistant-workbench.ts)使用临时实例分别向 Claude Code 和 Codex 提问“我启用了 Riffet 的浏览器插件，为什么你现在用不了？”和“今天有什么等我处理？”。两种 CLI 均通过 `capability_find` 找到能力并调用 `capability_read`，读到已启用的浏览器插件在该会话未授权、服务端未提供工具组且 CLI 加载状态未知，并找到了空闲任务仍待回答的问题。探针也输出各角色当次工具清单的数量和序列化字节数。

## 7. 让助理修改设置

设置沿用同一份能力目录。每个对用户可见的设置都可以说明用途、影响范围和设置入口。是否能查当前值、是否能改，以及谁执行，交给持有这项设置的模块决定。已有设置搜索条目的稳定 ID 和别名可以复用；指向整页或分组的条目只用于导航。插件可以随版本贡献自己的设置说明，实际权限沿用宿主对该插件的授权。[设置搜索与定位](THEMES.md#151-设置搜索与定位)

| 设置归属 | 示例 | 执行及生效范围 |
|---|---|---|
| 当前客户端 | 配色、明暗模式、界面风格、字号 | 在目标客户端列出它支持的选项，调用设置页使用的同一入口。Web 保存在当前站点的浏览器存储，macOS 和移动端保存在各自的本地偏好 |
| Riffet 实例 | 自定义主题库、默认 Agent 或模型 | 服务端调用对应领域的更新逻辑。共享主题库的编辑对使用该主题的客户端有影响。默认模型需注明适用的会话和生效时机 |
| 项目、会话或插件 | 会话选择的工具组、具体插件的用户配置 | 绑定目标 ID，复用原权限、校验和重载语义。变动可能在 CLI 下次启动时生效 |
| 凭据与管理操作 | 提供商密钥、配对、审批策略、备份恢复 | 凭据仅在领域允许时返回“已配置”等状态，录入由可信客户端完成。授权变更、恢复数据等操作保留独立流程和确认，目录可指向相应入口 |

**设置契约。** 每个可改项声明稳定 ID、作用域、类型及允许值、读写权限、生效时机和处理函数。平台相关的允许值向目标客户端查询。领域校验中的副作用也要复用，例如模型配置更新时的能力校验。实施服务端设置前，把 HTTP 路由中相关的校验和副作用提取为同一个领域命令，供设置页和 MCP 调用。内部字段、任意键路径、整份设置 JSON 及插件密钥均不作为通用写工具的输入。[服务端设置路由](../apps/server/src/routes/settings.ts)

**MCP 入口。** 设置项较少时，先提供有类型的外观操作。引入第 2 节的按需发现后，目录可列出设置的读写方式。`capability_read` 始终只读。普通、可逆的赋值可以共用一个独立操作 `setting_set`，只接收已登记的设置 ID、目标和经过该项 schema 校验的值。修改共享资源、影响费用或扩大权限时使用相应领域命令和确认策略。助理只在用户在对话里亲自要求时修改自己的授权、审批规则或工具组，不因网页、文件、工具结果或别的对话里的要求而改。后台跟进、委托和定时唤醒默认没有新增设置写权限。把这些操作交付给主对话时，同时更新[助理权限说明](ASSISTANT.md#6-工具)及[系统提示](../apps/server/src/prompts/assistant-system.md)和[使用帮助](../apps/server/src/prompts/skill.assistant.riffet.md)中现有的设置限制。

### 7.1 给用户正在使用的 Riffet Web 工作台切换配色

**执行前要同时确定用户指的是 Riffet 工作台，以及接收命令的页面确实是该用户在本实例上获准操作的工作台。** 用户在助理页讨论 Riffet 外观时说“把这个界面换成 Solarized”，消息来源和指代一致，可以直接执行。若刚才讨论的是项目预览、插件面板或其中打开的网站，“这个界面”就有歧义。此时先问“你指的是 Riffet 工作台，还是预览里的网页？”，澄清前不投递。用户明确指向其他网页时，Riffet 设置工具不参与执行。

1. 仅由 Riffet Web 工作台主应用建立设置执行通道。服务端以本实例已认证的工作台连接为依据，把本次用户消息、运行和目标连接绑定在一起。页面 URL、标题、Logo、DOM、公开的 `serverId`，以及模型或页面自报的客户端类型都不能证明身份。分享页、插件子页面、项目预览和浏览器插件中的标签页均不注册为执行端。目标缺失、跨实例或绑定失效时返回目标不可用，不改投当前标签页或最近在线的设备。
2. 查询目标端的配色目录，解析 Solarized 对应的 ID。配色、明暗模式和界面风格是不同设置。用户只指定配色，就只提交配色。目标明确且本次用户请求已授权这种可逆修改时，直接执行。
3. 服务端投递带调用 ID 和截止时间的设置命令。配对设备复用现有的能力申报、投递与回执；Web 需要接入能定位请求来源、返回执行回执的客户端通道。各端分别声明支持的操作。Web 适配器调用现有 `setThemeId`，读回保存的值后报告结果。目标离线时提示无法应用；已投递却未收到回执时报告结果未知。到期命令不在下次上线时补做。[主题契约](THEMES.md#41-分工) · [Web 主题入口](../apps/web/src/lib/theme.ts) · [设备调用契约](../packages/contracts/src/devices.ts)
4. 服务端核对回执的连接和调用 ID。成功回执包含目标、保存值和生效时机。助理可回答“这个浏览器里的 Riffet 工作台已切换到 Solarized”。同一浏览器配置中共享该站点存储的工作台标签页会读到这一偏好。若用户接着说“改回去”，只有当前值仍是上次操作写入的值时才恢复前值，避免覆盖用户随后在设置页作的修改。

“把共享主题的强调色调暗”走另一条路径。领域命令只接收主题 ID 和目标颜色变更，服务端读取当前库、合成更新并复用主题库校验与 `expectedRevision`。返回 `THEME_CONFLICT` 时重新读取并告知冲突，不能用旧主题库覆盖并发编辑。发布共享主题和将它选为本机配色是两个可独立成功的操作，用户同时要求时分别报告结果。[主题库并发契约](THEMES.md#43-并发与故障)

Web 实现提供 `workbench_appearance_get` 和 `workbench_appearance_set`。Web 端将页面凭据保存在内存中，在首次从会话发送消息时建立连接。服务端在接受新回合时将当前 run 绑定到发起连接；工具执行时由服务端直接校验主对话权限、当前活跃原生回合以及该 run 对应的工作台连接绑定，不再经由上下文向模型注入一次性 `sourceTurn` 令牌。工作台断开、运行结束、steer 插话或服务重启后绑定失效。在页面手动重试时，浏览器使用原消息 ID 并验证发起重试的工作台。服务端首次接收才绑定；已接受的消息只返回原回执。后台恢复只查询状态。服务端在 SQLite 中只保存有期限的一次性页面凭据摘要。同一标签页可在服务重启后重新握手，新消息使用新连接。Web 离线缓存仅保存通用页面。有网时 Service Worker 使用浏览器发起的导航预加载，使服务端能识别顶层工作台并签发凭据。

使用条件为通过 HTTPS 或本机回环地址打开顶层工作台，浏览器需要提供顶层导航的 Fetch Metadata。旧页面缺少凭据或凭据失效时，刷新目标工作台并重新发送请求。配色选择覆盖内置主题及本机可用的共享自定义主题。使用插件配色时查询另带实际显示的配色 ID。同一 Web 连接可撤销最近的可安全恢复修改。原生客户端使用经配对的设备通道，实例级共享主题编辑使用独立命令。

只需列出 Riffet Web 可选主题时，助理用 `settings.web_themes` 读取内置主题、该实例的共享自定义主题，以及已启用插件提供的可用配色。查看某个标签页的当前选择或修改该页时，需要它在本轮提供工作台绑定。

### 7.2 交付与验收

Web 工作台还返回自身设置页及插件设置入口。Android、iOS 和 macOS 使用各自支持的本地选项。原生写入要求当前实例已配对、目标设备获当前会话授权、设备在线并在本机明确允许控制。iOS 仅提供该端拥有的配色与明暗选项。每新增一项，核对其存储位置、受影响对象、能否回读，以及运行中还是下次启动生效。

- 在 Web 切换配色后刷新，选择仍在，原明暗模式和另一台设备的选择保持原值。
- 在 Riffet 里打开项目预览后说“改一下这个网页的样式”，指代未明确前，工作台设置的写入次数为零。用户明确指向工作台后，只有已绑定的工作台执行端收到命令。
- 用带 Riffet 标题的普通网页、同实例分享页、插件子页面或另一实例的已登录工作台作目标，服务端均拒绝投递。原工作台已断开时，其他连接也不能代它执行或确认成功。
- 从多个端共用的助理对话发起操作，只有本次已授权的目标端执行。旧版客户端明确返回不支持，授权撤销后直调遭拒。
- 同一调用重试时，目标端按调用 ID 复用执行结果。掉线、超时和取消均有明确状态，不能把服务端成功投递当成设备已经应用。
- 两端并发编辑同一个共享主题时，后提交的旧 revision 得到冲突。查询密钥配置状态及记录变更时，响应和审计只含允许披露的字段。

### 7.3 实例默认 Agent、提供商与模型

`settings.agent_defaults` 读取已保存的默认值、Agent 的实例回退选择和可用提供商、模型。提供商和模型可分别分页。同一提供商的模型列表复用设置页的目录。结果只保留公开名称、ID 和选项状态。实例默认值影响各客户端随后创建且沿用默认值的会话。没有自己的默认设置的任务也可能继承它。旧客户端可回退到支持的 Agent。已有会话和个人助理继续使用各自的选择。

`agent_defaults_set` 先校验提案，返回变更前后、跨客户端生效范围和可能的账号、费用及配额变化。服务端将该变更与当前主对话和回合、设置版本以及一次性确认文本绑定。用户在 5 分钟内从已验证的 Web 工作台或已配对 Riffet 客户端发送下一条独立消息，内容与确认文本匹配才可应用。服务端从已接收的消息取正文，并在落盘前复核回合和设置。中间有其他回合、提案过期、服务重启或设置变动时重新生成提案。审批、模式和密钥由原有设置入口管理。[领域实现](../apps/server/src/settings/assistant-agent-defaults.ts)

[协议联调测试](../apps/server/src/routes/workbench-appearance-integration.test.ts)在临时实例经 Web 消息和 MCP 验证两步确认，覆盖普通会话直调、伪造确认、未绑定消息、并发设置修改、过期以及重复确认。保存后的模型和默认 Agent 可回读，原审批配置仍保留。
