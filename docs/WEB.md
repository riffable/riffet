### 2026-11-09 会话 PDF 导出

范围为 Web 与 macOS，会话菜单的「导出为 PDF…」复用范围、外观和只读预览，默认浅色。内容沿用分享快照的完整提问、最终回答与关联资源，不经过图片分享的正文截断。Server 不生成 PDF、不启动浏览器；Web 调用当前浏览器打印，macOS 使用系统 WKWebView 的 `NSPrintOperation`，用户在打印窗口保存 PDF。

Web 的分享预览和 PDF 预览都在预览上方右侧提供「导出为 PDF」。分享预览加载时，同步用当前冻结草稿预加载独立的打印 iframe；打印资源就绪后启用导出按钮。点击导出只复核资源并打开打印窗口，不替换或重新加载可见预览、不重新读取会话、不刷新发布账号状态。打印准备失败可单独重试，不打断分享预览。离屏 iframe 的资源就绪等待保留任务回退，避免浏览器暂停动画帧后一直等待。空账号不占状态行；本地预览不显示未启用发布集成的提示。导出按钮随预览工具栏保持可见，正文在预览内滚动。

浏览器可能默认在 PDF 页眉页脚添加日期、标题和当前工作台网址。`window.print()` 无参数，不能设置浏览器的页眉页脚开关，CSS margin boxes 也不能覆盖浏览器默认内容（[Chrome 官方说明](https://developer.chrome.com/blog/print-margins#things_to_note_when_using_page_margins)）。因此保留每页 16mm 正文边距，在导出按钮旁明确提示：在打印窗口选择「保存为 PDF」，并关闭「页眉和页脚」。

`POST /api/sessions/:id/share/print` 复用 `ShareDraftRequest`、`ShareDraftEvent` 与 `ShareDraft`，仍受现有鉴权、会话锁、内容大小和文件读取边界约束。该入口跳过发布插件与账号检查，未确认的远端发布结果不阻止本地导出；草稿持久化 `localOnly` 标记，发布接口在调用插件前拒绝它。预览使用同一鉴权资源路由与过期清理，不增加导出任务表或远端发布记录。

阅读器通过 `?print=1` 进入自然文档流；`PrintRenderingContext` 让离屏图表和高亮立即渲染，图片使用完整比例而非裁剪缩略图。`data-print-pending` 标记尚未完成的渲染，`riffetPreparePrint()` 等待这些标记消失、字体加载和图片解码，再发送带 `capturedAt` 的 `riffet-share-ready`。40 秒总时限、卸载取消和显式失败占位防止无限等待或静默缺图；父视图只接受当前预览来源的消息，打印前再次确认就绪。

打印样式集中在 `apps/web/src/share/print.css`：默认 A4、16mm 边距；正文和长代码自然跨页、代码折行、标题尽量与后文同页、表格恢复 table 布局并重复表头、图片按单页高度等比限高。不能换行的宽公式在资源就绪和打印前按正文可用宽度缩小。整条回答不禁止跨页，不按字符或位图高度裁切。macOS 追加 `nativePrint=1`，CSS 页尺寸和边距使用 `auto`，由 `NSPrintInfo` 单独提供；固定 CSS 边距会覆盖 AppKit 参数，因此不能以零边距代替 `auto`。浏览器排版差异由各自系统打印预览体现，不承诺跨端页数相同。

### 2026-11-02 布局稳定性

**判断**：交互时的跳动不是单点缺陷，而是几何变化没有归属：

- 同一个布局决定散在多个组件里，其中一处以内容为输入。
- 加载时清空上次的值。
- 异步内容不占位。
- 滚动协调器的契约没有覆盖读者点击引起的变化。

修法是给每类几何变化指定唯一负责方，并规定每类变化的处理方式。以下位置均来自代码阅读，未在浏览器中复现。

状态：已全部实现，待确认的决策均按推荐项落地。实现与方案的出入见本节末尾的「实现记录」。

- 已做：类型检查、web 测试、构建；转录回放跑过一段空闲会话的录制。
- 未做：浏览器现场验收。

**原则**：每一次几何变化必须属于下面三类之一，不属于任何一类即为缺陷。

| 类 | 判定 | 处理 |
| --- | --- | --- |
| 消除 | 不携带信息的变化：加载闪现、媒体从 0 撑开、源码先于预览、间距随状态切换、滚动条占位、动画中途跨断点 | 预留尺寸或保留上次的值，变化不发生 |
| 过渡 | 读者需要知道的变化：输入框上方的队列、计划与提示，侧栏与面板，终端抽屉，过程块折叠，消息状态行 | 以动画呈现，规则见下 |
| 锚定 | 发生在读者视线之外的变化：视口上方的行变高、历史前插、估高被实测替换 | 不做动画，由滚动协调器补偿，视口里的内容不动 |

过渡规则：

- 纵向进出一律用 `Collapse`（`grid-template-rows` 加透明度，`--duration-base`），组件里不另写高度动画。
- 含正文的盒子不做 width 动画，因为每一帧都会重新换行。横向结构变化先一次性预留宽度，面板本身用 transform 滑入。右侧面板已经这样做（`WorkbenchPanels.tsx:69-74`），左侧栏 ⌘B 与会话侧栏照此改。
- 同一位置的状态替换，在固定尺寸的槽位里交叉淡化，槽位尺寸不变。输入框的发送/停止位已经是这样。
- 尺寸档位在变化开始时按目标状态算一次，动画过程中不跨断点。
- 消息区里的过渡与滚动协调器协作：
  - 跟随时，每帧保持底部；
  - 阅读时，每帧按锚点补偿；
  - 读者点击引起的展开或折叠，以被点击的元素为锚点。
- 减弱动效沿用现有规则：高度与位移直接到终态，保留 100ms 透明度。

**负责方**

1. **布局：`SessionScaffold` 与 `useSessionLayout()`**
   - `useSessionLayout()` 是唯一的布局决策点，以 context 下发。
     - 输入只有两类：会话容器宽度，以及读者的显式状态（左侧栏收起的目标值、面板开关、子 Agent 页）。不接受内容作为输入。
     - 输出 `{ aside: 'column' | 'none', nav: 'outline' | 'rail', plan: 'aside' | 'dock' }`。
   - `SessionScaffold` 用固定轨道的 grid（`minmax(0,1fr) 248px`）排布 header、消息区、输入框附属区、输入框、侧栏和浮层。叶子组件只填槽位，不改轨道。
   - 输入框附属区（队列、计划、提示条、目录错误）是一个槽位，内容进出由 scaffold 用 `Collapse` 过渡。
   - `<ContentColumn>` 让消息区与输入框共用宽度上限、内边距和滚动条预留，取代现在 6 处各自声明的 `data-content-column`。消息区是 `sm:px-4`，输入框是 `sm:px-5`，且只有消息区有 `scrollbar-gutter`。
   - 删除 `SESSION_ASIDE_SHOWS/HIDES` 和 `SessionAside` 的 `:has()` 规则。`TurnRail`、`TurnOutline`、`ComposerDock` 改为读取 `layout.nav` 与 `layout.plan`。
   - `NativeSession.tsx`（963 行）拆成两部分：数据与动作的 hook，以及 scaffold 组合。快速对话与子 Agent 页复用同一个 scaffold。
2. **状态：加载时保留上次的值**
   - key 变化时，同一会话沿用上一份结果，直到新结果到达。`loading` 只在完全没有可用值时成立，并在控件内部呈现（例如模型选择器内），不插入新行。
   - 模型目录 key 带有 `nativeSessionId`（`Workbench.tsx:126`），首条消息后原生会话 ID 写回，key 随之改变。当前帧 `nativeCatalog` 变成 `[]`（`:128`），输入框上方于是插入"正在加载模型目录…"（`NativeSession.tsx:869`）。刷新可以保留，但选择逻辑要按上面的规则沿用旧结果。
   - header 里异步出现的按钮（收藏、子 Agent、后台任务）放在标题右侧的操作区内淡入，不改变标题的截断位置。
   - **数据就绪**（2026-11-05 补）：能同步读到的值（本机副本、模块缓存、store），在 key 变化的那次 render 里就要用上，不能等 effect 跑完再写入，因为 effect 在这一帧画完之后才执行。跨项目或跨会话切换时，模型目录在 render 里用 `catalogStore.peek` / `peekProfiles` 读取（`Workbench.tsx`）。转录的内存副本在 layout effect 里同步发布（`useSessionSync.ts`）。按 key 重置的状态在 render 里调整，不用 effect 同步。
   - spinner 只在完全没有可显示的内容、并且等待超过 `WAIT_GRACE_MS` 时出现（`useLingering`）。
   - **浮层收起**：`DropdownMenuContent`、`PopoverContent`、`DialogContent` 在关闭动画中保留打开时最后一次的内容（`useClosingSnapshot`，`lib/overlay-navigation.ts`）。选择操作常常会改写列表本身：排序变化、勾选移动、某一行消失、文案翻转。淡出中的浮层保持读者选择时看到的样子，业务组件不必各自处理。
   - 开发环境的 `installFlashMonitor`（`lib/layout-shift-monitor.ts`）在控制台报告存在不到 500ms 的 spinner 和 disabled 状态。这类闪动不产生位移，layout-shift 观测不到。
3. **滚动：补充 `useTranscriptScroll` 的契约**（与上文 2026-10-27 的表格合并）

   | 变化 | following | reading |
   | --- | --- | --- |
   | 读者点击展开或折叠（过程块、工具行、思考） | 折叠，或在进行中的最后一轮里展开：每帧保持底部；其余展开以被点击元素为锚点，结束时仍在底部才继续跟随 | 以被点击元素为锚点 |
   | 回合结束时过程块自动折叠 | 动画折叠，每帧保持底部 | 动画折叠，按锚点补偿 |
   | 列宽变化 | 已测行高按宽度比例换算成估高，不清回 88px | 同左 |

   - 列宽变化这一条替代 2026-10-27"保留宽度变化时的行高失效规则"。
   - 阅读锚点下沉到块级（Markdown 段落、图片、围栏），解决长消息内部变高时正在读的文字移动，替代上文"若实际复现表明需要块级锚点，再扩展"。
   - 未窗口化列表的 `content-visibility` 统一使用 88px 估高（`TranscriptView.tsx:269`），先用回放测量首次上翻的抖动，再决定是否改用行高索引。
4. **媒体：预留尺寸**
   - 已知像素尺寸的图片一律写 `width/height`。`ToolImage` 已经算出宽高，但没有传给 `ZoomableImage`（`Timeline.tsx:502-506`、`ImageViewer.tsx:27`）。
   - 尺寸未知的图片（Markdown 图片、`ImageBlock`）先用固定比例的占位框，加载后在框内淡入，再过渡到真实高度。
   - 用户附件按 id 缓存 `attachmentMetadata` 给出的尺寸，窗口化重挂载时不再重复从 240×240 缩放（`MessageAttachments.tsx:67-109`）。
   - 预览围栏：渲染过的块，`useInView` 的初值为 true；Mermaid 缓存命中时直接出图；预览图带内在尺寸（`Markdown.tsx:145,219-224`、`ContentFence.tsx:13-26`）。
   - KaTeX chunk 到达前，用与渲染后同字号的占位，不用代码块外观；会话里含公式时提前加载 chunk。
   - 字体：为 Inter 与 JetBrains Mono 的回退字体加度量覆盖（`size-adjust` 等），让字体替换不改变行高和换行。效果未测量。

**检测与验收**

- 开发模式挂 `PerformanceObserver('layout-shift')`，在控制台报告每次偏移的来源节点。偏移发生时若 `document.getAnimations()` 中没有运行中的动画，标为"未过渡"。
- 每一期的现场验收：下列场景不出现"未过渡"的偏移。
  - 新会话连发两条
  - 回合结束
  - ⌘B
  - 开关面板
  - 打开子 Agent 页
  - 在底部展开过程块
  - 切换会话
  - 打开含图片、公式、图表的历史会话
- 扩展转录回放（`pnpm replay:transcript`），让它覆盖 scaffold 与输入框，并把上述判定接进逐帧报告。它仍然是按需运行的审计工具，不进测试套件。
- 类型检查、Web 构建，以及受影响的现有测试。不新增 UI 展示测试。

### 2026-10-27 打开会话后跳离底部

**原因**：缓存保存整个窗口，长会话的缓存会长到窗口预算（8MB）。打开时恢复满窗口后，空闲预取一页更早记录，`LaneWindow` 按请求方向从底部让出，删掉正在运行的回合末尾并置 `hasAfter`；`reconcile` 随之把 `following` 置为 false，且不再恢复。

**修改**：

- 窗口超预算时让出离读者较远的一端（`readerAtEnd`，由 `TranscriptView` 在每次位置变化、请求分页前告知）。读者在底部时，放不下的更早一页丢弃并返回 `none`，不算失败；读者在上方时，流式新行超预算也从底部让出。子 Agent 视图没有向下分页，保持末尾。
- 缓存只存窗口尾部 500 行 / 1MB。
- `following` 只由读者输入和显式命令改变：去掉 `hasMoreLater` 置 false 的规则；跟随中没有输入事件的滚动回到底部，焦点移动（键盘、读屏）记为读者输入。
- 回合的第一个过程块以服务端回合 `turn` 为键，翻入同一回合更早的行不再整块重挂载。

未在浏览器中复现验证；`sync.test.ts` 覆盖满窗口在底部预取、在顶部翻页与尾部缓存。

### 2026-10-27 输入框与滚动位置

输入框调整与滚动协调器均已实现。截图中的跳动尚未通过浏览器事件轨迹复现；下面记录实现边界，不代表真实输入法、触摸惯性或浏览器滚动已经通过现场验收。

**输入框实现**：

- 工具栏右侧只有一个固定尺寸的操作位。任务运行且草稿为空时显示停止，有草稿时显示发送；删除编辑时并列的小停止按钮和「立即发送」，删除草稿打断并发送的前端分支。发送沿用会话已有的排队／引导策略。

**滚动协调实现**：

现有纵向布局和独立消息滚动区继续使用。`TranscriptView` 中的跟底、读锚恢复、搜索定位、前插历史补偿和虚拟行定位收敛到会话实例内的 `useTranscriptScroll.ts`；`readingAnchor.ts` 只捕获锚点、计算目标位置，`virtualRows.ts` 继续负责行高索引和挂载窗口。消息区的所有 `scrollTop`／`scrollTo` 写入由协调器执行。

持久状态只有 `following` 与 `reading`。`following` 在最终布局变化后保持底部；`reading` 保存消息 key 和相对消息视口的偏移。`atBottom` 单独表示尾部是否可见，不能直接代替跟随意图。`hasMoreLater` 为真时，当前窗口底部不代表会话尾部。

搜索、轮次导航和确认卡片跳转使用可取消的临时定位操作，记录目标、会话代次及完成条件。定位期间由目标控制位置，完成后记录新的读锚；新定位、用户滚动和会话切换取消旧定位。底部跟随和布局补偿即时执行，轮次／确认卡片导航沿用当前动效偏好；未挂载目标及远距离跳转即时定位后按真实位置收敛。

| 变化 | following | reading |
| --- | --- | --- |
| 输入但输入区最终高度不变 | 不移动 | 不移动 |
| 输入区最终高度改变 | 保持底部 | 保持阅读锚点 |
| 新消息、流式更新、异步内容撑高 | 保持底部 | 保持阅读锚点 |
| 历史前插、估高被实测替换、虚拟窗口更新 | 保持底部 | 按同一锚点补偿 |
| 读者发送消息 | 保持底部 | 视口还在最新一轮（其首行不在视口之下）时转为跟随；更早的轮次或 `hasMoreLater` 时不动 |

已知同步变更在 DOM 提交前使用最近稳定锚点，提交后统一补偿；历史前插在数据实际提交前取锚，不在网络请求开始时取锚。消息视口、内容区和行测量的 ResizeObserver 使用上一次稳定锚点，不先抓取变化后的新位置覆盖它。已知提交的恢复放在重绘前；不通过固定延时等待布局。手势结束优先使用 scrollend，不可用时用 180ms 静默回退；该计时只结束用户手势，不延迟布局补偿。

滚动来源分为用户操作、程序定位和布局补偿。`scroll` 回调用于确认位置、更新可见窗口与记录稳定锚点，不再仅凭 `scrollTop` 减小、`scrollHeight` 未变推断用户上滚。保留滚轮、触摸惯性、键盘、滚动条、拖选和辅助功能产生的原生滚动；内部代码块自己消费的滚动不改变消息区跟随。普通内容点击只取消旧定位，真实滚动或文本选择才改变阅读模式；布局补偿和手势收尾不自行恢复跟随。已知程序写入记录操作归属，不用仅持续一帧的布尔锁屏蔽事件。

**消息投递与回合页脚**：与滚动意图一样，这两处各有一个状态模型，界面位置只从模型推导，不在组件里各自拼条件。

- `delivery.ts`：`sendPhase(run)` 把 `delivery` + `stage` 收成 `submitting → queued → starting → sent`，以及 `uncertain / failed / cancelled`。`messagePlace(run, working, next, queue)` 决定消息在输入框上方的队列还是正文，依据服务端随状态下发的队列（`status.queue`：下一条 `next`、阻塞原因 `held`，由服务端的 `native/lane.ts` 计算，与派发是同一个判断）：排队中的消息进队列，除非它就是正在开始的下一条；未应答的发送在队列被阻塞或已有下一条时进队列，否则进正文；引导始终在正文。旧服务端不下发队列时，退回按会话是否运行推断。`inQueue(run)` 决定「立即发送 / 编辑 / 取回」是否可用。新增判断走这三个函数，不再直接比较 `delivery` 与 `stage`。
- `transcriptRows.ts` 的 `TurnFooter`：每行 `none / held / shown`。会携带回合页脚的行（回合的回答，或没有回答时回合末尾的过程块）在回合运行时为 `held`，结算后为 `shown`。`held` 的行预留页脚位置，「正在处理」放在 `heldFooterRow` 给出的那一行里；结算只替换位置里的内容，不改变高度。运行中页脚换到后一行，只发生在正文本来就在增长时。

**转录回放**（`pnpm replay:transcript`）：录下一个会话的 sync 流，在无头 Chrome 里回放进真实的转录，逐帧报告不该发生的位移。

- `record <sessionId> [--seconds N] [--until-idle] [--out file]`：用本机 access token 登录本地服务，只读 `/api/v3/sessions/:id/sync?lane=main`，每帧连同到达时间写成 JSONL。
- `run <file> [--speed N] [--max-gap ms] [--width px] [--height px] [--headed] [--json report]`：以 Vite 开发服务器打开 `apps/web/replay.html`，按录制时序（长间隔截到 `--max-gap`）把帧交给真实的 `SessionSync` → `useSessionTranscript` → `TranscriptView`，有事件时退出码为 1。回放页不连服务端，分页请求一律挂起。
- 每个动画帧按布局位置（`offsetTop`，不含入场的 transform）读取可见的行与过程块内条目，报告：`state-shift`（只有状态类帧到达时行在动）、`drop`（跟随底部时行向下移，即下方有东西变矮或消失）、`left-bottom`（无输入却离开底部）、`remount` / `move`（同一个 key 换了元素，`move` 是独立行与过程块条目之间的迁移）、`replay`（入场动画再次播放）、`vanish` / `return`（可见的行离开 DOM / 又回来）。
- 不覆盖：本标签页自己的发送（本地副本、`http_pending`）与读者输入，录制里没有它们。

`TurnRail` 保留位置读取和当前轮次高亮，定位委托给消息视口。`Composer` 的滚轮余量由宿主传给明确的消息视口实例，移除全局查找、合成 wheel 和直接写入消息区 `scrollTop` 的路径。所有消息区写入迁移完毕后，才视为完成单一滚动所有权；导航列表、代码块和文本域自己的滚动仍由各自组件管理。

切会话或 reset 清理旧定位、锚点和帧任务。用户意图版本与布局重置版本分别记录：同会话的轮次加载会替换窗口，但仍可完成该次用户请求；用户滚动、新导航和切会话会使等待结果失效。轮次加载返回实际用户消息 key，替换加载前的 outline 占位 key；真正落点前再次校验意图。轮次加载与回到最新的 AbortSignal 一直传到 LaneSync 的分页 controller，取消后的迟到响应不能替换窗口。消息区隐藏期间不采集零尺寸锚点，恢复可见后按保留状态恢复。

保留当前 `content-visibility` 与 150／100 行窗口化阈值；宽度变化时的行高处理见 2026-11-02「布局稳定性」，已不再整体失效。虚拟窗口同步挂载和估高修正也进入同一位置恢复过程。宽度导致消息内部重新换行时，第一版保证保留同一消息的阅读上下文；锚点在顶行越过视口上沿时下沉到块级，不承诺逐字定位。

**验收**：类型检查、Web 构建和受影响的核心测试用于静态与协议验证；已有 sync 测试覆盖取消 around／latest 请求后忽略迟到响应，不新增 UI 展示测试。实际界面验证仍需覆盖中文收字、空白／尾部换行、上限处删字、附件与托盘伸缩、全屏往返、流式输出、上翻分页、虚拟化阈值和会话切换。固定宽度且目标仍存在的纯位移场景，位置恢复误差以不超过 1 CSS px 为目标；宽度重排按阅读上下文验收。

### 2026-10-09 已实现：会话历史连续性

本节覆盖下文旧诊断中关于「320 KiB 窗口」「重連／reset 替换旧页」的描述。

- 服务端 `transcript-window.ts` 按消息身份选择历史：目标 50 条用户／助手消息与至少两个轮次起点，最多 500 条；流式分片合并计数，工具事件随范围返回。历史耗尽或传输预算先到时提前结束。默认字节预算改用已有的 4 MiB 传输上限，按 UTF-8 计量；单个不可拆分事件超限时仍完整返回，不能把这个预算理解为严格的 SSE 帧上限。
- `reset.replaceFrom` 明确声明权威尾部的起点。同一 `chatId` 和历史 `generation` 下，Web 保留范围外的旧消息和分页游标，只校正范围内内容；草稿被正式消息替换、同 ID 内容更新、子 Agent 和后台预取均使用相同规则。旧服务端未声明范围时继续使用原先的保守追加判据。
- 断线后最新窗口与本机尾部不相交时，先沿历史游标补齐缺口，成功后一次合并；后续流帧依次处理。补齐失败保留当前画面并重试，切换连接会取消旧补齐任务。整体重建仅用于会话身份／历史代次变化等不能续接的情况。
- `readingAnchor.ts` 保存可见消息身份与视口偏移，消息更新和后续尺寸变化均可补偿；用户滚轮、触摸滚动或方向键操作会释放过时的分页定位。底部跟随与历史阅读分开，不因普通快照同步而重置滚动。
- 回归覆盖：240 轮历史的多页补齐与后续草稿结算、历史游标保留、同 ID 内容更新、取消／失败、UTF-8 计量、分片计数及阅读锚点。浏览器验证使用实际 `useNativeSession` 和 `TranscriptView`，配合合成网络帧；不代表真实后端端到端或性能压测。

正文窗口化已在 2026-10-18 引入（见 2026-10-24 一节）；工具大输出的独立按需接口、上翻自动预取尚未引入；现有「加载更早消息」仍用于访问确实未加载的历史。50／2／500 是参照 DeepSeek Harness 的初始分页策略，后续根据真实长会话测量调整，不影响已加载历史的保留契约。

## 1. 判据

不评判"好不好看"，只评判四个可验收的问题：

1. **打开即见**：刷新、换标签页、断网重连之后，看到的是上次的内容，而不是空白或转圈。
2. **位置不丢**：重连、翻历史、流式输出不会把阅读位置顶走。
3. **键盘可达**：桌面端的高频操作不依赖鼠标。这是 web 相对原生客户端的唯一结构性优势，必须用足。
4. **变化可感知、不喧哗**：状态变化看得见，但不以位移打扰阅读；减弱动效下仍然可感知。

## 3. 差距与机会

### 3.1 P0 —— 把已有的本机副本真正用起来

web 已经有一份本机副本（IndexedDB `riffet/transcripts`，8 个会话 / 5000 事件，`lib/transcript-store.ts:13,15`；内存热缓存 6 个，`nativeStream.ts:26`），也已经在拨号前先渲染它（`nativeStream.ts:101-115`）。但**它只被用来"先画一次"，没有被用来"少取一次"**：

- **流每次都是新窗口**。`nativeStream.ts:397` 打开 `/api/sessions/:id/native/stream` 时**不带** `window` / `generation` / `after`，而服务端已经支持（`app.ts:364`，实现在 transcript-window.ts（已随 sync v3 删除）；默认 320 KiB、上限 4 MiB）。
  于是每次刷新、每次重连、每次手机浏览器丢弃后台标签页后回来，都重新下载一个全新的 320 KiB 窗口，本机已翻过的旧页与阅读位置随之失效。移动端同样场景只取锚点之后的部分。
  **改**：有本机副本时按同一协议带上本机尾部 `generation` + `after=<nativeId>`；`reset` 到达后走已有的 `continuedBy` 判据只追加（`nativeStream.ts:215`，已正确实现）。EventSource 不能带自定义头，但参数在 URL 上，重连时重建 URL 即可。锚点认不出、代次不同时退回现状。
  **不带 `window`**：服务端命中锚点时只看自己的 4 MiB 上限，不看 `budget`；带上它只会把"锚点没认出来"时的兜底帧撑大，而浏览器有本机副本，不需要手机那样一次取 3 MiB。
  **验收**：断网重连与刷新页面后 `reset.events` 从锚点开始，已加载的旧分页与滚动位置仍在；对不带这些参数的旧服务端行为不变。

- **没有列表副本**。`Workbench.tsx:53` 的 `bootstrap` 初值是 `undefined`，只在 `:150` 从网络取；取不到就是错误页/转圈（`:775-787`），而不是「离线 · 显示 X 前保存的列表」。只有**选中的 id** 进了 localStorage（`Workbench.tsx:38-44`，`KEYS` 五个键）。
  **改**：项目与会话列表落 IndexedDB 或 localStorage（带时间戳），启动先画再连。
  **验收**：服务不可达时侧栏仍列出上次的会话，并明确标注陈旧时间。（2026-10-24 前启动时不可达会落到登录页，此条实际不成立，已修复。）

- **没有预取**。web 的 API 客户端里没有 `native/snapshot` 调用（`lib/api.ts`）；移动端每次刷新列表后对最近活跃的 8 个会话做差量预取（`MOBILE.md:295`）。这决定了「点开另一个会话」是否瞬间有内容。
  **改**：列表轮询后，对活动时间戳变化、且不在看的会话调 `/api/sessions/:id/native/snapshot`（`app.ts:418` 已支持锚点），合并进本机副本。

- **容量与淘汰要写明取舍**。web 现在 8 个会话 / 5000 事件，移动端 300 个 / 256 MiB。不是越大越好；要有一条"缓存可丢弃、读坏了当没有"的契约（`transcript-store.ts:6-8` 已有这个基调，需要写进本文并按它做淘汰）。

### 3.2 P1 —— 缺失的能力

- **消息全文搜索**（已落地）。侧栏此前只搜标题、标签、项目名与 cwd（`Sidebar.tsx:113,114,132`）。搜索弹窗分「标题 / 内容」两个页签，内容页签搜消息正文，命中直接打开会话并滚到那一行；标题页签无结果时提供"在内容中搜索"一项。
  设计上有一条硬约束：**搜索绝不启动 agent**。服务端只在**手上已经有转录**时建立索引（流式 reset 帧与 `/native/snapshot`），并只对显式声明 `readOnlySnapshot` 的 provider（目前是 Cursor）主动读取；提问因为已经落在 runs 里，覆盖全部历史且完全不读 provider。
  匹配用 SQL `LIKE` 并转义查询里的通配符，不用 FTS5——中文不需要分词器，这正是移动端当初要切二字词的原因。
  **验收**：搜索命中一条旧会话里的回答，点结果打开该会话并滚到该消息；索引未建完时如实显示"正在建立索引"。

- **显示设置**（已落地）。文字大小、会话间距、终端字号三项，只存本机，语义与移动端 `DisplaySettings` 对齐（文字大小 0.9/1/1.1/1.2，间距 0.75/1/1.25，终端字号 11/12.5/14/16）。
  文字大小改的是 `--text-*` 与配套行高（`calc(原值 * var(--text-scale))`），写在一条**不带 layer** 的 `:root` 规则里：不带 layer 才压得过 Tailwind 的 theme layer，且刻意不写进 `@theme`——`scripts/gen-mobile-theme.ts` 会把那些 token 解析成 Kotlin `sp`，生成的移动端主题必须保持裸 px。
  间距只作用于转录行距，触控目标尺寸与触摸设备上紧凑行之间的零间距不变；终端字号就地改 `term.options.fontSize` 并重新 fit（重建 xterm 会丢掉连接与回滚）。
  **验收**：三档文字大小立即重排且刷新后保留；`gen:theme:check` 仍通过。

- **通知的两处诚实与可用性**（已落地，`SettingsDialog.tsx:119`、`Workbench.tsx:281`、`nativeStream.ts:314`）：
  1. 文案此前暗示"后台推送"（"页面在后台时…会发送桌面通知"），而它只在这个标签页活着且连着服务端时才会响。现在说的是实话。
  2. 点通知此前没有任何反应。现在每条带 `tag`（同一会话替换而不是堆叠）与 `onclick`（聚焦窗口并打开该会话）。
  **验收**：断网或关掉标签页时，设置页的说法与行为一致；点通知跳到对应会话。

- **上传前降采样**（已落地）。超过长边 2048px 的图片在浏览器里重画后再上传，附件记录的尺寸随之改为重画后的尺寸，转录预留的框因此与实际到达的图片一致。PNG 保持 PNG（可能带透明），其余转 JPEG；解不开的、或本来就够小的原样上传；文件名跟着格式走。
  **验收**：一张 12MP 手机照片上传后字节数显著下降，缩略图与预览正常。

- **设置面的其余能力（当前不做）**。设置搜索、作用域 chip、设备管理界面、项目选择器原本属于早前那份设置契约，已随它一起移除。若将来重做设置面，`GET/DELETE /api/devices` 在服务端已可用而 web 端零调用，是最先能补上的一项。

- **未保存更改的兜底**（已落地）。三个 dirty 标志已存在（`SettingsDialog.tsx:477-479`），原本只在弹窗内切分区时拦（`:493-508`）；关标签页会静默丢弃 CLI / 提供商 / 项目配置的未保存修改。草稿本身靠 `sessionStorage` 存活（2026-10-24 起首页输入框也有，并连同附件与引用一起保存；`Composer.tsx` 去抖写入，切换会话、卸载、`pagehide` 与标签页隐藏时立即落盘）。现在任一 dirty 时挂一个 `beforeunload`。
  **验收**：有未保存修改时关标签页会被浏览器询问。

### 3.3 P2 —— 动效与品质

- **减弱动效的语义**（已落地）。现状曾是 `index.css:625-632` 把 `animation-duration` / `transition-duration` 一律压到 `0.01ms !important`，`README.md:297` 把它写成了契约。这**把淡入淡出也一起杀了**，而淡入属于状态可感知性——Apple 的做法是用 cross-dissolve 替代 zoom / push 转场，而不是让所有变化瞬时发生。
  **实现**：位移、缩放、视差从 `transition-property` 里排除（因此完全不过渡）；纯 `opacity` 与颜色保留 100ms linear；`shimmer` 在减弱动效下改静态。`transition-duration` 的 `!important` 会压过简写，第二条带同样的 `!important`。`README.md:297` 已同步。

- **动效 token 与控件一致性**（已落地）。全局原本只有一条共享缓动 `--ease-out-soft`（`index.css:135`），时长全是各组件字面量。现在补上了对齐 Material 3 的 `--ease-standard` / `--ease-decelerate` / `--ease-accelerate` 与 `--duration-fast/base/medium/slow`，UI 原语里的字面量改为引用它们（**纯改名，渲染值不变**）。已有的 `--ease-out-soft` 保留不动（124 处引用）。`Switch` 的 150ms 改为显式声明。
  **未做**：`Segmented` 的滑动指示器仍未抽成共用件——它是纯观感改动，且需要动 `controls.tsx` 与 `ModelPicker.tsx` 两处渲染，留到有眼睛盯着时再做。不新增动画库。

- **新内容淡入与阅读锚点对齐移动端**（**未做**）。web 现在有行的渐入（`TranscriptView.tsx`），但没有独立的"新内容淡入"开关（移动端有，`MOBILE.md:355,363`）；"有选区时不强制贴底"已在 2026-10-24 落地（选区出现即释放跟随），新内容淡入开关仍未做。
  **改**：把渐入挂到一个本机偏好上；贴底逻辑读"用户是否正在阅读"（选区或已向上滚动）。**验收**：正在读旧内容时到达的新行不把视口拽走。

- **焦点三件套**（对移动端 §4 原则的 web 落地，**前两件已落地**）：
  1. **未做**：只有**真的点击**转录区才让输入框失焦（点输入卡片内部、点选区、拖动都不失焦）。这条要在转录根上阻止浏览器的默认聚焦行为，没有浏览器就验不了，而且会危及长按选择——因此明确不做，而不是做一个没验过的。
  2. 输入区自己吃掉点击（移动端 `keepsFocusOnTap()` 的对应物）：**已落地**，只对卡片里的非交互区域生效，按钮/输入框/选区照旧。
  3. 手指按住期间不回收键盘占的高度，松手后再收（移动端 `keyboardPadding()`）：**已落地**，最后一个指针抬起时补一次高度，`window.blur` 兜住漏掉的抬起。
  **验收**：手机上输入一半去点转录看内容，输入框的键盘不闪退、内容不跳。

- **View Transitions 渐进增强**。设置层级推入/推出、面板切换可以用 `document.startViewTransition` 做，能力不足时保持现状（`@supports` / 特性判断）。层级推入用 iOS 风格曲线 `cubic-bezier(0.32, 0.72, 0, 1)`（进入 300ms、退出 250ms，退出比进入快）。**验收**：支持与不支持的两类浏览器都不出现跳变或卡顿。

### 3.4 P3 —— web 独有（原生客户端做不了或做不好）

这些是 web 相对原生客户端的**结构性优势**，是"提高品质"里最该被用足的部分：

- **URL 即状态 / 深链**（已落地）。原本只有登录时解析并剥掉 `?token=`（`App.tsx:41-47`），会话与项目选择只写 state + localStorage，所以刷新靠"上次选中"，链接不可分享。
  现在用 `history.replaceState` 把选择镜像成路径地址 `/c/<sessionId>`、`/p/<projectId>`（服务端与 Service Worker 对无扩展名路径都回 `index.html`；绝不 `pushState`——覆盖层返回栈每个覆盖层只压一条历史），启动时读一次并覆盖存储值。**验收**：把 URL 贴到另一台已配对的设备上能直接打开同一会话。

- **键盘优先：命令面板**（已落地）。原本全局只有三个快捷键（`⌘K` 搜索、`⌘B` 侧栏、`Ctrl+\`` 终端）。现在 `⌘K` 打开搜索、`⌘⇧P` 打开命令面板（搜索框输入 `>` 也会进入命令面板）：动作、会话、项目一起过滤，↑↓ 选择、Enter 执行、Esc 关闭，焦点留在输入框（活动行用 `aria-activedescendant` 跟踪），并复用覆盖层栈处理返回。
  **未做**：`?` 快捷键帮助页；设置项的逐行直达（面板目前能跳到分区，不能跳到某一行——那需要设置搜索）。
  **验收**：全程不碰鼠标完成"打开某会话 → 换模型 → 发消息 → 切面板"。

- **多标签页一致性**（**有意未做**，理由见 §5 P3 第 17 条）：真正需要跨标签同步的两项（主题、显示设置）已经通过 localStorage 的 `storage` 事件同步，而"两个标签互不干扰"本来就成立。

- **Safari/Chrome 的 PWA 化**（已落地）。原本没有 manifest、没有 Service Worker。现在外壳可缓存、可安装：导航 network-first（新构建不会被旧 HTML 缓存盖住），`/assets/*` cache-first，**API、SSE、WebSocket 一律不缓存**。注册只在生产构建里发生，免得和 HMR 打架。
  **诚实边界**：Service Worker 与安装都要求 **安全上下文**——`localhost` 或 HTTPS。用 `riffet start --host 0.0.0.0` 走明文 HTTP 的局域网访问注册会失败，于是没有离线外壳、也装不了；README 推荐的 Tailscale（`serve` 终结 TLS）满足这一条。失败是静默的（注册的 promise 被吞掉），界面上没有任何"已可离线"的暗示。
  **验收**：断网刷新仍能打开外壳并显示本机副本（在 localhost 或 HTTPS 下）；可从浏览器安装。

- **Screen Wake Lock**（已落地）。会话在跑且页面可见时保持屏幕常亮，结束即释放；不支持的环境静默降级，页面重新可见时重新申请。
  **与原文的偏差**：原文要求"做成开关并标注只在页面可见时有效"。**没有做开关**——它只在页面可见、且正在跑的时候生效，那正是读者在看着的时候，没有需要用户决定的事；一个没人要求的偏好比没有偏好更糟。**验收**：长任务期间手机不熄屏，退出后立即释放。

- **大屏生产力：分栏**（**留在路线图**）。工作台目前同时只有一个会话视图加右侧上下文。桌面端可以同屏两个会话（或转录 + 文件），这才是 web 相对手机的真正优势。原文自己就把它标为"优先级最低但要写进路线图"；它是唯一会实质改变布局的项，第二个面板选哪条会话、两个面板的输入框与终端怎么算都属于产品决定，值得在有眼睛盯着时单独做。

## 6. 明确不做

- **不引入路由库**。深链用 hash + `replaceState` 满足；设置保持弹窗/全屏页（它是模态任务，路由化会让"改一半刷新页面"变成常态）。
- **不做通知的公网推送中继**。与移动端同一理由（`MOBILE.md:469`）；web 的边界是"页面活着才有通知"，说清楚即可。
- **不做 web 端下载中心**。浏览器自带下载 UI 已覆盖保存、进度与历史（移动端之所以自建，是因为 Android 通知栏不适合管理）；只在桌面端确有需求时再评估。
- **不把时间线投影下沉到服务端**（`MOBILE.md:534` 的结论对 web 同样成立）。
- **不搬移动端的触觉反馈**。web 没有等价能力；`navigator.vibrate` 在桌面与 iOS Safari 不可用，为它单独写分支不划算。
- **不重写转录虚拟化**。2026-10-18 已在此基础上加了窗口化（`virtualRows.ts`），2026-10-24 补了展开状态记忆与会话内查找。此前已经做过一轮（按需面板、可视范围渲染、每帧合并渲染）；动它之前先证明还有热路径（见 §7 待测）。

## 7. 待确认的决策

1. **P0 / P1 / P2 与 P3 的 16、18 已落地**（见 §5）。剩下只有 17（多标签）与 19（大屏分栏），两项都已决定不做。
2. **`大屏分栏` 已决定先不做**（2026-10-08），留在路线图：它是唯一会实质改变布局的项，第二个面板选哪条会话、两个面板的输入框与终端怎么算都是产品决定，而且没有浏览器无法验证布局效果。
3. **`多标签一致性` 已决定不做**（2026-10-08）：见 §5 P3 第 17 条——真正需要同步的两项已经由 `storage` 事件覆盖，剩下的两项各自有更糟的代价。
4. **设置面要不要重做**：早前那份设置契约（六个分区、保存语义收敛、设置搜索、作用域 chip）已移除，当前没有计划。若仍想做，需要另起一份契约；本文的其余工作不依赖它。
5. **搜索的召回口径**（已实现，仍需确认）：提问覆盖全部历史，回答与工具调用只覆盖服务端见过转录的会话（跨重启保留）。是否要为此再加一轮"读取本机缓存"的客户端索引，取决于真实使用中回答的召回够不够。
6. **PWA 是否在范围内**：它会把"访问一个本地服务"变成"安装一个应用"，是体验提升也是形态改变，需要产品判断。**已实现**（§3.4），若要撤掉就是删掉注册与 manifest 两行。
5. **未测量的前提**：本文没有测过"打开会话到首屏可见"的真实耗时，也没有跑浏览器 E2E。P0 的收益判断基于协议与代码路径，不是实测数字；若要求"先测量再优化"，需要先补一个可重复的测量脚本（仍是未做项）。
6. **输入框的手势、附件与全屏编辑**：另立契约 `docs/COMPOSER.md`（2026-10-09，三期已全部落地）。已定：Enter 默认换行、⌘/Ctrl+Enter 在两种选择下都发送；开关是**账号级**（`AppSettings.composerEnterBehavior`），与本文 P3 里"文字大小/会话间距只影响这台设备"是两个作用域，界面上按契约写明；全屏编辑不做快捷键。图片附件在发送前就是缩略图（点开即预览），拖放覆盖整个窗口，全屏时对话列 `inert` 但仍可滚读——这三条都按契约验收，不在本文重复。
